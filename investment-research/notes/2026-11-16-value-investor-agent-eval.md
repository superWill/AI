# value-investor agent 校验（2026-11-16）

> 起因：用户问「能不能训练一个巴菲特 agent 专门研究股票」。仓库里已经有 `.claude/agents/value-investor.md`，问题是没被用、没被检验过、不引原文。本篇记录当天做的三件事和一个结论。

## 一、结论（先说）

1. **回测 6/6 全对，但这个结果不能当证据。** 六个案例它全部认出或猜出了公司（它自己如实报告的），匿名化和缩放没挡住。它知道这些公司后来怎样。`[KNOWN，本次实测，HIGH]`
2. **回测能说明的只有两件小事：** 它不是一律拒绝（6 个里放行 2 个），也不是在同一关机械地停（停在第 1 关 1 次、第 2 关 3 次、四关全过 2 次）。`[COMPUTED，HIGH]`
3. **唯一干净的检验是前向记录。** 从今天起每份判决记一行，到复核日对照。见第四节。
4. **ANT：停在第 1 关，「不懂，过」。** 理由是讲不清十年后为什么还赚钱：单位经济没稳定、说不出客户不换的机制、领先按季度算。

**为什么 6/6 不算数：**

- 六个全被认出。它在 A 上还自己指出：定义里本来就点名「AVGO/IBM 型」是收购陷阱，这题等于提前给了答案。
- 六个案例是我挑的，挑的时候我也知道结果。三好三坏的配比是人为的。
- n=6。
- 判决和结果对上得太整齐，这本身就是该怀疑的信号。

**它给出的理由本身是站得住的**（不依赖后见之明也能从材料里读出来）：A 的回购加分红超过自由现金流、商誉超过股东权益；C 的利润率四年不动、Y0 的跳升来自燃油；D 的自由现金流只有净利润的 13%。但「理由站得住」和「当时就会这样判」是两回事，后者这次测不出来。

**一个副产品：** 它在 A、C、D 三笔上和巴菲特当时的实际操作相反。这说明这个 agent 不是在模仿巴菲特的买卖，而是在执行一套比他本人更保守的筛子。用的时候要清楚这一点。

## 九、同日追加：改第四关 + 改筛选口径之后再看一遍

用户看到 0/16 后说「调整一下再看看」。改了两处，**都是先定标准、后看结果**。

### 9.1 改了什么，为什么

**第四关。** 前 16 份里 10 份停在这一关，理由多是「倍数太高 / 回落要熬很多年」。这把「估值倍数回落的账面回撤」和「本金永久损失」混在了一起，前者不是这一关要防的。改成三步算数（全文在 `.claude/agents/value-investor.md`）：

1. 正常化 owner earnings（周期平均，剔一次性项，写明剔了什么）。
2. 持有回报 = 可分配收益率 + 可持续增长率，假设十年后倍数不变。
3. 正常化盈利再砍 30% 重算。

过线：第 2 步 ≥10%，且第 3 步 ≥ 十年期美债（2026-11-13 为 5.15%）。10% 和 30% 是我定的，没有推导，只是在看结果之前写死了。

**中途改过一次公式。** 第一版写的是「盈利收益率 + 增长率」。KNSL 重判时 agent 指出这把留存利润算了两次（留存的钱既算进收益率，又算成增长的来源）。改成「可分配收益率 + 增长」。这次修改是在看到五份重判结果之后做的，方向是收紧。按新公式 KNSL 从 10.8% 降到 10.1%，仍贴线过；BRK-B 会比 8.9% 更低；ITRN 几乎全额派息，不受影响。MCRI、RLI 没有按新公式重算，只会更低。

**筛选。** 新增 `scripts/screen_quality_multiyear.py`：用 SEC XBRL frames 取 2021–2025 五年数据，要求每年盈利、每年 ROE ≥10% 且五年平均 ≥15%、最低年净利润 ≥ 最高年的 40%、收入四年复合 ≥4%、五年（经营现金流 − 资本开支）÷ 净利润 ≥0.7、市值 $3–100 亿、近三年平均净利润 ÷ 市值 ≥5%。约 106 家过基本面，13 只落在市值和收益率区间（`data/screens/2026-11-16-quality-multiyear.csv`）。

### 9.4 这一轮说明了什么，没说明什么

- 累计 25 份判决（17 + 8 行新记录，其中 2 行是取代旧行）：2 只贴线过，其余不过。
- 第四关现在给的是数字和差距，不再是「太贵」。这是这轮唯一确定的改进。
- **多年口径没有解决「在高点选中」的问题。** 2021–2025 这五年本身就是一个窗口：没有房价下跌（NMIH）、没有信用损失（FBP）、利润率高点（SFM）。五年平均抹不掉五年都在的顺风。要修得拉更长的历史（2008–2010），XBRL frames 在 2009 年之前没有数据。
- **筛选脚本有一个已知缺陷：** 某年缺资本开支科目时按 0 处理，会高估现金转化率。GNTX 筛选给 1.22，agent 自己算是 0.87。入选名单的 `fcf_conversion` 列不可靠，没修。
- **两只「过」不能当作筛子有效的证据。** 都在线上 0.1–0.3 个点，输入里有猜的数；10% 这条线挪半个点结果就变。而且我是看到 0/16 之后才改的标准——标准虽然先于新结果写死，但「要让它能放行一些东西」这个动机在先。
- 干净的对照（一个它应该放行的公司，看它放不放）还是没做。
- 六个 agent 里五个报告 `www.sec.gov` 拦截了通用 User-Agent，10-K / 10-Q 正文没读到，用的是 `data.sec.gov` 的 XBRL 加业绩稿。**所以这一轮的「读了一手文件」只成立一半。** 要读正文得在请求里带联系方式，这需要用户自己决定用哪个。
