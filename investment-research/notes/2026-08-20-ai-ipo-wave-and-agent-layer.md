# AI IPO 潮（⑦号顶部信号）+ Grok Bot 观察项

## 一句话

**三个万亿级 AI 标的在同一窗口排队上市（SpaceX 已成、Anthropic 秘密递交寻求 $2T+、OpenAI 临近）。这不是新信号，是 6/25 那份清单里「发行窗口在关」那一行的反转——但反转后的正确措辞是「发行在放量、承接在恶化」（SpaceX 破发、SKHY 首日 −16%），方向不变、机制描述更准。测湿度不测起火，时滞 1–2 年，不作择时。**

**同时必须记住一条相反方向的算式：OpenAI+Anthropic 的 ARR 增速（+262%）是四大超大厂 capex 增速（+77%）的 3.4 倍。这直接顶撞「AI capex 是泡沫」的主流叙事，且它降低而非提高「顶部临近」的先验。**

## 一、AI IPO 潮 —— 不是新信号，是「发行窗口」那一行的**方向反转**

### 🔴 建档时发现的问题（必须先说）

`notes/2026-06-25-top-signals-and-panic-discipline.md` 的信号清单里**已经有一行**：

> **⭐ 发行窗口在关（6/26 新增）**：OpenAI 据 NYT 考虑把 IPO 推迟到明年；SpaceX 上市即破发；7/20 更新 SK Hynix 纳斯达克首日 −16%。

### 两个对组合有实际影响的后果

**① 被动资金的挤出效应** `[INFERRED, MED]`

$2 万亿的标的进指数，被动基金**必须买**。买的钱从卖现有成分股来，而**指数再平衡的卖压是无差别的**。组合半导体权重高，会被无差别卖压扫到。

**② 一级向二级派发 = 经典周期晚期特征** `[COMMON]`

私募巨头集中在同一窗口上市，等价于内部人认为公开市场估值 ≥ 私募估值。

### ⭐⭐ 窗口重开，是利多还是更晚场？两种读法，必须都写出来

| | 读法 A（信号熄灭 = 偏多） | 读法 B（派发到极致 = 更晚场） |
|---|---|---|
| **论据** | 6/26 那行的前提「募不动」被证伪。窗口不但开了，还开出史上最大 IPO | 2000/3 的顶是**窗口先关**，但顶**之前**必然是 IPO 狂潮。窗口开+供给史无前例 = 正处在派发段 |
| **对应历史** | 假警报，泡沫再跑数月 | 1999–2000/2 |

### 🔴 判别式：看的不是能不能发出来，是**发出来之后二级能不能消化**

- **SpaceX 6/11 上市即破发**，8/4 首份财报后 NPR 形容股价「从天上飘回地面」
- SK Hynix 纳斯达克首日 **−16%**

> ## **供给出得来，但二级市场吃不下 —— 这支持读法 B。**
> **「募不动」和「募得到但破发」是同一条曲线上相邻的两点，后者更早、前者更晚。6/26 我把它记成了「募不动」，现在看应该记成「募得到但立刻破发」。**

**净判断 `[INFERRED, MED]`：⑦号那一行不熄灭，但要改写措辞——从「发行窗口在关」改为「发行在放量、承接在恶化」。方向不变，机制描述更准。**

### ⚠️ 但这个信号的性质必须写清楚

> **测湿度，不测起火**（同 memory `kimpremium-leverage-dashboard` 的定性）。
> **IPO 潮领先顶部的时滞是 1–2 年，方差极大。绝不作为择时器，也不构成任何减仓依据。**
> 它的正确用法：**当四大触发器开始亮灯时，这条决定「该信几分」——而不是它自己触发动作。**

### 与既有框架的关系

## 二、⭐⭐ 必须同时记的反证：收入增速是 capex 增速的 3.4 倍

**这一节比上一节重要。反向证据是半年后最容易被自己忘掉的东西——那时只会记得框架管用的那几次（post-hoc 偏误）。**

### 数据 `[KNOWN, HIGH]`

| | 2025 年底 | 2026/5 | **最新** |
|---|---:|---:|---:|
| **Anthropic ARR** | $90 亿 | $470 亿 | **$650 亿**（7 月底，Bloomberg） |
| **OpenAI ARR** | $200 亿+ | — | **$400 亿**（8/13，Bloomberg） |

- Anthropic **两个月加了 $180 亿年化收入**；Q2 收入同比 **14 倍**（$7.87 亿 → $115 亿）
- OpenAI **7 月单月 run rate +20%**；驱动是订阅 + 广告 + Codex + ChatGPT Work
- ChatGPT 广告试点（仅免费/Go 层）**六周破 $1 亿年化，600+ 广告主**
- 投资人预计 Anthropic 年底 ARR **$1,000–1,200 亿**

### 四大超大厂 2026 capex `[KNOWN, HIGH——CNBC/Futurum]`

| | 2026 指引 |
|---|---:|
| Amazon | $2,000 亿 → **$2,200 亿**（上调） |
| Microsoft | ~$1,900 亿 |
| Alphabet | $1,800–1,900 亿 → **$1,950–2,050 亿**（上调） |
| Meta | **$1,300–1,450 亿** |
| **合计** | **$7,250 亿**（2025 约 $4,100 亿） |

**每家 2026 年内至少上调过一次指引，多数上调两次。**

### 算式 `[COMPUTED]`

| | 2025 年底 | 2026 最新 | **倍数** |
|---|---:|---:|---:|
| 四大超大厂 AI capex | ~$4,100 亿 | **$7,250 亿** | **1.77x（+77%）** |
| OpenAI + Anthropic ARR | ~$290 亿 | **$1,050 亿** | **3.62x（+262%）** |

> ## **收入增速 ÷ capex 增速 = 262% ÷ 77% ≈ 3.4 倍**

**敏感度检验**（因为 OpenAI 2025 年底口径是「$200 亿+」的下限）：
即便把 OpenAI 2025 年底放宽到 $250 亿，合计 $340 亿 → $1,050 亿 = **3.09x（+209%）**，仍远超 capex 的 +77%。**结论对这个假设不敏感。**

**另一个参考比率**：$1,050 亿 ÷ $7,250 亿 = **14.5%**（两家前沿实验室 ARR / 四大厂当年 capex）。

### 判断 `[INFERRED, MED]`

**这不是 2000 年那种「零收入烧钱」的泡沫。泡沫的定义特征是投入远跑在产出前面——这里是反过来的。**

### 🔴 必须自己拆掉的四条 caveat

1. **ARR 不是收入。** 单月年化，一次大客户流失就掉一大块。
2. **没有利润。** 有报道称 OpenAI 2026 亏 $209 亿（未交叉核实，`[LOW-MED]`）。**收入翻三倍 ≠ 经济性成立，这两件事经常被混为一谈。**
3. **样本只有两家。** capex 服务的是整个市场的推理+训练需求，不只这两家。
4. **时间轴不对齐。** capex 折旧摊多年，ARR 是当期口径。分子分母不同质。

**净效果：降低「顶部临近」的先验，但不构成任何加仓依据。它只证明了需求是真的，没证明回报是真的。**

## 三、观察项建档：Grok Bot（xAI 云端 agent）

`[KNOWN, MED-HIGH——产品事实多源一致；安全架构一节依据 xAI 自身文档/FAQ 的二手转述，我未能直接打开 x.ai 原页面（404/403），待原文核实]`

### 是什么（2026-08-11 beta）

| | |
|---|---|
| **定位** | 不是聊天机器人，是**常驻云端的 AI 同事** |
| **⭐ 真正的差异化** | **不需要 API，不需要 MCP**——直接在云端电脑上操作 GUI，登录你现有的 app/邮箱/网站。没有干净接口的系统也能接 |
| **常驻性** | 关掉笔记本继续跑；**只在需要审批时回来**，不是每步问方向 |
| **学习方式** | 看你做一遍，然后自己重复 |
| **平台** | 桌面（有 Linux 版）+ iOS，Android 待发 |
| **定价** | 不单卖。捆绑 SuperGrok Heavy（$299/月）/ Cursor Ultra（$200/月）/ Cursor Teams Premium（$120/席/月）；企业走 waitlist |

**时间线细节**：8/11 发布即捆进 Cursor 付费档，而 **$600 亿收购 Cursor 是 8/14 才正式交割**——分销渠道比法律交割先跑。

### 🔴 关键：营销口径与实际架构不符

**营销说「每个 bot 有自己的云电脑」。实际是：账号下所有 bot 共用一台持久云电脑——一套浏览器 cookie、一个文件系统、一套命令行凭证，所有 bot 都能碰。**

xAI 自己的文档写得很直白：

> 屏幕是分开的工作面，**不是分开的安全边界**。

> FAQ：**不要把不同的 Bot 当作安全边界用。**

**后果**：邮件 bot 的浏览器会话里若有已登录的财务系统，CRM bot 和账号下任何其他 bot 都能进去。**一个被攻破或只是搞错了的工作流，就能横向拿到全部权限。**

> **这不是「AI 有幻觉」级别的风险，是权限模型级别的风险。**

### 与之区分：Grok Build（别混）

| | **Grok Build** | **Grok Bot** |
|---|---|---|
| 发布 | **5/14** beta，5/25 全量 | **8/11** beta |
| 形态 | 终端里的 **CLI 编码 agent** | **云端常驻的通用办公 agent** |
| 干什么 | 跑本地代码库，plan→search→build，**最多 8 个并行子 agent 在 git worktree 里** | 操作 GUI，跨 app 完成多步任务 |
| 模型 | 8/12 起默认 Grok 4.6（50 万上下文） | 同 |
| 对标 | Claude Code / Codex | 通用 computer-use agent |

配套：**Grok Skills**（可复用 .zip/.skill/.md 技能包，**明确兼容 Claude Code 的 skills / plugins / CLAUDE.md**）、**Connectors**（GitHub/Notion/Linear/Google Workspace/Microsoft 365 + 自带 MCP；5/22 加 Vercel/Canva/Gamma/S&P Global）。

### 投资含义 `[INFERRED, LOW-MED]`

**若「不靠 API、直接操作 GUI」这条路走通，打击面是 SaaS 集成层和 RPA（UiPath 那一类），不是模型层。**

**但它现在的安全模型过不了企业合规。** beta 阶段 + 权限模型不成立 = **不进论点，只进观察项，不据此动任何仓位。**
