# Deep Dive（单公司深度复核）

## 给 Agent 的指令

对某家公司进行**全量论点复核**。这是评分可以变更的唯一日常入口（除月初强制重打）。

**前置确认**（用户应明确）：

- 目标公司 ticker（必填）
- 触发原因（财报 / 单日异动 / 产品发布 / 创始人事件 / 月度 review / 用户主动）

## 步骤（约 30-60 分钟）

### Step 1 · 读旧档（10 分钟）

- 读 `../../companies/<TICKER>.md` 全文
- 读最近 14 天 daily 日志中关于该公司的所有条目
- 注意上次评分时间 + 当时各维度 0/1/2

### Step 2 · 拉新事实（15 分钟）

WebSearch 列表：

- 公司近 30 天新闻（按时间倒序）
- 最近一次财报（关键 KPI / 指引 / 管理层评论）
- 创始人 / 关键高管最近 30 天公开发言
- 主要竞品最近 30 天动作
- 行业 / 宏观对该公司的特异性影响

### Step 3 · 七维度逐项重打（20 分钟）

对每个维度（0/1/2）：

```
### 维度 X · <名字>
旧分：N
新分：M
变化原因：(必须有 ≥ 1 条客观证据 + URL)
不变原因：(若无变化，简述为何不变)
```

七维度都要写——即使无变化。

### Step 4 · 估值情景重算（10 分钟）

更新「估值与目标位」段：

- 当前价 / 市值（WebSearch）
- 三档情景的 5 年 IRR（基准 / 乐观 / 悲观）
- 加权 IRR（按合理概率分布）
- 若加权 IRR < 12% → 提示"减仓 / 观察 / 不加仓"
- 若加权 IRR > 20% → 提示"潜在加仓机会，但需结合仓位上限"

### Step 5 · 论点状态判定

判定结果之一：

- **论点稳固**（评分不变 / +1）：留 core，可考虑加仓
- **论点弱化**（评分 -1 ~ -2）：减仓 / 观察
- **论点破裂**（评分 -3+，或某维度从 ≥1 降到 0）：clear position，重新放回 watchlist 观察恢复

### Step 6 · 写入

1. 公司卡 `../../companies/<TICKER>.md`：
   - 七维度评分表更新
   - 「当前进度 - 已经发生」追加触发事件
   - 「估值与目标位」整段重写
   - 「历史评分变更」追加一行
2. `../../shortlist.md`：如果排名变化，更新顺序与备注
3. `../../framework/scoring.md`：更新评分快照表
4. `../../daily/YYYY-MM-DD-deep-<TICKER>.md`（独立文件）：完整 deep-dive 笔记

## 字数预算

- 单次 deep-dive 输出 1500-3000 字
- 公司卡更新通常 < 500 字增量
- 独立 deep-dive 笔记 1000-2000 字

## 输出要求

deep-dive 笔记结构：

```
# YYYY-MM-DD · <TICKER> Deep Dive

## 触发
（为什么做这次 deep dive，1-2 句）

## 旧 vs 新评分
| 维度 | 旧 | 新 | Δ | 关键证据 |
|---|---|---|---|---|

## 论点状态判定
（稳固 / 弱化 / 破裂 + 一段说明）

## 三档情景与 IRR
（更新后的）

## 仓位含义
（具体到加 / 减 / 持 / 清，但措辞用"对应仓位动作建议..."而非"建议买入"）

## 接下来 3-7 天关注
（明确事件 + 来源）
```

## 完成后简报

```
[<TICKER> deep-dive 完成]
- 总分：旧 N → 新 M (Δ ±X)
- 状态：稳固 / 弱化 / 破裂
- 仓位含义：<一句话>
- 已更新：companies/<TICKER>.md, shortlist.md, scoring.md, daily/YYYY-MM-DD-deep-<TICKER>.md
```

## 不要做

- 不要因为单日股价波动就改维度 7（估值是基于 5 年 IRR，不是 1 日股价）
- 不要预测短期股价
- 不要给出现金流 DCF 模型——这不是估值方法的问题
- 不要在没有 WebSearch evidence 的情况下重打分
