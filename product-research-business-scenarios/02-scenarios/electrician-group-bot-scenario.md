# 电工任务群场景说明

## 场景概述

给每个电工创建一个任务群，群内包含电工、调度员/主管和机器人。新任务到来时，由机器人自动在群内派发；电工在群内按固定格式或按钮反馈状态；机器人将反馈转成结构化数据，生成表格、统计和分析。

## 目标

- 让任务派发有记录、有确认、有状态
- 让反馈从聊天信息变成可统计数据
- 让主管从“盯聊天”变成“看报表和异常”

## 基本流程

1. 调度员创建任务或导入任务
2. 机器人向对应群发送任务卡片
3. 电工确认接单
4. 电工反馈到场、开工、完工或异常
5. 机器人追问缺失字段
6. 系统自动沉淀任务台账
7. 主管查看日报、周报、异常分析

## 机器人可承担的动作

- 发送任务卡片
- 催接单
- 催反馈
- 识别关键词并结构化
- 对缺失字段补问
- 超时提醒
- 汇总日报/周报
- 输出个人、区域、任务类型分析

## 推荐最小反馈字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 任务编号 | 是 | 便于关联任务 |
| 当前状态 | 是 | 已接单 / 已到场 / 已完工 / 异常 |
| 时间 | 是 | 状态发生时间 |
| 异常类型 | 否 | 仅异常时填写 |
| 异常说明 | 否 | 仅异常时填写 |
| 图片凭证 | 否 | 完工或异常时可上传 |

## 关键风险

- 一个电工一个群，后续群数量可能快速膨胀
- 电工可能仍然偏好语音和自由文本
- 群平台机器人权限可能不足
- 数据结构化准确率决定后续分析质量

## 调研重点

- 群是按“个人”建还是按“班组/区域”建
- 机器人是按钮式交互还是关键词式交互
- 主管真正需要哪些报表，而不是先做一堆泛化分析
- 电工在现场是否方便及时反馈
