## 1. RK3506 网关项目整体怎么理解

[INFERRED][HIGH] 本项目可以按以下链路理解：

```text
现场设备
  │  RS485 / DI / DO / AI / AO
  ▼
RK3506 网关采集与控制后端
  ├─ 读取设备状态
  ├─ 解析点表与工程值
  ├─ 执行本地控制和安全检查
  ├─ 提供本地 HMI 接口
  └─ 通过 MQTT 与云端通信
          │
          ▼
        EMQX
          │
          ▼
云端 Go 后端 → 数据库 / 告警 / 用户权限 / Web 管理后台
```

- [COMMON][HIGH] **EMQX** 是 MQTT Broker，负责接收、路由和投递网关与云端服务之间的 MQTT 消息。
- [COMMON][HIGH] EMQX 不是设备业务后端，也不负责决定泵阀该不该动作。
- [INFERRED][HIGH] 图中的 **Go 后端** 指云端管理系统的业务服务，不是 RK3506 内部采集程序，也不是 MCU 固件。
- [COMMON][HIGH] 云端 Go 后端通常处理设备档案、用户权限、告警、历史数据、命令记录和管理后台 API。
- [COMMON][HIGH] RK3506 侧负责贴近现场的采集、协议解析、本地控制、断网自治和安全边界。

## 2. ACL、QoS 和会话管理

- [KNOWN][HIGH] **ACL** 是访问控制列表，用来限制某个客户端允许连接、订阅和发布哪些 MQTT Topic。
- [COMMON][HIGH] ACL 可以阻止一个网关读取或控制不属于自己的设备 Topic。
- [KNOWN][HIGH] **QoS 0** 是最多发送一次，消息可能丢失，但开销最低。
- [KNOWN][HIGH] **QoS 1** 是至少到达一次，消息可能重复，因此消费者必须处理重复消息。
- [KNOWN][HIGH] **QoS 2** 是恰好到达一次的 MQTT 协议交付流程，握手和状态开销最大。
- [KNOWN][HIGH] **会话管理**保存客户端订阅、未完成的 QoS 流程和离线消息等状态，使客户端重连后可以继续之前的通信上下文。
- [COMMON][HIGH] 网关网络不稳定时，如果没有合适的会话策略，重连后可能漏消息、重复订阅或丢失未完成的 QoS 消息。
- [KNOWN][HIGH] MQTT 的交付保证不等于物理设备动作保证；泵是否真的启动仍要依靠现场反馈点确认。

## 3. RS485 和 Modbus 是不是固定组合

- [KNOWN][HIGH] RS485 定义的是差分电气接口，不规定寄存器、功能码或设备数据含义。
- [KNOWN][HIGH] Modbus RTU 是常运行在 RS485 上的应用协议，但 RS485 也可以承载厂家私有协议或其他串口协议。
- [KNOWN][HIGH] 看到设备带 RS485 接口，不能直接推断它一定支持 Modbus。
- [KNOWN][HIGH] 是否支持 Modbus、使用哪些功能码以及寄存器地址，必须以准确型号的通信手册为准。

## 4. 同一条 RS485 总线是否强制使用 9600

- [KNOWN][HIGH] 不是强制使用 `9600`。
- [COMMON][HIGH] 一条普通 Modbus RTU 总线在同一次通信配置下，所有参与设备需要兼容相同的波特率、数据位、校验位和停止位。
- [COMMON][HIGH] 可以统一配置成 `9600 8N1`，也可以是手册支持的 `19200 8E1` 等组合。
- [KNOWN][HIGH] 从站地址必须避免冲突，否则两个设备可能同时响应并造成报文碰撞。
- [COMMON][HIGH] 如果现场设备无法统一串口参数，应拆到不同 RS485 端口或不同总线；频繁切换参数轮询不是可靠的默认设计。

## 5. 校验位、停止位和 8N1

- [KNOWN][HIGH] UART 发送一个字符时，通常包含起始位、数据位、可选校验位和停止位。
- [KNOWN][HIGH] **校验位**对单个 UART 字符做简单奇偶检查，可以发现部分传输错误，但不能代替 Modbus 整帧 CRC。
- [KNOWN][HIGH] `N` 表示无校验，`E` 表示偶校验，`O` 表示奇校验。
- [KNOWN][HIGH] **停止位**标记字符结束并为接收端重新同步留出时间。
- [KNOWN][HIGH] `8N1` 表示 8 个数据位、无校验位、1 个停止位。
- [KNOWN][HIGH] `9600 8N1` 表示每秒 9600 个符号，字符格式为 8 数据位、无校验、1 停止位。

[COMMON][HIGH] 可用“快递包装”记忆：数据位是货物，校验位是简易封条，停止位是两个包裹之间的间隔。

## 6. 大端和小端

- [KNOWN][HIGH] 大端表示多字节数值的高位字节放在低地址或先传输的位置。
- [KNOWN][HIGH] 小端表示多字节数值的低位字节放在低地址或先传输的位置。
- [COMPUTED][HIGH] 数值 `0x1234` 按大端排列是 `12 34`，按小端排列是 `34 12`。
- [KNOWN][HIGH] Modbus 单个 16 位寄存器的数据字节按高字节在前传输。
- [COMMON][HIGH] 32 位或 64 位数据跨多个寄存器时，厂家可能采用不同字序，不能仅凭“大端/小端”四个字猜测。
- [COMMON][HIGH] 嵌入式开发者不必死记所有平台的默认端序，但必须知道何时检查协议手册、抓取原始字节并验证字节序和字序。

## 7. MCU、单片机和 RK3506

- [KNOWN][HIGH] MCU 是 Microcontroller Unit，即微控制器。
- [COMMON][HIGH] 中文工程语境中，MCU 与“单片机”通常指同一类器件。
- [KNOWN][HIGH] MCU 通常把 CPU、存储器、GPIO、定时器、UART、ADC 等功能集成在一颗芯片中。
- [COMMON][HIGH] MCU 适合确定性强、启动快、资源较小的实时采集和控制任务。
- [INFERRED][HIGH] 本项目中的 RK3506 运行 Linux，适合设备管理、网络通信、HMI 和复杂业务；MCU 或 M0 更适合快环、安全兜底和确定性 I/O。
- [COMMON][HIGH] Linux 侧发出命令不应绕过 MCU、硬接线或设备自身的安全联锁。

## 8. 干接点和湿接点

- [KNOWN][HIGH] **干接点**自身不提供电压，本质上只提供导通或断开状态，例如普通继电器触点。
- [KNOWN][HIGH] **湿接点**在有效状态下携带规定电压，例如输出 `24V DC` 表示有效。
- [COMMON][HIGH] 接入 DI 前必须确认输入模块期望干接点还是湿接点，并核对公共端、电压极性和允许电压范围。
- [COMMON][HIGH] 把外部带电的湿接点误接到仅接受无源触点的端子，可能导致误动作或硬件损坏。

## 9. 开关量和寄存器有什么区别

| 对象 | [KNOWN][HIGH] 典型宽度 | [KNOWN][HIGH] 典型含义 | [KNOWN][HIGH] 常见功能码 |
|---|---:|---|---|
| Coil 线圈 | 1 bit | 开关命令，可读写 | `01`、`05`、`0F` |
| Discrete Input 离散输入 | 1 bit | 开关反馈，只读 | `02` |
| Input Register 输入寄存器 | 16 bit | 测量值，只读 | `04` |
| Holding Register 保持寄存器 | 16 bit | 参数或数值，通常可读，是否可写由设备定义 | `03`、`06`、`10` |

- [COMMON][HIGH] 开关量适合表达开/关、运行/停止、报警/正常等二态信息。
- [COMMON][HIGH] 寄存器适合表达温度、压力、频率、累计量和参数等数值。
- [KNOWN][HIGH] 一个 32 位值通常占两个连续的 16 位寄存器，但实际数据类型、字节序和字序由设备手册定义。

## 10. 常用 Modbus 功能码

| 功能码 | [KNOWN][HIGH] 动作 |
|---|---|
| `01` | 读线圈 |
| `02` | 读离散输入 |
| `03` | 读保持寄存器 |
| `04` | 读输入寄存器 |
| `05` | 写单个线圈 |
| `06` | 写单个保持寄存器 |
| `0F` | 写多个线圈 |
| `10` | 写多个保持寄存器 |

- [KNOWN][HIGH] 设备不一定支持表中的全部功能码。
- [KNOWN][HIGH] 某地址是否可写必须以设备寄存器表为准，不能因为功能码存在就尝试写入。

## 11. 教学报文：写开关量、读寄存器、写寄存器

[KNOWN][HIGH] 以下示例假设 Modbus RTU 从站地址为 `1`；串口参数另行配置，不属于报文字节。

### 11.1 打开协议地址 0 的单个线圈

```text
请求：01 05 00 00 FF 00 8C 3A
响应：01 05 00 00 FF 00 8C 3A
```

- [KNOWN][HIGH] `01` 是从站地址，`05` 是写单个线圈，`00 00` 是协议地址 0。
- [KNOWN][HIGH] `FF 00` 表示 ON，`00 00` 表示 OFF。
- [COMPUTED][HIGH] `8C 3A` 是该请求的 Modbus CRC16，线上按低字节在前发送。
- [KNOWN][HIGH] 功能码 `05` 成功响应通常回显请求，表示协议层接受了写入。

### 11.2 从协议地址 0 开始读取两个保持寄存器

```text
请求：01 03 00 00 00 02 C4 0B
示例响应：01 03 04 01 2C 00 19 FB CC
```

- [KNOWN][HIGH] `03` 是读保持寄存器，`00 00` 是起始协议地址，`00 02` 是读取两个寄存器。
- [KNOWN][HIGH] 响应中的 `04` 表示后续有四个数据字节。
- [COMPUTED][HIGH] `01 2C` 等于十进制 300，`00 19` 等于十进制 25。
- [COMPUTED][HIGH] `FB CC` 是该示例响应的 Modbus CRC16。

### 11.3 向协议地址 100 写入原始值 300

```text
请求：01 06 00 64 01 2C C8 58
响应：01 06 00 64 01 2C C8 58
```

- [KNOWN][HIGH] `06` 是写单个保持寄存器。
- [COMPUTED][HIGH] `00 64` 是十进制协议地址 100，`01 2C` 是十进制原始值 300。
- [COMPUTED][HIGH] `C8 58` 是该请求的 Modbus CRC16。
- [COMMON][HIGH] 原始值 300 对应多少工程值，必须结合设备手册中的数据类型、倍率、偏移和单位解释。

## 12. 读取有数据返回，写入有没有返回

- [KNOWN][HIGH] 普通 Modbus 单播写入也有响应。
- [KNOWN][HIGH] 读取响应返回“读到的数据”，单点写入响应通常回显“写入了哪个地址和什么值”。
- [KNOWN][HIGH] 功能码 `10` 写多个寄存器时，成功响应只确认起始地址和写入数量，不回显全部数据。
- [KNOWN][HIGH] 异常响应会把原功能码最高位置 1；例如功能码 `06` 的异常功能码是 `86`。
- [KNOWN][HIGH] 广播地址 `0` 的写请求没有响应，所有从站都不得回复，以避免总线冲突。
- [COMMON][HIGH] 单播写入完全无响应通常应检查地址、波特率、8N1/8E1、CRC、接线、RS485 收发方向、设备在线状态和超时设置。
- [COMMON][HIGH] 写入响应只证明协议请求被设备接受，不证明泵、阀或继电器已经产生预期物理动作。
- [COMMON][HIGH] 对控制点应读取同一状态寄存器或独立反馈点，完成写后回读和动作确认。

## 13. 地址为什么容易差 1

- [KNOWN][HIGH] Modbus 报文中的协议地址是从 0 开始的偏移量。
- [COMMON][HIGH] 一些手册使用 `00001`、`30001`、`40001` 等人类可读参考编号，因此参考编号 `40001` 在报文里常对应协议地址 `0000`。
- [COMMON][HIGH] 不同厂家手册写法并不统一，必须确认表格给的是参考编号还是协议偏移量。

## 14. 幂等是什么意思

- [KNOWN][HIGH] 幂等表示同一业务命令执行一次或重复执行多次，最终业务效果相同。
- [COMMON][HIGH] “把设定温度设为 50℃”容易设计成幂等；“温度增加 5℃”不是天然幂等。
- [COMMON][HIGH] MQTT QoS 1 可能重复投递，网关应使用唯一 `command_id` 识别重复命令。
- [COMMON][HIGH] 重复的 `command_id` 不应再次写现场设备，而应返回第一次执行的已保存结果。
- [COMMON][HIGH] 幂等去重不能替代写后回读、有效期检查、安全联锁和权限校验。

## 15. 真设备接入必须拿到什么手册

[KNOWN][HIGH] 至少需要与准确制造商、型号、硬件版本和固件版本匹配的通信手册或官方寄存器表，并确认：

1. [KNOWN][HIGH] 物理接口、端子定义、A/B 极性、参考地、隔离、终端电阻和拓扑。
2. [KNOWN][HIGH] 波特率、数据位、校验位、停止位、从站地址范围和配置方法。
3. [KNOWN][HIGH] Modbus 变体、功能码、CRC、超时、最大连续读写数量和异常响应。
4. [KNOWN][HIGH] 每个点的地址、长度、读写权限、数据类型、符号、字节序、字序、倍率、偏移、单位和有效范围。
5. [KNOWN][HIGH] 写入前置条件、解锁流程、联锁、副作用、掉电保存、写入寿命、重启行为和恢复方式。
6. [KNOWN][HIGH] 写入后的确认方式，以及能否通过状态寄存器或独立反馈点验证物理动作。

[COMMON][HIGH] 推荐顺序是：准确手册 → 点表 → 离线报文测试 → 现场只读验证 → 单点白名单写入 → 写后回读 → 故障和断网测试。
