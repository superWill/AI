## 1. Modbus 是什么:一问一答(主从 / client-server)

Modbus 骨子里是**请求/响应**:**主站主动发请求,从站只能被问到才回**,从站永远不主动开口。
- 新标准改了叫法:**主站→客户端(client),从站→服务器(server)**,模型不变(server 不主动推送)。
- **Modbus RTU(串口)**:一条总线**只能一个主站**,多个从站。
- **Modbus TCP**:可多个 client 连一个 server,但仍是"谁发请求谁是主、server 只应答"。

**结论:Modbus 永远有"发起方/应答方"这个不对称关系,没有对等模式。**

## 2. 帧格式(用 demo 的真实字节拆)

帧 = `[从站地址][功能码][数据…][CRC低][CRC高]`

### 正常读保持寄存器(功能码 0x03)
```
主站发: 01 03 00 00 00 02 C4 0B
        │  │  └─┬─┘ └─┬─┘ └─┬─┘
        │  │  起始0   读2个  CRC
        │  └ 03=读保持寄存器
        └ 从站地址1

从站回: 01 03 04 00 EB 01 E6 0A 1D
        │  │  │  └─┬─┘ └─┬─┘ └─┬┘
        │  │  │  寄存器0 寄存器1 CRC
        │  │  └ 后续4字节
        │  └ 03
        └ 1号
        00EB=235→23.5℃   01E6=486→48.6%RH
```

### 异常响应(从站回错误)
```
01 83 02 C0 F1
   │  └ 异常码 02=非法寄存器地址
   └ 83 = 03|0x80,最高位置1 = "这是异常"
```
常见异常码:`01`非法功能码 / `02`非法数据地址 / `03`非法数据值 / `04`从站故障。
**主站必须会认 0x80 这个标志,别把异常当数据。**

### 无响应 = 超时
喊一个不存在的从站(或设备掉线),总线上没人应 → **主站靠超时判定"这台没了"**。

### 常用功能码
| 码 | 动作 |
|---|---|
| 0x01/0x02 | 读线圈 / 读离散输入 |
| 0x03/0x04 | 读保持寄存器 / 读输入寄存器(最常用) |
| 0x05/0x06 | 写单个线圈 / 写单个寄存器 |
| 0x0F/0x10 | 批量写线圈 / 批量写寄存器 |

## 3. 为什么 RS485 一定要主从

主从**不是 RS485 芯片自带的**,是 RS485 这种总线结构**逼出来的纪律**。三个特性叠加:

1. **共享**:多设备挂同一对线(A/B,multi-drop)。
2. **半双工**:同一根线,**同一时刻只能一个在发**。
3. **无冲突仲裁**:RS485 电气层不带"谁先说/撞了怎么办"。两个同时发 → 信号叠加成乱码,且谁都不知道撞了。

硬件不管"谁该说话",就必须上层定纪律。最简单的就是**主从轮询**:只有主站主动开口、每次只点名一个从站,被点到的那一个才回 → **任何时刻只有一个发送者,不会撞车**。

---

## 4. 对照:不同介质怎么解决"谁能说话"

| 介质 | 结构 | 要主从吗 | 怎么避免撞车 |
|---|---|---|---|
| **RS485** | 共享、半双工 | **要** | 主从轮询(Modbus) |
| RS232 / TCP | 点对点、全双工 | 不强制 | 各走各的线,本就不撞 |
| **CAN** | 共享 | 不要(多主) | 硬件按 ID 优先级**仲裁** |
| I2C | 共享 | 可多主 | 硬件仲裁 |
| Profibus | 共享 | 非单主 | **令牌**:拿到令牌才能说 |

**不是 Modbus 一定要主从,是"共享总线必须有发言纪律",Modbus 选的纪律就是主从。**

## 5. 硬件仲裁怎么做(CAN 为例)

CAN 多主、无需主站,靠**两个绝招**配合,全程不用 CPU、不丢数据:

**① 线与(wired-AND):0 永远压过 1。**
任何节点发 0(显性 dominant),整条线就是 0;全发 1(隐性 recessive)才是 1。
实现:发送端开漏/差分收发器——发 0 是主动拉,发 1 是松手,**主动拉的赢**。

**② 边发边听:发一位立刻读回总线。**
```
我发  我读到   结论
 0     0      没冲突,继续
 1     1      没冲突,继续
 1     0  ←   有人发0(比我强)→ 我输,立刻闭嘴转接收
```

逐位比 ID(从高位起),**ID 数值更小 = 优先级更高 = 赢,且赢家的帧一位都没被破坏**(非破坏性仲裁,不用重发);输家等空闲重试。
> 对比老以太网 CSMA/CD:撞了双方都废、都重发。CAN 是"撞了也分高低、赢家无损",所以实时性/确定性强。

**I2C 同理**:SDA 开漏线与,想发 1 却读到 0 → 输,退出。

## 6. 串口"连通" vs Modbus 多了什么

| 串口连通 | Modbus |
|---|---|
| 把字节发过去/收回来 | **从站地址**:一条总线挂多设备,点名通信 |
| 自己约定数据含义 | **功能码**:读/写标准动作 |
| —— | **寄存器**:数据按编号摆放,标准寻址 |
| —— | **CRC**:每帧自带校验,错了就丢 |
| —— | **异常码/超时**:出错有标准反馈 |
