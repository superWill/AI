# ADR: RK3506 与 MCU 的职责划分

> 状态：已接受（待现场安全等级确定后在方案 A/B 间二选一）
> 关联：[控制网关 PRD §6 安全分层](../product/thermal-control-gateway-prd.md) · [分阶段方案 P0a 选型](../product/thermal-control-gateway-phased-plan.md)
> 适用：热源控制网关（RK3506 + MCU + 机械/硬接线安全）

## 背景与诉求

希望用 RK3506 这类嵌入式 SoC 承担部分原本放在 MCU 上的工作，动机是 **MCU 定制性不强、可扩展能力差**。

核心判断：这两个痛点的根源不是 MCU 本身，而是**把灵活的业务/协议逻辑放在了 MCU 上**。这类逻辑放 Linux 才是正路。因此"搬过去"对这部分完全正确；真正要谨慎的只有"独立性/确定性"这一小块。

## 决策：按能力分，不按芯片分

MCU 当前承担的工作拆成两类，分别归位：

| 类别 | 例子 | 归属 |
|---|---|---|
| **灵活/可扩展逻辑**（痛点所在） | 协议适配、点表、控制策略、PID、状态机、HMI、MQTT、日志、配置、OTA | **RK3506 A7-Linux** |
| **确定性/独立性逻辑** | 看门狗、失效安全输出、硬实时快环 | **独立故障域**（片内 M0 或独立 MCU） |

灵活逻辑搬到 Linux 后，"加协议 = 加驱动+服务、加设备 = 改配置"，定制性/扩展性痛点消失。

## 为什么 RK3506 适配

RK3506 自带 **Cortex-M0 协处理器 + CAN-FD / 多 UART/SPI/PWM 等工业外设**，Rockchip 定位即"MPU 干 MCU+ 的活"。可形成两全结构：

```text
A7 ×3  跑 Linux    → 灵活逻辑、慢控制环（供温 PID 1–5s，Linux 绰绰有余）、HMI、上报
M0     跑 RTOS/裸机 → 确定性快环、稳定 I/O 时序（补 Linux 非确定性）
```

## 关键约束：片内 M0 ≠ 安全隔离

M0 与 A7 **同一硅片、同一供电域**：能解决**实时性**，但芯片掉电/过热/晶圆级故障时与 A7 一起失效，**不能充当 A7 的安全兜底**。

## 安全前提（已在 PRD 定）

真正的最后一道防线是 **机械（安全阀、失电关阀）+ 硬接线（急停、关键联锁）**，不是软件。安全分层：

```text
机械安全 > 硬接线联锁 > MCU > RK
```

这条结论把"独立电子看门狗"这一小块解放出来——因为电子件之外已有机械/硬接线兜底，电子看门狗放哪可按安全等级权衡。

## 两个可选方案（按安全等级二选一）

### 方案 A：RK3506（含 M0）挑大梁 + 极简独立看门狗 MCU（推荐用于高安全场景）

```text
RK3506 A7-Linux:        全部灵活逻辑 + 慢控制环
RK3506 M0:              确定性 I/O / 快环（若有）
独立小 MCU(STM8/STM32): 仅看门狗 + 失效安全输出，固件冻结永不改
机械/硬接线:            安全阀、失电关阀、急停（最后防线）
```

要点：独立 MCU **只干一件极简、几乎永不变更的事**，因此不存在"定制性/扩展性"问题——MCU 回归"傻而可靠"的本分，业务全在 RK。

### 方案 B：纯 RK3506（片内 M0 当看门狗），靠机械/硬接线兜底（推荐用于热源等慢过程）

```text
省掉独立 MCU，BOM 更低。
前提：机械安全阀 + 失电关阀 + 硬接线急停 确为最后防线；
      电子看门狗仅作纵深防御，而非唯一安全保证。
适用：热源这类慢过程 + 有机械兜底的场景。
```

### 选择标准

- 慢过程 + 有可靠机械/硬接线兜底（如热源） → **方案 B** 即可。
- 会快速伤人/毁设备、或需要电子件独立失效域 → **方案 A**。

## 搬到 Linux 必须解决的工程问题

MCU 即插即用，Linux 不是；以下不处理则长跑会出事：

1. **上电安全态**：Linux 启动需数秒，这期间输出状态须由**失电关阀/硬接线默认安全**保证，不能等 Linux 起来。
2. **掉电文件系统**：突断电会坏 rootfs → **只读根 + 小读写分区 + 日志型文件系统**，或 M0 处理优雅落电。
3. **GPIO/PWM 抖动**：负载高时时序抖 → 快时序**卸载给 M0 或硬件 PWM/CAN**，不用 A7 软件 bit-bang。
4. **长跑稳定性**：Linux 会泄漏/卡死/磁盘满 → **硬件看门狗**（M0 或独立 MCU）拉起 + 日志滚动限额。
5. **EMC/隔离**：与换 SoC 无关，隔离 I/O、24V、浪涌防护照常要做。

## 落地动作（接 P0a 选型）

- 控制核心选 **RK3506 并用上其 M0**，灵活逻辑全放 A7-Linux。
- 安全最后防线交给**机械/硬接线**。
- 独立电子看门狗：热源默认**方案 B**；现场安全等级要求高再升**方案 A**。
- 现场安全等级一旦确定，据"选择标准"锁定 A 或 B，并更新本 ADR 状态。

## 一句话

> 业务逻辑搬去 RK3506-Linux 是对的，这就是它存在的意义；但"看门狗+失效安全"要留在独立故障域（片内 M0 或极简独立 MCU），且真正的最后防线是机械/硬接线——不是任何软件。"MCU 定制性差"是把它用错了，让它回归"傻而可靠"，痛点自然消失。
