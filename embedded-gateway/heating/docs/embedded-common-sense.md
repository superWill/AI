# 嵌入式常识清单（分领域 · 标注 AI 能不能帮）

> 用途：把"老手脑子里那些常识"系统列出来，新人对照着长。
> 标注：**👤 = 人必须自己掌握/判断**（AI 够不着，重点）；**🤖 = AI 能帮**（一句话带过即可）。
> 配套：[成长路径](embedded-expert-growth-path.md) · [安全规则](safety/safety-rules-draft.md)
> 用法：遇到问题、或 AI 给了方案，先拿对应领域的👤条目过一遍——这是你的"刹车"。

---

## 0. 一条总纲

> **AI 让"写代码、查手册、搭协议"变廉价了；难的全在"物理世界 + 判断 + 责任"——也就是下面带 👤 的部分。**
> AI 没有眼睛、手、和对你这套硬件的现场认知，它会自信地错。**常识就是你识破它、不被它带沟里的能力。**

---

## 1. 供电与上电

- 👤 **板子行为诡异，先量电源。** 电压跌落、纹波大，是无数"灵异 bug"的真凶。
- 👤 上电前先量电压对不对（3.3V / 5V / 12V 别接错，接错可能烧）。
- 👤 电源功率要够；大电流外设（泵、阀、继电器）单独供电，别和 MCU 挤一路、共地乱走。
- 👤 有些芯片 core/IO 电源有**上电顺序**要求，顺序错可能锁死或损坏。
- 🤖 算分压/限流电阻、查芯片供电规格、画电源树——AI 能给初稿。

## 2. 时钟与复位

- 👤 **晶振不起振 = 整板不工作**，且现象千奇百怪；先确认时钟源真的在跑。
- 👤 时钟配错 → 所有依赖它的东西全乱：**波特率对不上、定时器不准、采样错**。通讯不通先怀疑时钟/分频。
- 👤 复位脚电平、看门狗复位要分清——"莫名重启"常是看门狗没喂或电源抖。
- 🤖 算 PLL/分频系数、读时钟树——AI 能帮。

## 3. 信号与总线（I2C / SPI / UART / 485）

- 👤 **不通先量波形，别改代码瞎试**——这是这一层的铁律。
- 👤 I2C：要上拉电阻；设备地址别冲突；不通先用逻辑分析仪看有没有 **ACK**。
- 👤 SPI：对齐 **mode（CPOL/CPHA）**；片选 CS 别忘、别接错。
- 👤 UART：**TX↔RX 要交叉**、必须共地；分清电平（TTL / RS232 / RS485 不能直连）。
- 👤 RS485：要收发使能控制、终端电阻、A/B 别接反；多机总线只能一个时刻一个说话。
- 🤖 写驱动初稿、解析协议帧、生成寄存器位定义——AI 能帮，**但要拿手册逐项核对它有没有读错**。

## 4. 网络与通讯（今天踩得最多）

- 👤 **分层排查，一层层往上，别跳：**
  ```
  物理(网线灯亮 L1) → 通不通(ping，L3) → 端口通不通(telnet 端口) → 应用(协议)
  ```
- 👤 **网线灯亮 ≠ 能通信**（L2 通、L3 不通，今天就是）；**ping 通 ≠ 端口通**（要单独测 TCP 端口）。
- 👤 IP / 子网掩码 / 网关 / 路由要配对；**同网段才能直连**；找某地址走错网口就到不了。
- 👤 **DNS 是单独一件事**：能 ping 通 IP 但域名解析失败，是 DNS 没配，不是网断。
- 👤 防火墙、端口没开放，也会"能 ping 不能连"。
- 👤 手动配的网络**可能是临时的**（重启没了），还可能被"网络管家"(NetworkManager)冲掉——今天都遇到了。
- 🤖 给排查命令、解释报错、列检查清单——AI 能帮（今天全程如此）。**但"现在卡在哪一层"要你看现象判断。**

## 5. 调试方法（最值钱的元常识）

- 👤 **先能稳定复现，再动手**；不能复现的 bug，改了也不知道好没好。
- 👤 **一次只改一个变量**；同时改三处，好了也不知道是哪处起的作用。
- 👤 **二分定位**：把问题范围一刀刀砍半。
- 👤 **仪器 > 日志 > 猜**：能量波形就别 print，能 print 就别猜。
- 👤 保留一个"能工作的版本"，随时能回退对比。
- 🤖 帮你列假设、解释报错、读 core dump/寄存器现场——AI 是好的"假设生成器"，**但不是结论**。

## 6. 固件 / 启动 / 存储

- 👤 **Flash 有写寿命**，别高频狂写同一块；写要按页擦除/对齐。
- 👤 **掉电保护**：写一半突然断电 = 文件/参数损坏；关键写入要有原子/双备份。
- 👤 OTA/bootloader **必须能回滚**——刷坏了不能变砖（尤其无人现场）。
- 👤 只读根文件系统的设备：改了东西重启就没（今天 BL412B 的网络配置也是这类临时态）。
- 🤖 写 OTA 流程框架、选文件系统、生成分区方案——AI 能帮。

## 7. 实时性与控制

- 👤 **中断里别干重活、别阻塞、别等**；ISR 要短，重活丢给主循环。
- 👤 任务优先级安排不当 → 优先级反转、关键任务被饿死。
- 👤 采样要够快又不能太占 CPU；硬实时有 deadline，超了就是故障。
- 👤 **控制环震荡先想物理**：执行器响应慢？传感器滞后？采样太快？——常是物理问题不是代码。
- 👤 PID 参数要按**你这台设备的真实响应**调，AI 给的初值只是起点。
- 🤖 PID 公式、滤波算法、调度理论讲解、生成框架——AI 能帮。

## 8. 内存与资源

- 👤 **栈会溢出**：深递归、大局部数组、中断嵌套都可能爆栈 → 随机死机/跑飞。
- 👤 堆碎片、`malloc` 失败、buffer 越界——嵌入式资源紧，要算清 RAM/Flash 够不够。
- 👤 **"随机死机"高度怀疑栈溢出或越界**。
- 🤖 估算内存占用、看 map 文件、静态分析工具——AI 能帮。

## 9. 安全与失效（人必须扛，AI 不会主动提醒）

- 👤 **分层兜底**：`机械 > 硬接线 > MCU > 软件`，**软件永远不是最后一道防线**。
- 👤 看门狗、失联/超时要回退到**安全默认**（你们的 `valid_until` 超时回本地策略就是）。
- 👤 任何执行（尤其外部下发的）先过**限值与联锁**校验，冲突就拒绝。
- 👤 每写一个功能就问：**"它坏了会怎样？伤不伤人/设备？谁兜底？"**
- 👤 **这是责任，不只是技术。** AI 只会把你要的功能写出来，**不会告诉你"这样写会烧锅炉"**。
- 🤖 生成看门狗、状态机、安全检查代码框架——AI 能帮，**但安全策略和边界你来定**。

## 10. 现场与工程（装到现场才暴露的占一大半）

- 👤 接线、接插件、**屏蔽、接地、EMI**：接地不好 = 各种莫名干扰；强弱电分开走线。
- 👤 工业环境的温度、湿度、振动、粉尘——实验室好好的，现场可能就出问题。
- 👤 现场调试条件差（没屏、没网、空间小），要提前想好怎么远程/串口进设备。
- 🤖 查接线规范、生成端子接线表、查 EMC 要求——AI 能帮。

## 11. 嵌入式 Linux 特有（BL412B / RK 这类带系统的板子）

- 👤 进设备靠 **SSH 或串口控制台**（无屏设备没有别的后门）。
- 👤 **没外网的设备装不了包** → 离线 vendor（今天 paho 就是这么搞的）。
- 👤 手动网络配置是临时的、会被网络管家冲掉（今天 `nmcli managed no` 才稳住）。
- 👤 程序要常驻：用 **systemd**，并配掉电自启、崩溃重启。
- 👤 **没有 RTC 的板子重启后时间乱**，要 NTP/手动同步——否则时间戳全错。
- 🤖 给命令、写 systemd unit、教离线装包——AI 能帮（今天全程）。

## 12. 协作与流程常识

- 👤 **出事先停手，别让情况更糟**：不确定时别急着重启/格式化/删（今天 `/etc` 误删，"先别重启"就是这条救的）。
- 👤 改之前先备份/能回退；用版本控制。
- 👤 不确定就**先评估再动手**，别在没掌握范围时做不可逆操作。
- 🤖 写 commit message、生成部署脚本、整理文档——AI 能帮。

---

## 怎么用这份清单

1. **排查问题时**：按领域翻到对应👤条目，常常一句话就点醒你卡在哪。
2. **AI 给方案时**：用👤条目当 sanity check——AI 没有现场和物理常识，这份清单就是你的刹车。
3. **带新人时**：让他每踩一个坑，回来在对应领域补一条自己的话——攒成你们团队自己的常识库。

> 记住总纲：**AI 会的（🤖）别花太多时间练；把精力压到 AI 干不了的（👤）——那才是你不可替代的地方。**
