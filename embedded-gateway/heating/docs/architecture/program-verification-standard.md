# 供热工业网关程序检测与验收标准

> [INFERRED][HIGH] 本文把学习过程中提到的可靠性、安全性和恢复要求，转成可执行、可记录、可验收的程序标准。  
> [COMMON][HIGH] 每个需求、代码模块、测试用例和缺陷单都应引用检测编号，避免只写“增强稳定性”这类无法验收的描述。

## 1. 使用规则

### 1.1 结果状态

| 状态 | 含义 |
|---|---|
| `PASS` | 检测完成，结果满足通过标准 |
| `FAIL` | 检测完成，但不满足通过标准 |
| `BLOCKED` | 缺少硬件、环境或前置条件，暂时无法检测 |
| `NOT_IMPLEMENTED` | 程序尚未实现该能力 |
| `NOT_APPLICABLE` | 经评审确认本型号不适用，并记录理由 |

### 1.2 优先级

| 等级 | 含义 |
|---|---|
| `P0` | [INFERRED][HIGH] 不通过时禁止进入现场控制运行 |
| `P1` | [INFERRED][HIGH] 不通过时禁止正式交付，或必须关闭相关功能 |
| `P2` | [INFERRED][HIGH] 可以进入受限试运行，但必须有整改计划 |

### 1.3 每次检测必须保存的证据

[COMMON][HIGH] 检测报告至少保存以下信息：

```text
检测编号
软件版本 / Git commit
配置版本
硬件型号与序列号
测试环境
输入条件和操作步骤
期望结果
实际结果
PASS / FAIL / BLOCKED
日志、抓包、截图或数据库记录
检测人员与检测时间
```

## 2. 配置与启动检测

| 编号 | 级别 | 检测项 | 检测方法 | 通过标准 | 失败后的程序动作 |
|---|---|---|---|---|---|
| `GW-BOOT-001` | P0 | 配置格式校验 | 删除必填字段、写入错误类型、重复点位 ID 后启动 | 程序拒绝激活配置，并指出具体字段 | 保持旧配置或进入维护模式 |
| `GW-BOOT-002` | P0 | 配置引用完整性 | 让联锁、反馈点或设备模板引用不存在的对象 | 编译或激活阶段拒绝配置 | 禁止带错误配置运行 |
| `GW-BOOT-003` | P0 | 配置量程合法性 | 设置下限大于上限、负超时、非法倍率 | 所有非法值被拒绝 | 保持当前有效版本 |
| `GW-BOOT-004` | P0 | 配置校验和 | 修改已保存配置中的任意字节 | 启动时发现校验失败 | 尝试备份；均失败则安全停机 |
| `GW-BOOT-005` | P1 | 配置版本兼容 | 使用旧 schema 和未知新 schema 启动 | 可迁移版本正确迁移；未知版本明确拒绝 | 不得静默按默认值运行 |
| `GW-BOOT-006` | P0 | 启动状态顺序 | 冷启动并记录状态变化 | 按 `BOOT → CONFIG_VALIDATING → FIELD_SYNCING → SAFE_IDLE/READY` 推进 | 未到 READY 前保持安全输出 |
| `GW-BOOT-007` | P0 | 点位初始质量 | 在现场数据尚未返回时读取快照 | 所有外部点初始为 `UNKNOWN/STALE`，不是 `GOOD` | 禁止未知关键点参与控制 |
| `GW-BOOT-008` | P0 | 启动输出安全 | 带负载或测试灯冷启动、快速上下电 | 初始化完成和联锁确认前，关键 DO 不产生危险脉冲 | 硬件和软件共同保持安全态 |

## 3. 采集、协议与质量码检测

| 编号 | 级别 | 检测项 | 检测方法 | 通过标准 | 失败后的程序动作 |
|---|---|---|---|---|---|
| `GW-ACQ-001` | P0 | 所有外部 I/O 有界超时 | 断开串口、网络和从站响应 | 调用在配置超时内返回，不永久阻塞 | 记录超时并继续其他任务 |
| `GW-ACQ-002` | P0 | CRC/帧校验 | 注入 CRC 错误、短帧和错误长度 | 错误帧不更新工程值 | 质量码变坏并统计错误 |
| `GW-ACQ-003` | P1 | Modbus 异常响应 | 返回 `0x83` 等异常帧 | 识别异常码，不当作普通数据解析 | 记录设备异常原因 |
| `GW-ACQ-004` | P0 | 单设备故障隔离 | 让一台从站离线，其他从站保持在线 | 正常设备仍按要求更新 | 离线设备退避探测 |
| `GW-ACQ-005` | P1 | 离线恢复 | 离线若干轮后恢复设备响应 | 一次或规定次数成功后恢复在线 | 清除连续失败计数并产生恢复事件 |
| `GW-ACQ-006` | P0 | 数据新鲜度 | 停止更新一个关键点并等待过期 | 超过 `stale_timeout` 后不再为 `GOOD` | 控制逻辑停止使用该点 |
| `GW-ACQ-007` | P0 | 工程量换算 | 输入量程端点、中点和边界外原始值 | 倍率、偏移、符号、字节序和单位均正确 | 越界值标记异常 |
| `GW-ACQ-008` | P1 | 物理范围检查 | 注入超出传感器量程的数值 | 标记 `OUT_OF_RANGE`，不伪装正常 | 产生诊断事件 |
| `GW-ACQ-009` | P1 | 信号故障识别 | 对 4–20 mA 通道注入断线/超量程电流 | 按设备说明书边界识别故障 | 标记传感器故障 |
| `GW-ACQ-010` | P1 | 跳变与卡值检测 | 注入单次尖峰和长时间不变化数据 | 按点位配置标记 `SUSPICIOUS/FROZEN` | 是否参与控制由安全策略决定 |
| `GW-ACQ-011` | P0 | 质量码传播 | 让原始采集点变为超时或坏帧 | 计算点、设备状态、HMI、MQTT 不得仍显示 `GOOD` | 保留故障来源 |
| `GW-ACQ-012` | P1 | 时间戳语义 | 延迟解析和上传同一条采样 | 同时区分采样时间、接收时间和上传时间 | 不用上传时间冒充采样时间 |

## 4. 任务调度与并发检测

| 编号 | 级别 | 检测项 | 检测方法 | 通过标准 | 失败后的程序动作 |
|---|---|---|---|---|---|
| `GW-RT-001` | P0 | 控制周期截止时间 | 在最大通信和界面负载下运行 | 关键任务的最坏执行时间和抖动不超过项目预算 | 超限计数并触发健康告警 |
| `GW-RT-002` | P0 | 控制路径不阻塞 | 审计调用链，并让数据库/MQTT故意卡住 | 控制任务不等待网络、磁盘、DNS或慢速串口 | 服务任务降级，控制继续 |
| `GW-RT-003` | P0 | 共享快照一致性 | 并发高频更新多字段，控制任务持续读取 | 每次读取只得到完整旧版本或完整新版本 | 不得出现半更新数据 |
| `GW-RT-004` | P0 | 竞态检测 | 多线程压力运行并重复启停 | 无随机状态错乱、重复输出和崩溃 | 失败即停止交付 |
| `GW-RT-005` | P0 | 死锁检测 | 注入锁竞争和异常返回路径 | 所有锁在限定时间内释放，任务心跳不中断 | 看门狗前先记录锁等待证据 |
| `GW-RT-006` | P1 | 优先级反转 | 让低优先级任务持锁，中优先级任务施压 | 高优先级控制任务阻塞不超过预算 | 缩短临界区或启用优先级继承 |
| `GW-RT-007` | P1 | 队列满载策略 | 提高生产速率直到各队列满 | 遥测可合并；命令明确拒绝；告警和审计不得静默丢失 | 记录溢出次数和最高水位 |
| `GW-RT-008` | P0 | 中断执行边界 | 测量 ISR 时间并检查调用 | ISR 不做网络、数据库、长循环或阻塞锁 | 将工作转交任务 |
| `GW-RT-009` | P1 | 绝对周期调度 | 长时间记录周期任务唤醒时间 | 周期误差不随执行轮数累计漂移 | 记录 deadline miss |
| `GW-RT-010` | P0 | 多任务看门狗 | 分别挂起采集、控制和输出任务 | 任一关键任务失去心跳时停止喂狗或进入安全态 | 保存复位原因 |

## 5. 控制与安全联锁检测

| 编号 | 级别 | 检测项 | 检测方法 | 通过标准 | 失败后的程序动作 |
|---|---|---|---|---|---|
| `GW-CTL-001` | P0 | 命令权限 | 使用无权限账户或来源下发命令 | 命令被拒绝并审计 | 不改变输出 |
| `GW-CTL-002` | P0 | 本地/远程模式 | 现场切换到本地模式后远程启动 | 远程命令被拒绝 | 返回明确原因 |
| `GW-CTL-003` | P0 | 命令限幅 | 下发超出安全上下限的设定值 | 写现场设备前被拒绝 | 记录 `blocked_by_safety` |
| `GW-CTL-004` | P0 | 命令限速 | 短时间内下发过大变化量 | 超过变化速率的命令被拒绝或受控斜坡处理 | 不产生突变输出 |
| `GW-CTL-005` | P0 | 联锁条件 | 分别触发急停、缺水、故障等条件 | 任一禁止条件成立时不写 DO/寄存器 | 记录具体联锁点 |
| `GW-CTL-006` | P0 | 联锁质量码 | 让关键联锁点超时、未知或异常 | 未知不按“安全正常”处理 | 进入配置的失效安全策略 |
| `GW-CTL-007` | P0 | 输出仲裁 | 自动、远程手动、本地和安全请求同时出现 | 输出结果符合经过评审的固定优先级 | 记录最终 owner 和 reason |
| `GW-CTL-008` | P0 | 写后反馈确认 | 输出启动命令但保持反馈关闭 | 在确认超时后判定失败 | 进入 FAULT/SAFE 状态并告警 |
| `GW-CTL-009` | P0 | 命令状态区分 | 执行一次正常和一次失败命令 | 正确区分 accepted/executing/executed/rejected/failed | 平台不得把 accepted 显示为已执行 |
| `GW-CTL-010` | P0 | 命令过期 | 延迟投递超过 `expires_at` 的命令 | 过期命令不执行 | 返回 `expired` |
| `GW-CTL-011` | P0 | 命令幂等 | 重复发送同一 `command_id` | 不重复产生物理动作，返回原结果或重复状态 | 保留去重记录 |
| `GW-CTL-012` | P0 | 失联回退 | 在远程控制过程中断开平台 | 本地联锁和自治继续，按策略处理远程所有权 | 不保持未经授权的无限期控制 |
| `GW-CTL-013` | P0 | 手动接管 | 自动运行时切换现场手动/本地 | 自动输出按策略释放，现场控制可接管 | 产生模式变更审计 |
| `GW-CTL-014` | P0 | 硬保护不可绕过 | 尝试通过软件命令覆盖急停/硬件保护 | 软件不能解除硬接线保护 | 禁止交付任何绕过路径 |

## 10. 可观测性与长期运行检测

## 11. 发布门禁

[INFERRED][HIGH] 建议按以下门禁决定版本能否进入下一阶段：

| 阶段 | 必须条件 |
|---|---|
| 开发自测 | 相关功能的 P0 用例全部执行，无已知越界、死锁和绕过联锁路径 |
| 集成测试 | 所有可自动化 P0/P1 用例纳入回归；失败用例有缺陷编号 |
| 板上测试 | GPIO 默认态、看门狗、串口、电源、存储、快速上下电和升级回滚通过 |
| 现场试运行 | 点表、量程、联锁、模式、反馈方向和安全输出经现场签字确认 |
| 正式发布 | P0 全部 `PASS`；P1 无未批准 `FAIL`；所有 `BLOCKED` 有风险结论 |
