# 热源控制网关 · 分阶段实现方案

> 用途：把 [PRD](./thermal-control-gateway-prd.md) 和 [设计辩论](./thermal-control-gateway-design-debate.md) 的结论，落成"项目可排期"的分阶段实现方案。采纳评审结论：**按"试点型热源控制终端"立项，不做"成熟自控柜替代品"承诺**；MVP 太大，拆成台架→现场顾问→有限自动→供暖季验证四段推进。
> 配套三张工程表（本文 §6）：现场 IO 表、安全联锁表、分阶段验收表。三张表补齐 = 从"方案可行"进入"可排期"。
> 优化平台联动的分阶段落点见 §4.5，依据 [数据接口契约](../protocols/upstream-platform-data-contract.md) 与 [补位策略](../business/upstream-platform-data-gap-filling.md)。

## 1. 立项口径（先把话说死）

```text
Go：可以继续做。
前提：先做试点产品，不做成熟替代品承诺。
```

- **可行**：作为"采集 + 顾问控制 + 安全协同 + 平台联动"的热源控制网关。
- **暂不可行**：作为"直接替代成熟 PLC 自控柜、无人值守全自动控制"的产品——需至少一个完整供暖季验证后再谈规模化。
- **战场**：中小热力站 / 楼栋热力入口 / 成本敏感 / 数据自主，不正面替换大站房成熟自控。

## 2. 排期硬约束：供暖季窗口

热源控制**只能在供暖季验证**——非供暖季无热负荷，现场顾问/自动控制无法真实测试。这决定了阶段必须卡时间窗：

```text
2026-06 ~ 2026-10（非供暖季）   →  P0a 台架验证（不依赖热负荷，吃满这个夏天）
2026-11 起（供暖季开始）        →  P0b 现场顾问模式（接真实泵阀，人确认）
供暖季 2026–27 期间             →  P1  有限自动控制（试点站、有人值守）
完整供暖季 2026–27 跑完          →  规模化决策（2027 春）
```

> 含义：**台架阶段是夏天唯一能全力推进的窗口，必须在 10 月底前把软件骨架+仿真闭环+硬件选型+三张表全部做完**，否则错过供暖季就要再等一年。

## 3. 阶段总览

| 阶段 | 名称 | 一句话目标 | 是否动真实热源 | 时间窗 |
|---|---|---|---|---|
| **P0a** | 台架验证 | 软件骨架在台架/仿真上跑通，不接真实执行机构 | 否（模拟输出） | 2026-06~10 |
| **P0b** | 现场顾问模式 | 接真实泵阀/补水/供温，系统给建议、人确认执行 | 半（顾问，安全项自动） | 2026-11 起 |
| **P1** | 有限自动控制 | 试点站开放供温/补水/循环自动闭环，有人值守 | 是（受监督） | 供暖季 26–27 |
| **P2** | 供暖季验证 + 能力补全 | 跑满一个供暖季，补压差/多泵/平台优化，再谈规模化 | 是 | 26–27 全季→27 春 |

每阶段都设**准入条件（entry）**和**出口标准（exit）**，不达标不进下一段。

## 4. 各阶段详细方案

### P0a 台架验证（2026-06 ~ 10，非供暖季主战场）

**目标**：在不接真实阀泵的前提下，把"采集→校验→控制策略→输出→上报→安全协同"的软件骨架全部跑通，控制效果在**仿真被控对象**上验证收敛。零热源风险。

**准入**：RK3506 开发板到位；DAQ4212 温度链路已通（现状已具备）。

**范围**：
- 传感器采集 + 标准点位模型（复用采集 PRD 点位模型）。
- 传感器校验（量程/断线/跳变/相关性）——`[决策5]` 重点先行。
- 气候补偿曲线 + 一次侧阀门 PID 微调，**输出到日志/仿真**，不驱动真实执行机构。
- 仿真被控对象（简化换热站热力学模型：滞后+惯性），让控制环能在台架上看到收敛/振荡。
- 状态机主干（自检/待机/启动/运行/调节/告警/急停）。
- 本地 HMI（复用 `prototype/hmi/`）。
- MQTT 心跳/遥测/告警/命令回执（contract 定稿）；遥测帧含**时间戳 + 质量码**，设定值下发/回传协议（FR-M09~M12）一并纳入 contract 草案。
- RK↔MCU 心跳协议草案 + **模拟 MCU**（看门狗/安全否决先仿真）。
- 日志 + 配置 schema + smoke test harness。

**复用现状**：`prototype/firmware-sim/`（C 模拟器）作控制环载体；`prototype/hmi/` 作 HMI；DAQ4212 温度采集已通。

**交付物**：
1. 点位模型 + 配置 schema。
2. MQTT topic/payload 规格（定稿）。
3. RK↔MCU 心跳/安全协议草案。
4. 仿真被控对象 + 控制环收敛曲线。
5. HMI 台架版。
6. smoke test + 24h 连续运行报告。
7. **三张表初稿**（IO 表模板、安全联锁表草案、验收表）——见 §6。

**出口标准**：
- [ ] 控制环在仿真对象上稳定收敛、无持续振荡。
- [ ] 传感器注入故障（断线/漂移/跳变）时，系统能识别并禁自动调节。
- [ ] 模拟 MCU 心跳超时 → 进入安全态；恢复需握手。
- [ ] MQTT/HMI/日志 24h 连续运行无异常、无内存增长。
- [ ] 三张表初稿完成，现场 IO 待确认项清单明确。

**不做**：真实阀泵驱动、工业级硬件、压差闭环、多泵、平台优化。

### P0b 现场顾问模式（2026-11 起，供暖季开窗）

**目标**：在试点站接入真实泵阀/补水/供温，系统**给出建议开度/动作，由运维确认执行**；安全相关（定压补水、急停、保护）按规则自动/硬接线。积累一个供暖季的现场基线数据。`[决策7]`

**准入（硬门槛，缺一不可）**：
- **现场 IO 表填实**（§6.1）——执行机构类型/接口/量程/控制方式全部确定。`[决策2]`
- **安全联锁表定稿**（§6.2）——机械/硬接线/MCU/RK 责任划清。`[决策4]`
- 试点站选定；机械安全阀、失电关阀、硬接线急停**到位并验收**。
- 工业级硬件就绪（隔离 IO、24V、浪涌、DIN、宽温）。`[决策8]`
- 真实 MCU 固件具备看门狗 + 关键保护。

**范围**：
- 真实多协议采集（DAQ/Modbus/串口）+ 现场点位标定。
- 传感器校验在真实噪声/干扰下生效。
- 顾问模式：HMI 显示建议动作，人工确认执行；阀泵不自动动。
- 定压补水**可自动**（安全相关，但受保护约束）。
- 现场调试与整定工作流：点动模式、曲线/PID/定压整定、整定留痕。`[决策6]`
- 真实 RK↔MCU 安全协同；硬接线急停联调。
- MQTT 上报真实数据 + 平台基线看板；上送即带**时间戳 + 质量码**，作为优化平台的现场标准化数据源（补位策略缺口②）。
- 条件具备时接入**荷侧/室温采集**（楼栋入口、抽样室温），补优化平台最缺的需求信号（缺口①）。

**交付物**：
1. 现场接入与标定记录。
2. 整定记录（每站曲线/PID/定压值）。
3. 供暖季基线数据集（供温、能耗、人工操作 vs 系统建议对比）。
4. 安全联锁现场验收报告。

**出口标准**：
- [ ] 真实数据稳定采集、校验在现场干扰下有效。
- [ ] 系统建议动作与有经验运维的人工操作方向一致（可量化对比）。
- [ ] 定压补水自动运行正确，补水失败能保护。
- [ ] 硬接线急停、机械安全阀、失电关阀现场实测有效。
- [ ] 现场整定工作流可用，调试人员能独立投运。

**这一阶段就是"信任建立期"**：不开放高风险自动动作，用数据证明系统判断可靠，为 P1 铺路。

### P1 有限自动控制（供暖季 26–27 期间，试点站）

**目标**：在 P0b 数据证明建议可靠后，在试点站**开放供温/补水/循环的自动闭环**，仍有人值守、可随时切顾问/手动。

**准入**：
- P0b 基线数据显示系统建议稳定、方向正确、无危险误判。
- 安全联锁全部现场验收通过。
- 现场运维认可切自动（不是研发单方面决定）。

**范围**：
- 气候补偿 + PID 自动驱动一次侧阀。
- 循环泵自动启停（一期恒速）+ 启动顺序联锁自动执行。
- 定压补水自动。
- 急停/保护人工确认复位。
- 自动/顾问/手动一键切换，本地优先。

**出口标准**：
- [ ] 自动连续运行 72h+，供温跟随曲线收敛、稳态无振荡。
- [ ] 阀门动作受限幅/死区/速率约束，无频繁满行程。
- [ ] 分层安全在自动运行下全部生效（含断 Linux 验证）。
- [ ] 断网后自动控制与保护继续，恢复后过期命令不补执行。
- [ ] 控制动作/整定/保护全程日志可追溯。

**不做**：多站规模化、变频压差闭环、无人值守。

---

### P2 供暖季验证 + 能力补全（26–27 全季 → 27 春决策）

**目标**：试点站跑满整个供暖季自动运行，收集节能/稳定性数据；同时补全二期能力。供暖季结束做规模化 Go/No-Go。

**范围**：
- 变频泵压差闭环、多泵轮换/一用一备。
- 远程模式完整化 + 命令安全校验 + 断网缓存补传。
- **优化平台设定值闭环执行**（FR-M09~M12）：平台下发目标供温/阀位 → 本地 PID 执行 → 回传 achieved；带 valid_until，失联超期回退本地自治。见 [PRD §8.6](./thermal-control-gateway-prd.md)。
- 平台侧：分时多段曲线、节能寻优、跨站点调度。
- 节能与稳定性量化报告（vs 人工/vs 改造前）。

**规模化 Go/No-Go 依据**：
- 供暖季无安全事故、无因控制误动作导致的投诉/停热。
- 节能或供热品质相对人工有可量化改善。
- 现场整定与运维成本可控、可复制。

### 4.5 优化平台联动的分阶段落点

平台联动横跨多个阶段，遵循"**先做干净数据源，再做策略执行端**"的次序（与 [补位策略](../business/upstream-platform-data-gap-filling.md) 的价值排序一致）。

| 能力 | 落在阶段 | 说明 | 依据 |
|---|---|---|---|
| 上行协议 + 时间戳/质量码定稿 | **P0a** | contract 草案含遥测帧时间戳、质量码、设定值下发/回传 | 缺口② |
| 标准化数据上送（带时间戳+质量码） | **P0b** | 真实数据流向平台，成为现场标准化数据源 | 缺口② |
| 荷侧/室温采集补位 | **P0b（条件具备时）** | 补平台最缺的需求信号，显著提升负荷预测 | 缺口①（最高价值） |
| 盲区中小站覆盖 | **P0b→P2** | 随网关低成本铺开自然带来 | 缺口③ |
| 设定值闭环执行（FR-M09~M12） | **P2** | 平台给目标值、本地 PID 执行、回传 achieved | 缺口④ |
| 断网缓存补传（seq 连续、replay） | **P2** | 平台时间序列无洞 | 缺口⑤ |

**次序逻辑**：P0b 先把"现场标准化数据源"做实（最易证明价值、最易谈合作）；闭环执行门槛最高、风险最大，放到 P2 控制能力成熟、平台优化上线后再做。安全边界不变——平台始终是顾问/优化角色，不绕过 机械>硬接线>MCU>RK。

## 5. 跨阶段风险与缓解（评审 5 大风险落到阶段）

| 风险 | 缓解动作 | 落在阶段 |
|---|---|---|
| 传感器漂移/接线错误致错误控制（比断网更危险） | 传感器校验 P0a 先行；关键测点故障禁自动调节 | P0a 设计 / P0b 现场验证 |
| 执行机构不确定（4-20mA/0-10V/三点/Modbus 控制模型不同） | 现场 IO 表为 P0b 硬门槛，不填不接真实阀 | P0a 出表 / P0b 准入 |
| 安全责任与合规边界（动泵阀=安全相关产品） | 安全联锁表分层定责；机械安全阀/失电关阀/硬接线急停优先 | P0b 准入 |
| 现场整定成本被低估 | 交付调试/点动模式 + 整定工作流 + 留痕，不靠发 JSON | P0b |
| 工业化硬件成本（隔离/24V/浪涌/DIN/宽温/存储） | 工业级载板纳入 BOM；成本表述诚实化；日志留存策略 | P0a 选型 / P0b 硬件 |

### 6.2 安全联锁表（P0b 硬门槛）

明确每项保护"由谁兜底"，对应 `[决策4]` 四层：机械 > 硬接线 > MCU > RK。

| 保护项 | 触发条件 | 兜底层 | 动作 | 复位方式 | 验证方法 |
|---|---|---|---|---|---|
| 超压泄压 | 供压 > 安全阀整定 | **机械** | 安全阀机械泄压 | 自复位/检修 | 现场打压试验 |
| 超压预防 | 供压 > 软高限 | MCU/RK | 降泵频/停补水/降负荷 | 自动 | 注入高压信号 |
| 断电关阀 | 失电 | **机械** | 弹簧复位关一次侧阀 | 上电恢复 | 断电实测 |
| 急停 | 按下急停 | **硬接线** | 直接断执行回路 | 人工复位 | 现场按动实测 |
| 泵故障联锁 | 变频器/泵故障干接点 | **硬接线** | 停故障泵（启备用） | 人工/自动 | 模拟故障信号 |
| RK 失控 | RK 心跳超时 | **MCU** | 进安全态（关/减阀、停泵） | 握手恢复 | 杀 RK 进程实测 |
| 超温 | 供温 > 高限 | MCU | 减/关阀、泵散热后停 | 人工确认 | 注入高温信号 |
| 缺水/低压 | 压力 < 低限且补不上 | MCU+RK | 启补水；失败停泵防空转 | 人工确认 | 模拟低压 |
| 传感器故障 | 断线/越限/跳变/矛盾 | RK | 禁自动调节、降级/转手动、告警 | 数据恢复 | 拔传感器/注入异常 |

### 6.3 分阶段验收表

| 阶段 | 准入条件 | 关键验收项 | 出口标准 |
|---|---|---|---|
| P0a 台架 | 开发板+DAQ 到位 | 仿真收敛、传感器故障识别、模拟 MCU 兜底、24h 运行 | 软件骨架稳定 + 三张表初稿 |
| P0b 现场顾问 | IO 表填实 + 安全联锁表定稿 + 硬件/安全到位 | 真实采集校验、建议方向对、补水自动、硬接线急停实测 | 一个供暖季基线数据 + 安全现场验收 |
| P1 有限自动 | P0b 数据可靠 + 安全验收 + 运维认可 | 自动 72h+ 收敛、分层安全生效、断网继续、日志可追溯 | 试点站自动运行稳定 |
| P2 供暖季验证 | P1 稳定运行 | 整季无事故、节能/品质量化改善、整定成本可控 | 规模化 Go/No-Go |
