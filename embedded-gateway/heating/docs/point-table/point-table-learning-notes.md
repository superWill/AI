# 点表学习笔记：从现场设备到 App 添加设备

> 目标：把“点表从哪来、谁来建、量程怎么配、和 App 添加设备是什么关系”讲清楚。  
> 适用场景：RK3506 供热网关、RS485/Modbus 采集、DAQ/IO 模块、HMI 展示和 MQTT 上报。

## 1. 先记一句话

MCU 或 RK3506 不知道现场意义，点表把现场意义告诉程序。

没有点表时，程序只知道：

```text
2 号设备，0 号寄存器，值是 12000
```

有了点表后，程序才知道：

```text
这是供水压力，现在是 0.80 MPa，质量码 GOOD，可以显示、上传，也可以参与控制判断。
```

## 2. 点表从哪来

点表不是 MCU 自己猜出来的，也不是嵌入式工程师凭空编的。它通常来自几类资料：

| 来源 | 提供什么 |
|---|---|
| 设备厂家说明书 | Modbus 地址、功能码、寄存器地址、数据类型、倍率、字节序 |
| 传感器铭牌 / 型号资料 | 输出类型、量程、单位，例如 `4-20mA`、`0-1.6MPa` |
| 自控图纸 / 电气接线图 | 传感器接到哪个模块、哪个通道、哪个端子 |
| 工艺 / 暖通 / 消防要求 | 点位名称、现场含义、报警上下限、联锁规则 |
| 现场调试记录 | 实际从站地址、波特率、接线修正、方向修正 |

嵌入式工程师的工作是把这些资料整理成程序能读的配置。

## 3. 点表是谁建的

小项目里，嵌入式工程师可能全包：看说明书、接线、设地址、建点表、写程序、现场调试。

正规工业项目里，通常是多人共同确定：

| 角色 | 负责什么 |
|---|---|
| 设备厂家 | 给协议、寄存器表、倍率、数据格式 |
| 自控 / 电气工程师 | 确定现场有哪些点，接在哪些模块和端子上 |
| 工艺 / 暖通 / 消防工程师 | 确定点位含义、报警值、联锁逻辑 |
| 嵌入式工程师 | 把工程资料变成网关配置和采集程序 |
| 调试工程师 | 现场核对地址、量程、单位、方向、报警是否正确 |

所以点表可以由嵌入式工程师建，但依据必须来自设备、图纸、现场和工艺要求，不能靠猜。

## 4. 设备表、点表、状态表的区别

这三个表很容易混，先按人话区分：

```text
设备表：我现场有哪些设备
点表：每个设备下面有哪些数据点，每个点怎么读、怎么算
状态表：现在每个点的最新值是多少，数据靠不靠谱
```

### 4.1 设备表管“谁”

设备表描述一个设备怎么接入系统。

示例：

| 字段 | 示例 |
|---|---|
| 设备名称 | 1 号 AI 采集模块 |
| 接口 | RS485-1 |
| 协议 | Modbus RTU |
| 从站地址 | 2 |
| 波特率 | 9600 |
| 采集周期 | 1s |

### 4.2 点表管“读什么、怎么算”

点表描述设备下面的具体点位。

示例：

| 点位 | 设备 | 寄存器 / 通道 | 原始信号 | 工程量 |
|---|---|---|---|---|
| 供水压力 | AI 模块 2 | AI1 / 寄存器 0 | `4-20mA` | `0-1.6MPa` |
| 回水压力 | AI 模块 2 | AI2 / 寄存器 1 | `4-20mA` | `0-1.6MPa` |
| 循环泵运行反馈 | DI 模块 3 | DI1 | 开关量 | 运行 / 停止 |
| 补水阀打开指令 | DO 模块 4 | DO1 | 开关量 | 打开 / 关闭 |

### 4.3 状态表管“现在是多少、靠不靠谱”

状态表是程序运行时不断更新的数据。

示例：

| 点位 | 当前值 | 单位 | 质量码 | 更新时间 |
|---|---:|---|---|---|
| 供水压力 | 0.80 | MPa | GOOD | 10:01:03 |
| 回水压力 | 0.62 | MPa | GOOD | 10:01:03 |
| 阀门反馈 | -- | % | OFFLINE | 10:01:05 |

## 5. App 里的“添加设备”和点表是什么关系

App 里的“添加设备”，通常是在建立设备表，也就是把一个物理设备挂进系统：

```text
添加设备：DAQ4212 或 RS485 AI 模块
接口：RS485-1
协议：Modbus RTU
地址：2
波特率：9600
```

这一步只是告诉系统：

```text
我有一个设备，它在哪里，它怎么通信。
```

完整点表还要继续配置这个设备下面的点位：

```text
AI1：供水压力，4-20mA，0-1.6MPa
AI2：回水压力，4-20mA，0-1.6MPa
DI1：循环泵运行反馈
DI2：循环泵故障反馈
DO1：补水阀打开指令
```

所以关系是：

```text
添加设备
  ↓
选择设备模板
  ↓
生成默认通道 / 寄存器
  ↓
配置点位名称、量程、单位、报警值
  ↓
形成完整点表
```

比较好的 App 设计是：用户选择设备型号后，系统自动带出默认点位模板，用户只改现场相关字段。

## 6. 一个完整例子：供水压力

现场任务：

```text
RK3506 要采集供水压力，并显示在 LCD 上。
```

### 6.1 先确认现场点位

点名：

```text
供水压力
```

现场含义：

```text
供热管道供水侧压力
```

单位：

```text
MPa
```

### 6.2 看传感器

压力变送器铭牌可能写：

```text
供电：24VDC
输出：4-20mA
量程：0-1.6MPa
```

这里的 `0-1.6MPa` 来自传感器铭牌或型号资料，不是 MCU 自动知道的。

### 6.3 看接线和采集模块

现场通常不是传感器直接接 RK3506，而是：

```text
压力传感器
  ↓ 4-20mA
AI 采集模块
  ↓ RS485 / Modbus RTU
RK3506
```

需要确认：

```text
AI 模块地址：2
通道：AI1
寄存器：0000
```

### 6.4 看 AI 模块说明书

AI 模块说明书可能写：

```text
通道 1 当前值：寄存器 0000
功能码：03
数据类型：uint16
单位：0.001mA
```

如果 RK3506 读到：

```text
12000
```

先换成电流：

```text
12000 * 0.001 = 12mA
```

再换成压力：

```text
压力 = (12 - 4) / 16 * 1.6 = 0.8MPa
```

### 6.5 写成点表

| 字段 | 示例 |
|---|---|
| 点位 ID | `supply_pressure` |
| 点位名称 | 供水压力 |
| 设备类型 | AI 采集模块 |
| 接口 | RS485-1 |
| Modbus 地址 | 2 |
| 功能码 | 03 |
| 寄存器地址 | 0000 |
| 数据类型 | uint16 |
| 原始单位 | `0.001mA` |
| 输入信号 | `4-20mA` |
| 工程量程 | `0-1.6` |
| 工程单位 | MPa |
| 换算公式 | `(raw * 0.001 - 4) / 16 * 1.6` |
| 报警低限 | 0.20MPa |
| 报警高限 | 1.20MPa |
| 质量码规则 | 超时、CRC 错、离线、超量程 |
| 展示位置 | LCD 首页 |
| 上传字段 | `supply_pressure` |

## 7. 量程是谁配的

量程分几种情况。

### 7.1 智能设备已经换算好了

例如 Modbus 温度模块直接返回：

```text
452
```

说明书写：

```text
实际温度 = raw / 10 = 45.2℃
```

这时 RK3506 只需要按说明书换算。

### 7.2 普通 4-20mA 传感器需要配置量程

例如压力传感器：

```text
4mA = 0MPa
20mA = 1.6MPa
```

这个量程来自传感器铭牌，通常需要在 App 或配置文件里填。

### 7.3 阀门、电机控制量也需要配置比例

例如阀门 AO 控制：

```text
4mA = 0% 开度
20mA = 100% 开度
```

RK3506 只知道你配置了这个比例，它不会天然知道阀门的实际行程和现场安装位置。

## 8. DI / DO / AI / AO 在点表里怎么理解

| 类型 | 人话解释 | 常见例子 |
|---|---|---|
| DI | 数字输入，读开关状态 | 泵运行反馈、泵故障、阀门开到位、急停 |
| DO | 数字输出，控制开关动作 | 启动水泵、打开阀门、声光报警 |
| AI | 模拟输入，读取连续变化的量 | 温度、压力、液位、阀位反馈 |
| AO | 模拟输出，输出连续控制量 | 阀门开度指令、变频器频率给定 |

注意：AI/AO 往往不是直接等于温度或压力，中间还有电压、电流和工程量的换算。

## 9. DI / DO / AI / AO 的工程深入

入门时只要记住 `DI` 是读开关、`DO` 是控开关、`AI` 是读连续量、`AO` 是输出连续量。

工程落地时不能只看这个分类，还要看电气形态、接线方式、故障判断、精度、隔离和安全态。

### 9.1 DI 深入：不是只有 0/1

DI 读到的是 `0/1`，但真正要关心的是这个 `0/1` 从哪来。

常见 DI 形态：

| DI 形态 | 人话解释 | 注意事项 |
|---|---|---|
| 干接点 | 对方只给一个开关，不带电 | DI 模块自己提供检测电压 |
| 湿接点 | 对方直接给 `24V` 或其他电压 | 要确认输入电压范围，不能直接接 MCU GPIO |
| NPN / PNP | 工业传感器常见输出方式 | 要和 DI 模块源型/漏型输入匹配 |
| 24V 隔离输入 | 工业现场常用 | 抗干扰更好，保护网关侧 |
| 高速计数输入 | 用于脉冲、水表、电表、编码器 | 要确认最高频率和滤波设置 |

最容易出错的是干接点和湿接点：

```text
干接点 = 对方只是一个开关
湿接点 = 对方给你一个有电压的信号
```

接线前必须确认：

```text
这个反馈是干接点，还是有源 24V？
```

另一个关键是常开和常闭：

```text
常开 NO：平时断开，动作时闭合
常闭 NC：平时闭合，动作或断线时断开
```

安全场景常偏向常闭，因为断线也能暴露出来。

```text
常开故障输入：线断了也像没故障，危险
常闭故障输入：线断了会变成故障，系统能发现
```

所以 DI 点表不应只写 `pump_fault = DI1`，更完整应包含：

| 字段 | 示例 |
|---|---|
| 信号类型 | 干接点 / 24V 湿接点 |
| 有效电平 | 高有效 / 低有效 |
| 触点类型 | 常开 NO / 常闭 NC |
| 滤波时间 | 20ms / 100ms / 500ms |
| 断线策略 | 是否能检测断线，断线是否按故障处理 |

### 9.2 DO 深入：输出必须考虑负载和安全态

DO 不是简单“拉高一下”。常见输出形态：

| DO 形态 | 特点 | 适合场景 |
|---|---|---|
| 继电器输出 | 隔离好，可切不同电压；慢，有寿命 | 泵启停、阀门开关、报警器 |
| 晶体管输出 | 快、寿命长；电压电流范围有限 | 高频动作、小功率直流负载 |
| MOS 输出 | 快、适合直流功率开关 | 电磁阀、小电机、LED 等 |
| 开漏 / 开集输出 | 只能主动拉低，需要外部上拉 | 信号级控制、告警输出、总线类信号 |

DO 配置要关心：

```text
输出最大电流是多少？
能不能带感性负载？
有没有续流二极管或浪涌保护？
上电默认是 ON 还是 OFF？
程序崩溃时输出保持还是断开？
通信失联时输出怎么办？
```

例如电磁阀、接触器线圈、继电器线圈都是感性负载。断电瞬间可能产生反向高压，需要续流或浪涌保护，否则 DO 模块容易损坏。

DO 点表或设备配置里应包含：

| 字段 | 示例 |
|---|---|
| 上电默认 | OFF |
| 失联安全态 | OFF / 保持 / 指定值 |
| 最大保持时间 | 补水阀最多打开 60s |
| 是否需要反馈 | 需要 DI 或 AI 反馈确认 |
| 是否允许远程写 | 是 / 否 |
| 写入前条件 | 无急停、无故障、模式允许 |

工业里最怕的是：

```text
程序死了，但 DO 还保持打开。
```

所以 DO 一定要设计安全态。

### 9.3 AI 深入：AI 的核心是精度链路

一个压力值从现场到程序，中间会经历：

```text
真实压力
  ↓
传感器误差
  ↓
4-20mA 输出误差
  ↓
线缆干扰 / 接地问题
  ↓
AI 模块采样误差
  ↓
ADC 分辨率
  ↓
软件滤波
  ↓
量程换算
  ↓
工程值
```

所以 `0.80MPa` 不是天然真理，而是经过测量链算出来的结果。

AI 需要关心：

| 概念 | 人话解释 |
|---|---|
| ADC 位数 | 12bit / 16bit / 24bit，决定理论分得多细 |
| 采样率 | 每秒采多少次 |
| 精度 | 实际准不准，例如 `±0.1%FS` |
| 分辨率 | 最小能分辨的变化 |
| 零点漂移 | 长期运行零点会不会偏 |
| 温漂 | 环境温度变化会不会影响读数 |
| 滤波 | 抑制噪声，但会增加响应延迟 |

要区分：

```text
分辨率 = 理论上能分多细
精度 = 实际上准不准
```

例如 16bit ADC 测 `0-10V`：

```text
10V / 65535 ≈ 0.000153V
```

看起来很细，但实际精度还受传感器、参考电压、模拟前端、噪声和接地影响。

### 9.4 为什么 4-20mA 常用于工业现场

`4-20mA` 的优势不是“数字好看”，而是工程上好用：

```text
抗干扰强
适合长距离
线缆压降影响小
可以检测断线
```

核心是 `4mA` 这个活零点：

```text
4mA = 量程下限
20mA = 量程上限
0mA = 很可能断线、掉电或回路故障
```

常见故障判断：

```text
< 3.6mA：可能断线或传感器故障
> 21mA：可能超量程或传感器故障
```

相比之下，`0-20mA` 的问题是：

```text
0mA 既可能代表真实 0，也可能代表线断。
```

所以工业现场更常用 `4-20mA`。

### 9.5 AO 深入：AO 是控制风险点

AO 是输出连续控制量，常见于：

```text
阀门开度
变频器频率
比例阀控制
风机转速
```

AO 风险在于它会直接影响设备动作：

```text
传感器坏了，控制算法还在算
AO 模块通信断了，输出保持旧值
程序重启时 AO 瞬间归零
手自动切换时输出跳变
```

所以 AO 必须有保护：

| 保护 | 作用 |
|---|---|
| 限幅 | 不能超过允许范围，例如 `0-100%` |
| 斜率限制 | 不能从 `10%` 瞬间跳到 `100%` |
| 手自动无扰切换 | 模式切换时输出不要突变 |
| 失联安全态 | 通信断开后输出到安全值或保持策略 |
| 回读确认 | 读取 AO 实际输出或设备反馈 |

例如阀门控制：

```text
算法算出目标 85%
软件限制最大开度 70%
最终实际输出 70%
```

这叫限幅。

再比如：

```text
当前 20%
目标 80%
每秒最多增加 5%
```

这叫斜率限制，用来减少冲击和系统震荡。

### 9.6 工程级点表要记录的属性

初级点表只写：

```text
点名、地址、寄存器、单位、倍率
```

工程级点表还应考虑：

```text
信号类型
量程
有效电平
滤波时间
报警限
故障限
质量码规则
安全态
是否参与控制
是否需要反馈确认
是否允许远程写
```

例如一个阀门 AO 点：

| 字段 | 示例 |
|---|---|
| 点位 ID | `valve_cmd` |
| 类型 | AO |
| 输出信号 | `4-20mA` |
| 工程量 | `0-100%` |
| 安全态 | `0%` |
| 最大变化率 | `5%/s` |
| 允许模式 | 自动 / 手动 |
| 写入前条件 | 压力质量码 GOOD，系统无急停 |
| 反馈点 | `valve_feedback` |
| 反馈偏差报警 | `>10%` 持续 30s |

### 9.7 每个点都要想故障模型

现场不是只会正常工作。每个点都要问：

```text
断线怎么办？
短路怎么办？
值卡住不变怎么办？
值跳变怎么办？
通信超时怎么办？
单位配错怎么办？
量程配错怎么办？
命令发出但没反馈怎么办？
反馈反了怎么办？
```

例如 AI 压力：

```text
0mA -> 断线
3.2mA -> 低于有效范围，故障
22mA -> 超量程或传感器故障
10 分钟完全不变 -> 可能卡死，要结合现场判断
突然从 0.4MPa 跳到 1.5MPa -> 可能是真异常，也可能是干扰
```

从“会采集”到“能工程落地”，差别就在这里。

## 10. 工程级 AI 点表示例：供水压力

初级点表可能只写：

```text
供水压力，AI1，4-20mA，0-1.6MPa
```

工程级点表要继续回答：

```text
这个压力值可信吗？
断线了吗？
跳变了吗？
要不要报警？
能不能参与控制？
如果这个点坏了，泵和阀门怎么办？
```

一个供水压力点可以按这条链路设计：

```text
现场传感器
  ↓
AI 模块采样
  ↓
原始值合法性判断
  ↓
工程量换算
  ↓
滤波
  ↓
质量码
  ↓
报警判断
  ↓
控制联锁
  ↓
LCD / MQTT 展示
```

### 10.1 基础身份信息

| 字段 | 示例 |
|---|---|
| 点位 ID | `supply_pressure` |
| 点位名称 | 供水压力 |
| 系统区域 | 二次侧 / 供水管 |
| 点位类型 | AI |
| 是否参与控制 | 是 |
| 展示位置 | LCD 首页、压力详情页 |
| 上传字段 | `supply_pressure` |

点位 ID 给程序用，点位名称给人看。中文名可以改，`point_id` 尽量稳定。

### 10.2 采集来源

| 字段 | 示例 |
|---|---|
| 采集设备 | RS485 AI 模块 |
| 接口 | RS485-1 |
| 协议 | Modbus RTU |
| 从站地址 | `2` |
| 功能码 | `03` |
| 寄存器地址 | `0000` |
| 数据类型 | `uint16` |
| 原始单位 | `0.001mA` |
| 采集周期 | `1s` |
| 超时时间 | `200ms` |
| 重试次数 | `1` |

例如读到：

```text
12000
```

表示：

```text
12.000mA
```

### 10.3 传感器和量程

| 字段 | 示例 |
|---|---|
| 传感器类型 | 压力变送器 |
| 供电 | 24VDC |
| 输出信号 | `4-20mA` |
| 工程量程 | `0-1.6MPa` |
| 单位 | `MPa` |
| 精度 | 以铭牌 / 手册为准 |
| 安装位置 | 供水管 |

换算公式：

```text
mA = raw * 0.001
pressure = (mA - 4) / 16 * 1.6
```

如果 `raw = 12000`：

```text
mA = 12
pressure = (12 - 4) / 16 * 1.6 = 0.8MPa
```

### 10.4 故障边界

对于 `4-20mA`，要先判断电流本身是否可信。

| 条件 | 判断 |
|---|---|
| `< 3.6mA` | 断线 / 传感器故障 |
| `3.6-4.0mA` | 低于量程，标记可疑或低限 |
| `4.0-20.0mA` | 正常换算 |
| `20.0-21.0mA` | 高于量程，可能超量程 |
| `> 21.0mA` | 传感器故障 / 超量程故障 |

质量码可以这样设计：

| 质量码 | 含义 |
|---|---|
| `GOOD` | 通信正常，电流在有效范围，工程值合理 |
| `LOW_FAULT` | 电流低于断线阈值 |
| `HIGH_FAULT` | 电流高于故障阈值 |
| `TIMEOUT` | 设备没回 |
| `CRC_ERROR` | 帧校验失败 |
| `OFFLINE` | 连续多次失败 |
| `INVALID` | 换算后不合理 |

### 10.5 滤波和延时

压力信号会抖，不能每个瞬间值都直接拿去控制。

| 字段 | 示例 |
|---|---|
| 滤波方式 | 滑动平均 |
| 滤波窗口 | 5 次 |
| 最大跳变限制 | 每秒不超过 0.3MPa，超过标记突变 |
| 报警延时 | 5s |
| 恢复延时 | 10s |

恢复延时用于避免压力在报警线附近来回跳：

```text
0.19MPa 报警
0.21MPa 恢复
0.19MPa 又报警
0.21MPa 又恢复
```

### 10.6 报警限和控制限要分开

不要把量程、故障限、报警限、控制限混成一个“范围”。

| 类型 | 示例 | 含义 |
|---|---|---|
| 量程 | `0-1.6MPa` | 传感器能测的范围 |
| 故障限 | `<3.6mA` / `>21mA` | 信号本身可能坏了 |
| 报警限 | `<0.20MPa` / `>1.20MPa` | 需要提示人 |
| 控制限 | `<0.25MPa` 启动补水，`>0.35MPa` 停止补水 | 自动控制用 |

报警是给人看的，控制限是程序动作的条件，它们可以不同。

### 10.7 控制联锁

参与控制的测点，质量码必须进入联锁条件。

例如补水控制：

```text
如果供水压力 GOOD
并且压力 < 0.25MPa
并且系统在自动模式
并且没有急停
并且补水泵无故障
并且水箱不缺水
则允许启动补水泵
```

如果压力质量码不是 `GOOD`：

```text
禁止自动补水
保持或关闭相关输出
报警：供水压力信号异常
```

不能只看数值，还必须看这个数值是否可信。

## 11. 采集程序怎么用点表

程序内部推荐按这个流程：

```text
读取设备表和点表
  ↓
按设备地址和采集周期轮询
  ↓
发送 Modbus RTU 请求
  ↓
收到响应后校验 CRC
  ↓
按点表解析寄存器
  ↓
按量程换算成工程值
  ↓
判断质量码
  ↓
更新状态表
  ↓
LCD 显示 / MQTT 上传 / 报警 / 控制逻辑
```

关键原则：

- 某个设备超时，不能拖死整个网关。
- CRC 错误的数据不能使用。
- 超出合理量程的数据要标记 `INVALID`。
- 连续失败要标记 `OFFLINE`。
- 控制输出前必须检查质量码、限幅、联锁和反馈。

## 12. 记忆总结

```text
设备表 = 现场有哪些设备
点表 = 每个设备有哪些点，每个点怎么读、怎么算
状态表 = 当前每个点是多少，数据靠不靠谱
```

```text
添加设备不是完整点表，但它是建立点表的入口。
```

```text
MCU 负责执行，点表负责解释现场。
```
