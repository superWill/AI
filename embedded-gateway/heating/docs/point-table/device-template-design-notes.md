# 设备模板设计笔记：硬件模板、业务模板与关注指标

> 目标：把 App 添加设备时需要的“设备模板”梳理清楚，尤其是每类设备要自动生成哪些点、必须配置哪些硬性指标、现场调试要关注什么。  
> 适用场景：RK3506 供热网关、热源站、换热站、DAQ/IO 模块、RS485 Modbus 设备、HMI 设备卡片和控制策略配置。

## 1. 为什么需要设备模板

如果每次添加设备都让用户从零配置通道、寄存器、量程、单位、报警和控制策略，配置成本高，而且很容易错。

设备模板的作用是：

```text
选择一种设备类型
  ↓
自动生成默认通道 / 默认点位 / 默认控制骨架
  ↓
用户只补现场相关信息
  ↓
减少重复配置和低级错误
```

模板不是为了炫技，而是为了让 App 能主动帮用户检查：

- 必填字段有没有漏。
- 点位类型有没有绑错。
- 量程和单位是否合理。
- 命令点有没有反馈点。
- 高风险输出有没有安全态。
- 控制策略有没有联锁和人工复位。

## 2. 两类模板必须分清

设备模板建议分成两类：

```text
硬件模板：描述模块能力
业务设备模板：描述现场对象
```

### 2.1 硬件模板

硬件模板关心“这个硬件能接什么信号、通道在哪里、怎么通信”。

典型硬件模板：

- RS485 8AI 模块。
- RS485 8DI 模块。
- RS485 8DO 模块。
- RS485 AO 模块。
- DAQ4212。
- 电表。
- 热量表。
- 变频器。

硬件模板关注：

| 关注项 | 说明 |
|---|---|
| 通信接口 | RS485、USB、Ethernet、CAN、M-Bus |
| 协议 | Modbus RTU、Modbus TCP、厂家 SDK、私有协议 |
| 通道能力 | AI/DI/DO/AO 数量 |
| 寄存器或通道地址 | 每一路对应哪个寄存器、线圈或 SDK 通道 |
| 支持量程 | `4-20mA`、`0-10V`、`±10V`、24V DI 等 |
| 数据类型 | `uint16`、`int16`、`uint32`、`float32` |
| 精度 / 分辨率 | ADC 位数、采样精度、输出精度 |
| 隔离能力 | 通信隔离、通道隔离、电源隔离 |
| 默认通信参数 | 波特率、校验位、停止位、超时、重试 |

### 2.2 业务设备模板

业务设备模板关心“现场这个对象需要哪些点、怎么显示、怎么控制、怎么判断故障”。

典型业务设备模板：

- 供水压力测点。
- 补水泵。
- 循环泵。
- 一次侧调节阀。
- 变频器驱动泵。
- 热量表。
- 电表。
- 消防泵。
- 排烟风机。

业务模板关注：

| 关注项 | 说明 |
|---|---|
| 必需点 | 这个业务对象必须绑定哪些点 |
| 可选点 | 有则增强诊断，没有也可运行 |
| 点位角色 | 命令、反馈、故障、测量、设定值 |
| 控制策略 | 启停阈值、回差、最大运行时间、反馈超时 |
| 联锁条件 | 急停、手自动、质量码、缺水、故障 |
| 安全态 | 急停、失联、故障、重启后的输出状态 |
| HMI 卡片 | 页面上展示哪些字段和状态 |
| 事件记录 | 启动、停止、故障、复位、参数修改 |

一句话：

```text
硬件模板解决“线接到哪里”
业务模板解决“这个东西在现场是什么意思”
```

## 3. 模板绑定关系

业务设备通常不会直接对应一个硬件模块。

例如一台补水泵，信号可能分散在多个 IO 模块：

| 业务角色 | 类型 | 绑定到 |
|---|---|---|
| 启动命令 | DO | 4 号 DO 模块 DO1 |
| 运行反馈 | DI | 3 号 DI 模块 DI1 |
| 故障反馈 | DI | 3 号 DI 模块 DI2 |
| 补水压力 | AI | 2 号 AI 模块 AI1 |
| 缺水开关 | DI | 3 号 DI 模块 DI3 |

所以 App 里应该同时有：

```text
硬件设备
业务设备
点位绑定
控制策略
```

推荐流程：

```text
先添加硬件设备
  ↓
生成硬件通道
  ↓
把通道配置成点位
  ↓
添加业务设备
  ↓
把业务角色绑定到点位
  ↓
生成 HMI 卡片和控制策略
```

## 4. 硬件模板示例：RS485 8AI 模块

### 4.1 适合接什么

RS485 8AI 模块适合把现场模拟量接入网关。

典型接入：

- 供水压力。
- 回水压力。
- 水箱液位。
- 阀门开度反馈。
- 变频器频率反馈。
- 温度变送器。

### 4.2 必须配置的硬性指标

| 指标 | 示例 | 为什么重要 |
|---|---|---|
| 接口 | RS485-1 | 决定走哪条总线 |
| 协议 | Modbus RTU | 决定帧格式和读写方式 |
| 从站地址 | `2` | 总线上唯一识别设备 |
| 波特率/校验位 | `9600 8N1` | 两边不一致会乱码或无响应 |
| AI 通道数 | 8 路 | 决定自动生成多少通道 |
| 输入信号 | `4-20mA` / `0-10V` | 决定换算公式和故障判断 |
| 寄存器地址 | AI1=`0`、AI2=`1` | 决定从哪里读值 |
| 数据类型 | `uint16` | 决定如何解析字节 |
| 原始单位 | `0.001mA` 或 `0.001V` | 决定 raw 如何变成电流/电压 |
| 采集周期 | `1s` | 决定刷新速度 |
| 超时/重试 | `200ms` / `1` | 决定离线判断和总线效率 |
| 是否隔离 | 是/否 | 影响抗干扰和安全 |

### 4.3 App 自动生成内容

选择 `RS485 8AI 模块` 后，App 应自动生成：

```text
AI1 未配置
AI2 未配置
AI3 未配置
AI4 未配置
AI5 未配置
AI6 未配置
AI7 未配置
AI8 未配置
```

每路通道默认带出：

| 字段 | 默认值 |
|---|---|
| 类型 | AI |
| 数据类型 | `uint16` |
| 功能码 | `03` |
| 质量码 | GOOD / TIMEOUT / OFFLINE / INVALID |
| 默认状态 | 未配置 |

### 4.4 现场关注点

- 确认是电流输入还是电压输入。
- 确认模块是否需要跳线切换量程。
- 确认 `4-20mA` 传感器是否有 24V 供电。
- 确认屏蔽层和接地方式。
- 确认 AI 模块读到的是电流、电压，还是已经换算后的工程值。
- 长线优先选隔离型模块。

## 5. 硬件模板示例：RS485 DI/DO 模块

### 5.1 RS485 DI 模块

DI 模块适合读取开关量状态。

典型接入：

- 泵运行反馈。
- 泵故障反馈。
- 阀门开到位/关到位。
- 水箱低水位。
- 急停。
- 手自动状态。

必填指标：

| 指标 | 示例 | 为什么重要 |
|---|---|---|
| DI 通道数 | 8 / 16 / 32 路 | 决定通道模板 |
| 输入类型 | 干接点 / 24V 湿接点 | 接错可能读不到或烧模块 |
| 有效电平 | 高有效 / 低有效 | 决定 1 是动作还是恢复 |
| 触点类型 | NO / NC | 决定断线是否能被发现 |
| 滤波/去抖 | `20ms` / `100ms` | 防止抖动误判 |
| 隔离 | 通道隔离 / 组隔离 | 影响抗干扰 |

现场关注点：

- 故障、急停、保护类信号优先考虑常闭。
- 运行反馈要区分来自接触器辅助触点，还是变频器状态。
- 如果反馈逻辑反了，HMI 会显示完全相反的状态。

### 5.2 RS485 DO 模块

DO 模块适合输出开关命令。

典型控制：

- 启动补水泵。
- 启动循环泵。
- 打开电磁阀。
- 控制声光报警。
- 给控制柜一个启动触点。

必填指标：

| 指标 | 示例 | 为什么重要 |
|---|---|---|
| DO 类型 | 继电器 / 晶体管 / MOS | 决定能带什么负载 |
| 最大电压电流 | 例如 `250VAC 5A` 或 `24VDC 0.5A` | 超过会烧输出 |
| 输出逻辑 | 闭合有效 / 高电平有效 | 决定 ON 的真实含义 |
| 上电默认 | OFF | 防止上电误动作 |
| 失联安全态 | OFF / 保持 / 指定状态 | 通信断开时必须明确 |
| 感性负载保护 | 续流 / 浪涌吸收 | 电磁阀、接触器线圈需要 |
| 最大保持时间 | 例如补水阀 60s | 防止无限动作 |

现场关注点：

- DO 发出命令不代表设备真的动作。
- 必须绑定 DI/AI 反馈确认。
- 高风险输出要有人机确认和权限控制。
- 程序重启、通信中断、看门狗动作时输出要回安全态。

## 6. 硬件模板示例：DAQ4212

### 6.1 适合场景

DAQ4212 更像实验台/柜内采集模块，适合快速接入多路电压型模拟量和部分数字 IO。

典型用途：

- 原型阶段快速采集传感器电压。
- 采集 `0-10V`、`±10V`、`0.5-4.5V` 类型信号。
- 做阀位反馈、温度/压力变送器电压输出实验。
- 做本地 HMI 数据演示。

### 6.2 必须确认的硬性指标

| 指标 | 当前项目关注 | 为什么重要 |
|---|---|---|
| 接口 | USB / Ethernet / SDK | 决定 RK3506 如何访问 |
| Linux ARM SDK | 必须实测 | x86 能跑不代表 RK3506 能跑 |
| AI 通道 | 多路单端模拟输入 | 决定可接多少传感器 |
| AI 量程 | 常见 `±5V` / `±10V` | 不能直接读 `4-20mA`，除非加采样电阻 |
| AI 分辨率 | 例如 16 bit | 影响理论分辨能力 |
| AO | 模拟量输出 | 可做原型控制，但高风险控制要谨慎 |
| DIO 电平 | 3.3V CMOS / TTL 级别 | 不能直接接 24V 工业 DI/DO |
| 供电 | USB 或外部 12V/24V | 影响现场稳定性 |
| 隔离 | 需确认 | 影响抗干扰和安全 |

### 6.3 关键提醒

DAQ4212 的 AI 读的是电压，不是电流。

如果要读 `4-20mA` 传感器，需要在电流回路里加采样电阻，例如把电流转换成电压：

```text
4mA * 250Ω = 1V
20mA * 250Ω = 5V
```

然后 DAQ 读到的是 `1-5V`，软件再换算成工程量。

### 6.4 App 模板关注点

选择 `DAQ4212` 后，App 应提示：

- AI 通道默认是电压型。
- DIO 不是 24V 工业 IO。
- `4-20mA` 传感器需要采样电阻或前端转换模块。
- SDK 和目标 RK3506 架构兼容性需要检测。
- 更适合原型验证，不一定适合强干扰现场直连。

## 7. 业务模板示例：供水压力测点

### 7.1 必需点

供水压力测点通常只需要一个 AI 或 Modbus 测量点：

| 角色 | 类型 | 示例 |
|---|---|---|
| pressure_value | AI / Bus | 供水压力 |

### 7.2 必填指标

| 指标 | 示例 | 为什么重要 |
|---|---|---|
| 现场名称 | 供水压力 | HMI 和告警给人看 |
| 点位 ID | `supply_pressure` | 程序和 MQTT 稳定引用 |
| 来源点 | AI1 / Modbus 寄存器 | 决定数据从哪来 |
| 信号类型 | `4-20mA` | 决定故障判断 |
| 工程量程 | `0-1.6MPa` | 决定换算公式 |
| 单位 | MPa | 决定展示和上报 |
| 报警低限/高限 | `0.20` / `1.20` | 给人看和告警 |
| 控制启动/停止限 | `0.25` / `0.35` | 给控制逻辑用 |
| 质量码规则 | GOOD / TIMEOUT / LOW_FAULT | 决定是否可信 |
| 是否参与控制 | 是/否 | 参与控制则必须检查质量码 |

### 7.3 关注点

- 量程、报警限、控制限不要混在一起。
- 压力质量码非 `GOOD` 时，不能继续自动补水。
- 压力跳变要判断是现场真实变化还是采集干扰。
- HMI 要显示值、单位、质量码和更新时间。

## 8. 业务模板示例：补水泵

### 8.1 必需点和可选点

| 角色 | 类型 | 必需 | 说明 |
|---|---|---|---|
| run_cmd | DO / Bus | 是 | 补水泵启动命令 |
| run_feedback | DI / Bus | 是 | 补水泵运行反馈 |
| fault_feedback | DI / Bus | 是 | 补水泵故障反馈 |
| pressure | AI / Bus | 是 | 补水控制依据，通常是供水压力 |
| low_water | DI | 建议 | 水箱缺水保护 |
| auto_manual | DI / Param | 建议 | 本地手自动状态 |
| frequency_feedback | AI / Bus | 可选 | 变频泵频率反馈 |

### 8.2 必填控制指标

| 指标 | 示例 | 为什么重要 |
|---|---|---|
| 启动压力 | `<0.25MPa` | 低压时自动补水 |
| 停止压力 | `>0.35MPa` | 形成回差，防频繁启停 |
| 压力低延时 | `5s` | 防止瞬时抖动误启动 |
| 最大连续运行 | `120s` | 防止漏水或传感器故障导致无限补水 |
| 启动反馈超时 | `5s` | 命令发出后确认泵真的启动 |
| 停止反馈超时 | `5s` | 停止后确认泵真的停下 |
| 故障后复位 | 人工复位 | 防止故障自动反复启动 |
| 上电默认 | OFF | 防止上电误启动 |
| 失联安全态 | OFF | 通信断开进入安全状态 |

### 8.3 联锁条件

补水泵启动前至少检查：

- 系统处于自动模式。
- 供水压力质量码是 `GOOD`。
- 供水压力低于启动阈值。
- 急停未触发。
- 水箱不缺水。
- 补水泵无故障。
- 本地手动没有接管。

### 8.4 反馈诊断

| 情况 | 诊断 |
|---|---|
| 命令 ON，反馈 OFF | 启动失败 |
| 命令 OFF，反馈 ON | 非指令运行 |
| 反馈点故障或超时 | 不允许自动判断成功 |
| 故障反馈 ON | 停止输出并报警 |
| 补水超时压力未恢复 | 停泵、报警、人工复位 |

### 8.5 HMI 卡片

补水泵卡片建议显示：

- 当前状态：停止 / 运行 / 故障 / 手动 / 禁止自动。
- 启动命令。
- 运行反馈。
- 故障反馈。
- 已连续运行时间。
- 最近一次启动原因。
- 未启动原因或联锁不通过原因。

## 9. 业务模板示例：循环泵

循环泵和补水泵类似，但通常更关注运行可靠性、变频控制和压差。

### 9.1 常见点位

| 角色 | 类型 | 说明 |
|---|---|---|
| run_cmd | DO / Bus | 启动命令 |
| run_feedback | DI / Bus | 运行反馈 |
| fault_feedback | DI / Bus | 故障反馈 |
| freq_cmd | AO / Bus | 频率给定 |
| freq_feedback | AI / Bus | 实际频率 |
| delta_pressure | AI / Bus | 压差反馈 |
| auto_manual | DI / Param | 手自动状态 |

### 9.2 硬性指标

| 指标 | 示例 | 关注点 |
|---|---|---|
| 最小/最大频率 | `20-50Hz` | 防止低频空转或超限 |
| 频率变化率 | `2Hz/s` | 防止水锤和系统冲击 |
| 启动反馈超时 | `5s` | 判断启动是否成功 |
| 指令反馈偏差 | `>5Hz` 持续 10s | 判断变频器或反馈异常 |
| 压差目标 | 例如 `80kPa` | 作为控制目标 |
| 故障停机策略 | 故障立即停机 | 安全优先 |

### 9.3 关注点

- 变频器优先用 Modbus，可获得更多状态和故障码。
- AO 控制变频器时要确认 `0-10V` 对应多少 Hz。
- 循环泵通常影响主系统运行，故障策略要比补水泵更谨慎。

## 10. 业务模板示例：一次侧调节阀

### 10.1 常见点位

| 角色 | 类型 | 说明 |
|---|---|---|
| valve_cmd | AO / Bus | 阀门开度命令 |
| valve_feedback | AI / Bus | 阀门实际开度 |
| open_limit | DI | 开到位 |
| close_limit | DI | 关到位 |
| fault_feedback | DI / Bus | 阀门故障 |

### 10.2 硬性指标

| 指标 | 示例 | 关注点 |
|---|---|---|
| 输出信号 | `4-20mA` / `0-10V` | 决定 AO 换算 |
| 开度范围 | `0-100%` | HMI 展示和控制限幅 |
| 最大开度 | 例如 `70%` | 工艺限幅 |
| 变化率 | `5%/s` | 防止系统冲击 |
| 失联安全态 | 关闭 / 保持 / 指定开度 | 和工艺安全有关 |
| 反馈偏差报警 | `>10%` 持续 30s | 判断卡滞或执行失败 |

### 10.3 关注点

- 阀门命令和反馈必须分开看。
- 阀门反馈长期跟不上命令，要判断卡滞、接线、执行器故障。
- 调节阀参与 PID 时必须有限幅和斜率限制。
- 失电开、失电关、失电保持要按现场工艺确认。

## 11. 模板校验规则

App 保存模板或实例前，建议做这些校验：

| 校验 | 示例 |
|---|---|
| 类型匹配 | `run_cmd` 必须绑定 DO 或可写 Bus 点 |
| 必需点完整 | 补水泵缺少运行反馈则不能启用自动控制 |
| ID 唯一 | `supply_pressure` 不能重复 |
| 地址唯一 | 同一 RS485 总线不能有两个相同从站地址 |
| 量程合理 | `range_min` 必须小于 `range_max` |
| 报警限合理 | 低报警应小于高报警 |
| 控制回差合理 | 启动阈值应低于停止阈值 |
| 安全态存在 | 高风险 DO/AO 必须配置失联安全态 |
| 质量码参与控制 | 控制输入点必须要求 `GOOD` |
| 反馈超时存在 | 命令类输出必须有反馈超时或说明为何不需要 |

## 13. 记忆总结

```text
硬件模板 = 设备有什么通道，怎么通信
业务模板 = 现场对象需要哪些点，怎么显示和控制
绑定关系 = 把业务角色绑定到具体点位
校验规则 = 防止配置错导致现场误动作
```

设备模板最终解决的问题不是“把表单做漂亮”，而是让系统知道：

```text
这个设备必须有哪些信号
这些信号来自哪里
哪些参数必须配置
哪些错误必须提前拦住
哪些状态必须给现场人员看清楚
```
