# 面向优化平台的数据缺口与网关补位策略

> 用途：明确上游"优化平台"（智慧供热源-网-荷-储数字孪生 / 负荷预测 / 水力计算 / 调度优化类云端系统）在数据上的命门，以及本热源控制网关如何作为**现场标准化数据采集源 + 策略落地执行端**精准补位。
> 版本：2026-06-02
> 关联：[控制网关 PRD](../product/thermal-control-gateway-prd.md) · [控制逻辑](thermal-energy-co-controller-logic.md) · [调研对比报告](thermal-source-edge-gateway-research-report.md) · [市场参考](market-reference.md)

## 0. 一句话结论

> 优化平台的价值 ≈ **数据质量 × 覆盖广度 × 闭环能力**；本网关恰好是这三项的**乘数**。
> 平台做不了、也不该做现场硬件——这就是网关互补且防御性强的卡位：**现场标准化数据采集源 + 策略落地执行端**。

## 1. 上下游关系

| 角色 | 职责 | 落点 |
|---|---|---|
| **优化平台**（上游） | 源-网-荷-储数字孪生、负荷预测、水力计算、调度/负荷分配、应急策略 | 热力公司调度中心 / 云端 |
| **本网关**（现场） | 标准化高频采集、本地气候补偿+PID 闭环执行、安全兜底、事件上报、断网续传 | 热源 / 换热站 / 管网节点现场 |

平台输出的是**策略**，本网关提供的是平台缺的**干净数据**并负责**把策略落地执行并回传结果**。二者互补，不竞争。

## 2. 平台的核心命门

平台的模型再强，吃的是现场数据。它的本事在算法，命门在数据来源——而数据正是边缘网关的主场。平台普遍依赖"已有 DCS/SCADA 扩展接入"，由此带来五个结构性缺口。

## 3. 五大数据缺口 → 网关补位（按价值排序）

### 缺口①：荷侧 / 末端真实需求信号（最大的洞）

- **缺什么**：源侧、一次网、大站数据可从 DCS/SCADA 获得；但"荷"——尤其是**室温**——几乎空白。没有室温，负荷预测只能靠室外温度倒推，永远在"猜需求"。室温是数字孪生里**唯一真正代表需求的变量**。
- **平台为何拿不到**：要室温就得在楼栋/户内布大量无线传感，这是**现场硬件活**，纯软件云平台干不了也不愿干。
- **网关怎么补**：站端**汇聚无线室温采集（LoRa/NB 等）**，把楼栋入口热量/流量/温度 + 抽样户室温标准化上送。**这一项把负荷预测从"猜"变成"测"**，是网关最不可替代的价值。

### 缺口②：数据质量——时间同步 + 质量码（让水力模型真能算）

- **缺什么**：水力计算需要**全网各节点压力/流量/阀位在同一时刻的快照**。现有 SCADA 多为**分钟级、各点不同步、无统一时间戳、无质量码**——拿这种数据算水力模型，等于用一堆错位的照片拼运动轨迹。
- **平台为何拿不到**：这是现场采集层的物理问题，云端无法补救。
- **网关怎么补**：**统一时间同步（NTP/PPS）+ 秒级高频采样 + 每点带质量码（good/stale/bad/估计值）+ 标准点表与单位**，把脏 SCADA 变成**模型可直接用的干净数据**。

### 缺口③：盲区——没有自动化的中小换热站

- **缺什么**：平台数据建立在"已有 DCS/SCADA"之上，但大量中小站根本无自动化，对平台是**纯黑洞**，覆盖不全则数字孪生不完整。
- **网关怎么补**：低成本边缘网关让原本看不见的站点**变可见**，直接扩大平台数据覆盖面。

### 缺口④：开环——策略下发后无执行回传

- **缺什么**：平台输出的是调度/控制**建议**，落地靠现场拧阀，**收不到"设定值有没有被执行、实际到没到"的反馈**，全链路开环。
- **网关怎么补**：**接收平台下发设定值**（目标二次供温 / 目标阀位）→ 本地气候补偿+PID 执行 → **回传实际阀位/泵频/是否达标**，把"建议"闭成"可验证的执行环"。

### 缺口⑤：事件与断网续传

- **缺什么**：DCS 轮询会漏掉快变（泵跳闸、压力骤升）；网络一断，时间序列出洞，污染预测/训练。
- **网关怎么补**：**边缘事件检测**（事件驱动、带时间戳的报警，而非轮询快照）+ **断网本地缓存与补传**，保证平台拿到的时间序列无缺口。

## 4. 各层应上送的测点（网关采集范围）

> 标注：✅ 平台已能从 DCS/SCADA 获取；🔶 平台普遍缺失、由网关补位。

| 层 | 设备 | 测点 | 平台用途 | 状态 |
|---|---|---|---|---|
| 源 | 锅炉/热电厂/换热首站 | 供回水温/压、流量、总供热量、燃料/电耗、出力 | 负荷分配、源侧调度 | ✅ |
| 网·一次网 | 干线/分段/中继泵站 | 各节点温/压/流量、循环泵频率/电流、补水量/压 | 水力计算、解列、漏损监测 | 部分🔶（同步性差） |
| 网·换热站 | 板换/一二次侧 | 一次供回温/压/流量+阀位、二次供回温/压/流量、循环泵频、补水泵状态、定压、本地室外温度 | 站级负荷预测、气候补偿、二次网平衡 | ✅大站 / 🔶中小站 |
| 荷·热用户 | 楼栋/单元/户 | 楼栋入口供回温/流量/热量、抽样户室温、热量表 | 负荷预测、按需供热、过/欠供识别 | 🔶（最关键缺口） |
| 储 | 蓄热罐（若有） | 罐温分层、蓄/放热流量、SOC | 削峰填谷、调度优化 | 🔶 |

## 5. 平台各优化功能的输入需求（网关按需上送）

| 平台功能 | 所需输入 | 关键要求 |
|---|---|---|
| 负荷预测 | 历史供热量 + 室外温度/天气 + 室温反馈 + 时间特征 | **室温反馈**为精度核心 |
| 水力平衡/计算 | 全网各节点压力/流量/阀位/泵频 | **实时、同步、带时间戳** |
| 气候补偿/按需供热 | 室外温度 + 二次供温 + 抽样室温 | 本地化边界条件 |
| 调度/负荷分配 | 源侧出力 + 各站实时热耗 + 管网传输延迟 | 站点覆盖完整 |
| 应急/解列 | 压力异常、流量突变、泵故障、补水激增 | **事件驱动 + 时间戳** |

## 6. MVP 切入优先级

1. **缺口① 室温/荷侧 + 缺口② 时间同步与质量码**——先做。这两项能立刻、显著提升平台模型精度，**最容易证明价值、最易谈成合作**。
2. **缺口③ 盲区中小站覆盖**——随网关低成本铺开自然带来。
3. **缺口④ 闭环执行回传**——待网关本地控制能力（气候补偿+PID）成熟后上，价值最高但门槛也最高。
4. **缺口⑤ 事件/断网续传**——伴随采集能力同步具备。
