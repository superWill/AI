# 嵌入式踩坑清单(现象 → 根因 → 避坑)

> 真实踩过的坑,按领域分。每条:**现象 → 根因 → 避坑**。
> 配套:[常识清单](embedded-common-sense.md) · [成长路径](embedded-expert-growth-path.md)
> 总纲一句:**卡住你两小时的几乎都不是代码,是物理/系统常识。**

---

## 1. 硬件接线 / 串口

| 现象 | 根因 | 避坑 |
|---|---|---|
| 串口自环不通(发了收不回) | 短接帽**间距不对**(烧录口 2mm vs 排针 2.54mm),或**方向放反**(8/10 同排相邻,帽子要横放,不是跨两排) | 拿不准就用**母对母杜邦线**;先确认 1 脚方向 |
| 单向能通、另一方向不通 | 接**错串口口**(TXD 接到了 pin12=ttyS2,而非 pin10=ttyS1) | 对着手册逐针核对;**用 `/proc/tty/driver/serial` 的 tx/rx 计数器**分方向定位(仪器>猜) |
| 跨机 TTL 收不到 | **没共地**(板子和转接板不同电源,GND 没接) | 跨机 TTL **必须接 GND**;同板才可省 |
| 5V/3.3V 混接 | 电平不匹配,可能打坏 IO | 接前确认电平;USB-TTL 设 3.3V |

## 2. 网络

| 现象 | 根因 | 避坑 |
|---|---|---|
| 跳板机 ping 不通板子 | 接板子的网口缺**主机路由**(/32);WiFi 覆盖了同网段把流量引错口 | `ip route add <板子IP>/32 dev <网口>`;`nmcli dev set <口> managed no` 防网管冲掉 |
| 重启后网络全没了 | 手动配的 IP/路由是**临时态**,断电/重启/网管都会清 | 要持久就写配置文件 + 开机脚本;心里有数"手动=临时" |
| 同网段也访问不了板子 Web | WiFi **AP 客户端隔离**(设备间不让互访) | 用不隔离的网络,或网关自开 AP;调试用 SSH 端口转发 |
| 浏览器开 localhost 转圈/502 | 系统**代理拦了 localhost** | 代理白名单加 `127.0.0.1, localhost`;或用 `--noproxy` |
| 跳板机 IP 变了 | 断电重启后 DHCP/静态地址变化 | 别写死 IP;记录设备的稳定标识 |

## 3. 蓝牙(BLE / BlueZ)

| 现象 | 根因 | 避坑 |
|---|---|---|
| iPhone 配不上裸 Linux 设备 | iOS **只跟有标准服务(音频/HID/MFi)的设备配对** | 控制面板别想着和手机配对;采数据用 BLE 广播/GATT,不需配对 |
| 扫不到指定设备的名字 | BLE **隐私随机地址 + 不报名**(尤其 iPhone) | 用可控的、会报名的设备(BLE 传感器/nRF Connect)做测试 |
| 注册成功但其实没广播 | 广播包**超 31 字节**(128 位 UUID+名字+TxPower) | 广播只放名字,128 位 UUID 等连上后再发现 |
| 板子蓝牙起不来(另一块板) | 设备树 `wireless-bluetooth` disabled / 缺固件 | 先查 `hciconfig`、设备树状态、固件是否在 |

## 4. Modbus / RS485

| 现象 | 根因 | 避坑 |
|---|---|---|
| 大量"请求 CRC 错"、请求粘连 | 从站**靠时间间隔分帧不可靠**,慢一点就把多个请求粘一起 | **按 Modbus 帧长精确分帧**(0x03 请求固定 8 字节);主站发请求留足帧间静默 |
| 读寄存器报"越界/异常码2" | 寄存器**稀疏**(0,1,2 和 10,11),一次连续读跨了空洞 | **分段读**(0-2 一次、10-11 一次) |
| 为什么必须主从 | RS485 是**共享 + 半双工 + 无硬件仲裁**,不定纪律会撞车 | 主站轮询、点名通信;同一总线只能一个时刻一个发 |
| 时间戳全错 | 板子**没 RTC**,重启时间乱 | NTP / 上电向云校时;遥测带 `clock_sync` 标记可信度 |

## 5. 嵌入式 Linux(buildroot / busybox)

| 现象 | 根因 | 避坑 |
|---|---|---|
| `pkill`/`pgrep` 命令不存在,脚本静默失败 → 僵尸进程累积 | busybox **阉割版**,没这些工具;`ps` 也没 `-w` | 用 **`/proc/*/cmdline` 扫描找 PID 再 `kill`**;`killall`(busybox 有)可用 |
| 装不了任何包 | **没包管理器**(opkg/apt/apk 都没)、可能没外网 | 离线 vendor(纯标准库脚本) / 交叉编译静态二进制 |
| 用不了 NetworkManager/systemd | buildroot 非 systemd(busybox init)、无 NM | 用 `wpa_supplicant`/`wpa_cli`/`udhcpc` + `/etc/init.d/Sxx` |
| 改了重启就没 / 改了能持久 | 看根文件系统:只读 rootfs 改了丢;可写 ubifs 改了留 | 先 `mount` 看 rw/ro;关键配置写持久区 |

## 6. 交叉编译 / LVGL

| 现象 | 根因 | 避坑 |
|---|---|---|
| 程序一渲染就段错误 | LVGL 默认 **`LV_COLOR_DEPTH=16`**,而 DRM 是 32bpp,不匹配 | lv_conf 设 `LV_COLOR_DEPTH=32` 配 XRGB8888 |
| 同样段错误(ARM) | 绘制缓冲 **`uint8_t[]` 对齐 1**,LVGL 按 32 位写 → ARM 未对齐访问崩 | 缓冲用 `uint32_t[]`(天然 4 字节对齐) |
| `github.com` 拉代码失败(TLS) | 国内访问被掐 | 用 **gitee 镜像** |
| `lv_font_conv` 报 "Unsupported ttcf" | `.ttc` 是字体集合,工具只吃单字面 | 先用 `fonttools` 抽出 SC 单字面再转 |
| libc/库版本对不上跑不了 | 动态链接 ABI 不匹配 | **`-static` 静态编译**,只依赖 libc,拷过去就跑 |

## 7. DRM / 显示

| 现象 | 根因 | 避坑 |
|---|---|---|
| 黑屏 | **多个 DRM 客户端抢显示**(多实例面板 / 厂家 demo + 自己) | 保证全屏只有**一个** DRM master;守护脚本启动前 `killall` 残留 |
| 想往屏幕画却没 `/dev/fb0` | 现代板子是 **DRM/KMS,无 fbdev** | 不能 `echo > /dev/fb0`;用 LVGL/裸 DRM,或重编内核开 fbdev 仿真 |
| 网页想上屏却上不了 | 板子**没浏览器**(精简镜像) | 控制面板用 LVGL 原生;非要网页得重编固件加 kiosk 浏览器(重) |

## 8. UI / 线程 / 部署

| 现象 | 根因 | 避坑 |
|---|---|---|
| 触摸/切页卡顿 | **UI 线程里做了阻塞 I/O**(串口轮询),`lv_timer_handler` 被卡住 | **采集放独立线程,写走命令队列,UI 线程永不阻塞 I/O**(同网关"采集/上传解耦") |
| 切页后一片 `--` | 读偶尔失败就显示无数据;没缓存 | 缓存**最后好值**;用**颜色标质量**(新鲜/变旧/无数据)——别把旧数据当新数据,也别当没数据 |
| 覆盖二进制 `Text file busy` | 文件正被运行 | **`mv` 改名再写新文件**(Linux 允许重命名运行中的文件) |
| 后台跑的程序看不到输出 | Python **stdout 缓冲**,非交互不刷 | `python3 -u` 或 `flush=True` |

## 9. 选型 / 架构(踩过弯路)

| 弯路 | 教训 |
|---|---|
| 想给低端板装浏览器显示网页 | 浏览器吃 100MB+ 内存、跑满 CPU,低端核扛不住;**控制面板该用 LVGL 原生**(实测仅 2.7MB) |
| 想在小屏上配置设备 | 小屏不便输入;**配置和展示分开**——后台网页配,小屏只显示配好的 |
| 把网页 HMI 硬塞到本地 LCD | 网页 HMI 适合**手机/远程**看;本地操作屏用 LVGL,两者分工 |
