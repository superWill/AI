# ADR-0001：换热站/消防场景 视觉安防——能力与权限边界

- 状态：Proposed（待现场设备清单确认后转 Accepted）
- 日期：2026-07-01
- 决策者：Will
- 适用范围：driver-monitor 视觉栈复用于换热站/消防无人值守站的「人员安防 + 火情可视复核」
- 关联：既有原型 `消防二总线 → MCU 事件锁存 → RK3506 展示/记录/上报`；driver-monitor（RK3568J + GStreamer/MPP + RKNN）

---

## Context

要把 driver-monitor 的视觉栈从「驾驶舱瞌睡检测」改造为换热站/消防站的安防监控：监控人员活动、火情可视预警、录像取证。场景特征与驾驶舱相反——**无人值守、场景常年空、蒸汽/热管/机械/指示灯构成强干扰背景、夜间切近红外(near-IR)灰度**。安防身份带来「错误成本不对称」（漏报 >> 误报）与合规约束。

本 ADR 只钉**能力与权限边界**，不定实现细节。核心风险与被否方案见下。

### 被否 / 被降级的方案
- **纯视觉烟雾检测**：换热站蒸汽在像素上与烟雾几乎不可分 → 白天仅实验性、强 ROI + 高阈值；夜间关闭。
- **近红外当热成像**：普通 IP cam near-IR 夜视靠反射补光、**不测温**，「火焰发热必高亮」不成立。夜间视觉火情不进产品承诺。
- **加热成像(LWIR)**：暂不加。热异常 ≠ 火灾（热管/阀门/电机/蒸汽本就是高温背景），要可靠探火应优先加**适配现场燃料/干扰源的认证火焰探测器**，而非通用热成像。仅当现场数据证明增益，才单独立项验证。
- **person+fire+smoke 单一多类模型**：不预先定死；合模 vs 分模由板端吞吐/精度/误报实测决定。
- **视觉板做人脸白名单鉴权**：否。near-IR 夜间召回差、隐私风险、可靠性差，不压给需故障隔离的哑板。

## 贯穿不变量（所有决策的上位原则）

1. **机器只产事实与推断；顶层「confirmed」（正式火警 / confirmed_intrusion）只能由人或被指定的权威系统产生。** 消防、安防两个危害域同构。
2. **权威是被「指定/工程化」赋予的属性，不是从「信号可读」推断出来的。** 能读门磁 ≠ 门磁权威；能读传感器 DI ≠ 它是认证链。
3. **不确定性只升「通知优先级」，绝不改「事件分类」。** 风险等级不许冒充事实判断。
4. **诚实降级贯到顶**：证据/授权/权威任一缺失，如实标注（`evidence_status=unavailable` / `unverified_presence` / cache as-of 版本），比让事件整体消失或伪装完成判断更可取。

## Decisions（七条边界）

### ① 火情语义与联动边界
视觉/时间规则**永不**产生正式火警或消防联动，只产 `visual_prealert`。正式火警只来自认证探测链（消防二总线→主机）、手动报警按钮或消防主机。人工「看摄像头确认」后的升级动作，其**执行体仍是认证系统**（人到主机/手动按钮操作），视觉不经软件一键确认变火警。认证事件→可反向调取对应片段（取证增强，尽力而为）；视觉→不得反向注入认证链。

### ② 值守假设与通知升级
按**无人值守 / 不能保证及时响应**设计（取最弱响应保证；有人值守只是超集）。`visual_prealert` 与人员事件**远程推送到明确值班岗 + 要求 ack + 超时升级**。**升级只升通知等级（谁被 ping、多响），永不升为火警等级，事件分类不变。** 真火响应由认证链自主联动，**不在人工 ack 关键路径上** → 无人值守/ack 慢不危及消防响应。值班岗界面上认证火警与 advisory 必须**视觉不可混淆**，advisory 永不遮蔽/冒充认证告警。

### ③ 站点网络与存证
网络按**间歇可断**设计：本地自治 + 持久化存证 + 存储转发。检测/录像/本地记录不依赖上行。**证据不可静默覆盖**——视觉事件用独立于遥测环形缓冲的 durable outbox（遥测可丢旧值，证据不可）。补投按优先级 + 原始发生时间，**不冒充发生时间**。队列积压 / 磁盘逼近上限 / 通知链失联**本身必须产生设备健康告警**。

### ④ 硬件切分（两板故障隔离）
每站一块**已验证具备 NPU 的 RK3568J 级视觉板 + 单路摄像头**（MVP）；RK3506 只承担 heating、消防事件汇聚、平台通信，**不塞推理负载，不进消防联动路径**。两板故障隔离是边界①的**硬件级纵深防御**：视觉板 crash/OOM/盘爆不影响认证链。控制/安全依赖**单向**（视觉→RK3506 推 advisory；RK3506 对火情决策永不依赖视觉）；反向仅允许**按 event_id 的尽力证据拉取**，非阻塞可失败。
- 已知限制（须显式记录）：**单摄有覆盖盲区，「无入侵告警 ≠ 无入侵者」。**
- 验证门（硬件接受前必须探测通过，非「有 NPU 即可」）：MPP H.265 硬解、RKNN 人体模型达标 fps、证据盘容量、**片段编码/复用链 `splitmuxsink`/`mp4mux` 在板**。
- RK3506 是「上报」单点 → 其存活须**平台侧心跳监测**（死网关报不了自己的死）。

### ⑤ 两级托管 + 两阶段确认
- 视觉板：保存原始事件、缩略图、完整片段、本地 outbox。
- RK3506：收到**自足事件包（元数据 + 缩略图）**→ 先持久化到自己的 relay outbox → 回 `custody_ack`。`custody_ack` 仅表示 RK3506 接管副本，**≠ 平台已收**。
- 平台业务确认 → `delivery_ack`；两板才可标记已投递。
- 完整片段只留视觉板、按需拉取；丢失 → 事件仍在，标 `evidence_status=unavailable`。
- 两级 outbox 允许重复、**禁止静默丢失**，平台按稳定 `event_id` 幂等去重。
- **握手层也须幂等可重试**（custody_ack 回程丢失时重发+去重，不重复落盘）。
- **片段淘汰资格 = `delivery_ack`/保留策略，永不 = `custody_ack`**；事件投递生命周期与证据保留生命周期分离，仅在「淘汰优先淘已 delivery 者」处相交。
- **视觉板永不直接重传上行**，只向 RK3506 重新交接；`delivery_ack` 回传视觉板为尽力而为（丢了只多占保留，不丢数据）。
- **按事件类别分档托管**：入侵 + 健康故障 = 保证 custody；实验性 `visual_prealert` = 最低耐久档、容量压力下最先淘汰，避免噪声通道饿死真事件。
- 极限诚实：两级托管界定「单板损失」风险，非无限容量；长断网 + 两板 outbox 满 → 回到③容量优先淘汰（先普通循环录像，再低优先级已确认事件）+ 健康告警。**无声丢失禁止，优雅降级有地板。**

### ⑥ 入侵语义（三级来源 / 四级分类）
视觉板**只输出 `person_observation`**（一次人员出现 episode：start/end/confidence/证据引用），**不输出 `person_present` 长状态，不输出 `intrusion`**。
- episode **START 立即发 OPEN observation（触发告警）**，END 发**同 event_id 的幂等更新**（补时长/置信/证据）。触发靠 open 不靠 close（否则进场不告警、离场才告警）。

运营层（RK3506，离线可算）四级语义：
| 分类 | 含义 |
|---|---|
| `person_observation` | 视觉事实，仅表示检测到人 |
| `expected_presence` | 有有效工单/巡检窗口，但**不证明具体身份** |
| `unverified_presence` | 授权上下文缺失/过期/不可访问 |
| `suspected_intrusion` | 窗口外出现，或与门禁/门磁/工单规则冲突 |

- `confirmed_intrusion` **不由视觉或时间规则自动产生**，只来自值班人员确认或被指定的独立安防系统权威结果。
- 不确定 → 升通知优先级，**事件仍叫 `unverified_presence`**。
- `suspected_intrusion` 需**人工双向裁决**（升为 confirmed / 驳回为合法计划外）；裁决作为标注，仅在治理下改进规则，**绝不自动回调权威规则**。
- 授权策略权威源可在平台，但 **RK3506 必须缓存带版本 + 有效期的工单/巡检窗口**；断网且缓存过期 → 降级 `unverified_presence`，不假装完成授权判断。`expected_presence` 须带**缓存版本 + as-of 时间戳**（可能因平台侧撤销而 stale），高安防场景缓存有效期要短。

### ⑦ 物理安防链权威性
门磁 DI（经 DI 或 `KHDQ-0400` 读 0/1）**只是观测，不是权威链**。
- 门开 → `door_open_observation`；门拆 → `tamper_observation`（**须线路监测/独立防拆信号**才成立）。两者单独都不证明入侵。
- 「窗口外门开 + 视觉见人」→ 至多 `suspected_intrusion`（反例：合法抢修、门未关严、维护操作）。
- 仅当**项目明确指定的独立安防系统**输出其自身 `intrusion_alarm`/`forced_entry_alarm`，才映射为 `confirmed_intrusion`。
- 消防与安防不完全类比：认证消防链权威边界有既有工程体系，普通门磁 DI **不天然获得同等权威**。
- **基线（拿到设备清单前）：无权威安防链** → 门磁+视觉+工单融合的自动化天花板 = `suspected_intrusion`，`confirmed_intrusion` 仅人工。
- 融合层落点：门磁在 RK3506 I/O、person_observation 在视觉板，唯一汇合处 = RK3506 → **推断引擎 + 工单缓存跑在 RK3506**（离线自治），平台仅为缓存权威源。

## Consequences

- 视觉系统定位为**认证链旁的增强件**：人员安防主力 + 火情可视复核，永不承担正式火警/联动。
- 站点断网可独立运行：本地检测、录像、存证、离线分类（基于缓存窗口）全部可用。
- 跨两板任一永久损坏，事件与缩略图仍可保全（⑤）；认证消防链在视觉板/盘/网/平台全失效时仍自主联动（①④）。
- 代价：额外状态复杂度（双 outbox、两阶段确认、四级语义、缓存版本），换取跨板故障后的事件保全与告警可信度。

## Open questions（现场事实，非设计决策，待设备清单）
- **F1**：换热站是否部署了带身份授权、强行开门判定、防拆监测的**独立门禁/安防控制器**，而非仅普通门磁？（决定 ⑦ 是否存在权威源、confirmed 能否自动化）
- **F2**：`KHDQ-0400` 输入是否为 **supervised input**（线路监测/EOL）？否则 `tamper_observation` 都发不可靠。
- **F3**：摄像头夜间为 near-IR 灰度已定；**IR 夜间人体召回须单独实测**（白天指标不可外推）。
- **F4**：站点存储容量 `df -h` + 保留天数/合规要求（③⑤ 环形上限按「天」设）。
- **F5**：录像作为工人监控个人数据的**访问控制/目的限定/保留治理**（隐私边界不止「不做人脸」）。

## P0 范围（可离线开发/测试，不依赖板子）
把 pipeline 从「人脸/瞌睡」改造为「人体检测 → person_observation episode 状态机（open/update）→ PNG 存证」。人体后处理与 episode 逻辑为纯逻辑，用现有 `scripts/replay.py` 合成/回放帧序列离线测。**P0 不碰 fire/smoke、不碰四级分类上行**（那是 P1/P2，依赖 RK3506 缓存与 MQTT）。
