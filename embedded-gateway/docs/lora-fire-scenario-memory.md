# LoRa 消防场景项目记忆

更新日期：2026-07-05

## 当前结论

- [KNOWN][HIGH] LoRa 是物理层调制技术；LoRaWAN 才包含标准入网、认证、寻址和网络管理。
- [INFERRED][HIGH] 消防场景中，LoRa 应定位为水压、液位、阀门状态、泵房环境和运维信息的辅助遥测链路。
- [INFERRED][HIGH] 火灾首次报警、声光、喷淋、排烟和消防泵等关键联动不应仅依赖 LoRa。
- [KNOWN][HIGH] 普通 LoRa 终端不能直接挂到消防二总线；通常需要独立 LoRa 链路或专用协议转换设备。
- [KNOWN][HIGH] 普通 UART/SPI LoRa 模块不能直接连接 RS485 端口；需要 RS485-LoRa 集中器或相应接口转换。

## 消防 LoRa 设备三分法（2026-07-06 补）

关键判据：不是"有哪些设备"，而是每个设备**在法规里的身份**。同一个无线烟感，装在出租屋合规、冒充甲类厂房的火灾自动报警系统就违规。

### 一层：辅助遥测——LoRa 的正当地盘（本项目主要接这层）

- [INFERRED][HIGH] 消防水系统：管网/喷淋末端**水压**、水箱/水池**液位**、泵房**流量**、稳压泵启停状态。慢变量，秒级延迟无所谓，LoRa 最扎实的一类。
- [KNOWN][MED] 消防栓监测：内置压力开关+压力传感器，报盗用水/撞倒/欠压；市政场景多用 NB-IoT（无自建网关，蹭运营商基站）而非 LoRa。
- [INFERRED][HIGH] 阀门状态遥信（信号阀/检修阀开关到位，**是遥信不是远程控阀**）、泵房/管廊环境（温湿度/可燃气/门磁）、电气火灾（剩余电流/测温）、运维信息（心跳/电量/故障）。

### 二层：无线探测报警——营销与合规错位的重灾区

- [KNOWN][HIGH] 市场主推：LoRa 无线烟感/温感/手报/可燃气/声光警报器/输入输出模块（青鸟、有人、乐鸟、海康），被包装成"无线智慧消防主机+全套末端"。
- [KNOWN][MED] **品类区分（量产前须核对条文）**：这些无线烟感在法规上属 `独立式感烟火灾探测报警器`（GB 20517），**不是** `火灾自动报警系统`（GB 50116）里的联网探测器。
  - GB 50116 强制场所要求有线火灾自动报警系统+二总线+联动控制器，喷淋/排烟/卷帘联动不许仅靠无线（呼应本文档第 9 条）。
  - LoRa/NB 无线烟感的合法主战场=**独立式报警**：九小/三小场所、出租屋、老旧居民楼、养老院、文物古建等布线难又非强制联网处，做"独立报警+云端转发手机/街道"。
- [INFERRED][HIGH] 搜索里列的应用场景（学校/库房/公寓/福利机构/博物馆）全是独立报警类，不是甲级写字楼主报警系统。

### 三层：网关/集中器（一对多的汇聚点，别漏）

- [KNOWN][HIGH] 私有 LoRa 星型集中器（RS485 出口）：亿佰特 E53-GW、四信、海康私有主机——主网关当一个 RS485 从站，帧内带 DeviceID。
- [KNOWN][HIGH] 标准 LoRaWAN 集中器（SX1302）：H3C IG4500-L、HKT、YOBIIQ 配套网关，走 ChirpStack/NS。
- [KNOWN][MED] 国际标准 LoRaWAN 烟感选型参考：HKT SD100、YOBIIQ SD-1001、GlobalSat LS-134、Netvox RA02G。

### 对 RK3506 设计的落点

- [INFERRED][HIGH] 本网关真正要接的几乎全是**第一层**（水压/液位/阀位/环境），走已定的 lora bus `report`/`poll` 双模。
- [INFERRED][HIGH] 若接第二层无线烟感，务必在设备档案标成"辅助/独立报警"性质、与真正的火灾自动报警系统在数据模型上隔离，**不许在 UI 冒充首警源**，否则把厂商彩页的合规错位继承进产品。

## 双 RS485 网关的当前建议

```text
RS485-1 → 二总线协议转换器 → 消防二总线设备
RS485-2 → RS485-LoRa 集中器 ))) 多个 LoRa 辅助监测终端
```

- [INFERRED][HIGH] 主网关把 LoRa 集中器视为一个 RS485 从站。
- [INFERRED][HIGH] 集中器返回的数据必须携带终端 DeviceID，主网关再映射到设备类型和安装位置。
- [INFERRED][HIGH] 如果网关有可用以太网、USB、SPI 或额外 UART，优先用这些接口接 LoRa，把 RS485 留给现场总线。

## 身份与配置原则

- [KNOWN][HIGH] LoRa 物理层本身不提供完整设备身份管理。
- [COMMON][HIGH] 私有 LoRa 报文至少应包含 `DeviceID`、消息类型、计数器、长度、载荷和校验字段。
- [KNOWN][HIGH] `DeviceID + CRC` 不能证明真实身份；需要安全认证时使用每设备密钥和标准消息认证码。
- [KNOWN][HIGH] LoRaWAN 使用 `DevEUI`、`JoinEUI`、根密钥完成 OTAA，并在会话中使用 `DevAddr`、会话密钥、帧计数器和 `MIC`。
- [COMMON][HIGH] 设备档案应维护 `DeviceID → 设备类型 → 安装位置 → 解析器 → 密钥索引` 的映射。

## 已商品化的配置方式

- [KNOWN][HIGH] 厂商私有配对：网关进入添加模式，终端靠近并按键配对，网关保存终端身份。
- [KNOWN][HIGH] 标准 LoRaWAN：平台预注册终端标识和密钥，终端通过 OTAA 入网。
- [COMMON][HIGH] 私有星型集中器：集中器维护节点表，或透传包含 DeviceID 的报文给主网关。
