# LoRa 协议梳理与网关对接方案

> 目标：为 RK3506 集成网关评估 LoRa 接入路径（抄表 / 阀控类低速率设备），
> 并给出最小成本的实测方案。
> 本文技术参数为业内通识；国内频段监管细节标注了置信度，采购前建议复核原文。

## 1. LoRa 是什么：分清三层

| 层 | 名称 | 归属 | 说明 |
|---|---|---|---|
| 物理层 | **LoRa (PHY)** | Semtech 私有调制 | CSS 线性扫频扩频调制，芯片只有 Semtech 及授权厂（SX1262/SX1268/LLCC68 等） |
| MAC 层 | **LoRaWAN** | LoRa Alliance 开放标准 | 星型拓扑 + 入网/加密/信道规范，需要网关 + 网络服务器（NS） |
| 私有协议 | **透传/私有星型** | 各模块厂自定义 | 如亿佰特 E22 的透传/定点模式，国内抄表行业大量使用 |

**关键结论：买了 LoRa 模块 ≠ 有了 LoRaWAN。** 透传模块（E22 等）只给你一条无线串口，
组网、寻址、防冲突、加密全部要自己做（或用厂家的定点模式做一半）。

## 2. LoRa PHY 核心参数

- **频段**：Sub-GHz ISM。中国常用 470–510 MHz（计量仪表）与 433 MHz；欧洲 868 MHz；美国 915 MHz。
- **扩频因子 SF7–SF12**：SF 越大 → 灵敏度越高、距离越远，但速率越低、空口时间指数级变长。
  SF12/125kHz 灵敏度约 -137～-148 dBm，链路预算可到 ~170 dB。
- **带宽 BW**：125 / 250 / 500 kHz；**编码率 CR**：4/5–4/8。
- **速率**：约 0.3–62.5 kbps（透传模块常给 2.4k 默认档）。抄表一帧几十字节完全够。
- **距离**：22 dBm + 胶棒天线，城市楼宇间 1–3 km，郊区开阔 5 km+（厂标 5 km 是理想值）。
- **半双工、无载波侦听**：本质是 ALOHA 信道，多节点同发必然撞包 → 上层必须做
  **轮询（master 逐个点名）** 或 **时隙**，这是私有组网设计的核心。

### 国内频段监管（置信度：中，采购/量产前需复核）

工信部 2019 年第 52 号公告（微功率短距离设备）：470–510 MHz 划给**民用计量仪表**类使用，
e.r.p. ≤ 50 mW，且对发射占空比/单次发射时间有限制。热表/阀控属计量场景，用 470 段合规风险最低。
LoRaWAN 的 CN470 频段规范（470.3–489.3 MHz 上行）即基于此。

## 3. LoRaWAN 要点（如果走标准路线)

```
终端(Class A/B/C) --LoRa--> 网关(SX1302 集中器, 纯透传)
    --Semtech UDP / BasicStation--> 网络服务器 NS (ChirpStack v4)
    --MQTT/gRPC--> 应用(我们的 gateway-go / 平台)
```

- **Class A**：终端主动上行后才开 2 个下行窗口，最省电 → 适合电池热表。
- **Class C**：常收，下行随时可达 → 适合市电阀控（要下发开关阀命令就得 B 或 C）。
- **入网**：OTAA（DevEUI/JoinEUI/AppKey 派生会话密钥，推荐）或 ABP（写死密钥）。
- **安全**：AES-128 两层（NwkSKey 完整性 / AppSKey 载荷加密），帧计数防重放。
- **NS 选型**：ChirpStack v4（Go 写的，单二进制 + PostgreSQL/Redis），可跑在服务器，
  也能跑在 ARM Linux 网关本地；应用侧走 MQTT 集成，gateway-go 订阅即可。
- **网关硬件**：必须是 SX1302/SX1303 集中器（8 信道并发解调）。
  单信道"假网关"（SX1276 自制）只能收一个 SF/频点，仅玩具用途，不要买。

## 4. RK3506 网关的三条对接路径

### 路径 A：透传/定点模式私有组网（推荐先做）

```
热表/阀控 + E22 模块  <--LoRa 定点模式-->  E22 模块 --UART/USB--> RK3506 gateway-go
```

- 硬件：网关侧 1 片 E22-400T22D 接 UART（或 E22-400T22U 直接插 USB）；设备侧同款模块。
- E22 要点：M0/M1 引脚切模式（传输/WOR/配置/休眠）；配置模式下发参数帧设
  地址/信道/空速/功率；**定点模式**下帧头带目标地址+信道，可实现一对多点名。
- gateway-go 侧：`go.bug.st/serial` 开串口 → 自定义帧（地址 + 命令 + 长度 + 载荷 + CRC16）
  → **主从轮询**收发，超时重发 2–3 次。与现有 Modbus/DL/T645 抄表的主从模型同构，
  代码结构可以直接复用轮询调度器。
- 优点：<¥100 打通全链路，无 NS 依赖，行业内热表本来就多用这种方案。
- 缺点：无标准加密/入网，协议自己维护；换厂家模块要重写。

### 路径 B：标准 LoRaWAN（设备生态要求时再上）

- 网关侧：SX1302 USB 集中器（或 mini-PCIe/SPI 模块 + 转接）接 RK3506，
  跑 `sx1302_hal` packet forwarder；ChirpStack 部署在服务器（RK3506 A7 核跑全套 NS 偏重）。
- gateway-go 通过 MQTT 订阅 `application/+/device/+/event/up`，下行发 `.../command/down`。
- 成本：集中器模块/HAT 约 ¥400–800，外加一个 LoRaWAN 终端开发板调试。
- 触发条件：接入的表/阀本身是 LoRaWAN 出厂协议，或平台方要求标准化。

### 路径 C：外挂商用 LoRaWAN 网关

买 Dragino/RAK 成品网关，RK3506 只做应用层（MQTT 对接 NS）。设备量大、不想碰射频时用。
测试阶段不推荐——贵且学不到东西。

## 6. 最小测试计划

1. 两片 E22 + USB-TTL 分接两台电脑（或一台电脑双串口），透传模式互发，验证收发/距离/丢包。
2. 切定点模式，配不同地址，验证一对多点名。
3. 网关侧模块接 RK3506 UART/USB，gateway-go 里写轮询 demo：每 5s 点名一个从机地址，
   收响应帧校验 CRC，统计 RSSI（E22 可开 RSSI 字节输出）与丢包率。
4. 拉距离实测：楼内、跨楼、小区尺度各测一组 SF/空速档位，记录丢包-距离曲线。
