# facgw —— 消防控制室图形显示装置（CRT）侧网关

火灾报警控制器的上位机端：对下按 `docs/protocols/crt-link-draft.md` 收控制器上行报文，
对上提供消防监控页面。控制器侧（主机）不在本目录，见 `fire-alarm/firmware/`。

## 为什么先做这一端

执行表 `docs/testing/test-cases-execution.xlsx` 里有 **31 条用例卡在"待条件：需 CRT 对端"**
——CM-02/03/04/10～15/17、UI-15/22、LC-03.6、FT-07.4、WD-01.5。没有对端设备就测不了
"五类信息上报"、"协议一致性"、"授时接收"、"CRT 通信断时本地仍能独立判定"。本网关就是
那个对端；同时 GB 16806 本来也要求主机能与图形显示装置通信，属产品必需件。

## 跑起来

```bash
cd fire-alarm/gateway

# 无硬件演示：自带模拟主机，脚本循环播放一个完整现场（故障→首火警→联动→反馈→监管→屏蔽→复位）
go run ./cmd/facgw -sim -points points.sample.json

# 接真机：控制器作为 TCP 客户端连到 :7801（串口场景用 socat 桥接）
go run ./cmd/facgw -points points.sample.json
```

页面在 http://127.0.0.1:8080 。串口接法：

```bash
socat -d -d /dev/tty.usbserial-XXXX,b9600,raw,echo=0 TCP:127.0.0.1:7801
```

## 页面

| 区域 | 内容 |
| --- | --- |
| 顶栏 | 链路 / 主电 / 备电状态灯 + 时钟 + 授时·自检·复位下行命令 |
| 六计数 | 火警·监管·启动·反馈（红）· 故障·屏蔽（黄）——配色按 GB 4717 5.3.2.1 灯色规则 |
| 首火警条 | 首火警锁存显示，复位前不被后续火警顶掉（5.4.1.7）|
| 事件记录 | 全量事件流，按类型筛选，时间倒序 |
| 点位状态 | 点表视图：一个点可同时显示火警+故障+屏蔽（状态位并存，不压扁）|
| 报文 | 收发帧的十六进制原文 + 解析结果，供协议一致性核对（CM-04 / CM-10 / CM-14）|

## 协议实现要点

帧格式 `SOF(1) VER(1) SEQ(2) SRC(2) DST(2) TYPE(1) LEN(2) DATA(0..1024) CRC(2)`，
多字节小端，CRC-16/MODBUS（0xA001 反射，初值 0xFFFF）覆盖 SOF..DATA。

**与草案的一处差异，须与固件侧对齐后回写草案**：草案写"0x7E 在 DATA 中转义"，但
SEQ/LEN/CRC 同样可能取到 0x7E——只转义 DATA 的话，一个 `SEQ=0x007E` 的帧会被接收端
当成新帧起始，链路直接错位。本实现**对 SOF 之后的全部字节转义**，使 SOF 成为流中唯一
的 0x7E，重同步才有确定语义。`TestEscapeCoversHeaderNotOnlyData` 锁这个行为。

## 状态保持语义

三种保持方式在代码里是分开的，这是最容易写错的地方（`internal/model/state.go`）：

| 类别 | 行为 | 条款 |
| --- | --- | --- |
| 火警 / 启动 / 监管 | 锁存，保持至手动复位 | 5.4.1.1 / 5.4.2.9 / 5.4.5.2 |
| 故障 / 反馈 | 跟随，源消失即消失 | 5.4.3.2 / 5.4.2.9 |
| 屏蔽 | 独立于复位，只能手动解除 | 5.4.4.7 |

复位帧只清锁存态；屏蔽不动，故障也不清——故障由主机在复位后重新上报（5.4.3.8）。
`state_test.go` 的每条用例都对应一条条款，跑 `go test ./...` 即验证。
