# User Notes

以下是当前关于消防业务和现有方案的现场信息整理，保留原始判断，后续逐条验证。

## Current Facts / Assumptions

1. 现场设备使用二总线。单回路最多约 256 个设备，因为地址按 2 字节设计；这与普通 DI/DO 点位不同。
2. 现有单片机负责屏幕显示和硬件按钮。屏幕不可点击，界面是按坐标硬编码绘制。
3. 现在有串口显示器方案，优势是可拖拽、适配快，劣势是价格高。原屏幕约 10 元，串口显示器约 120 元。
4. 新设计目标是把单片机替换成嵌入式平台。原因是单片机定制成本高，每次需求变更都要重新开发；嵌入式更适合利用 AI 和软件化配置，降低定制成本。
5. 新平台希望在消防基础上增加安防能力，例如 2 路视频采集 + 分析。
6. 现在网关已经内置，但仍需要外接一根网线。
7. 多个主机互联使用 RS485，类似局域网互联。
8. 受实际场景限制，现场人员较少，需要产品降低人工配置、维护、排障成本。
9. 目标是在 RK3506 上完成原单片机的采集和控制能力，同时设计有价值的附加功能。
10. 资源问题需要重点核查：原 MCU 是 GD32F407VET6，RK3506 是否能完全支撑原有实时控制、二总线、HMI、联网和扩展能力。

## Terms To Normalize

- “设备”与“点位”要区分。一个设备可能对应多个输入/输出/状态点。
- “二总线 256 设备”是协议地址空间上限，不等于认证可用容量。实际上限还受总线供电、电流、轮询周期、响应时间、故障隔离和型式试验约束。
- “嵌入式替代单片机”不是只替换芯片，而是产品架构从固定固件改成“可配置平台 + 安全控制内核”。

## Immediate Expert Judgment

这个方向有商业价值，但不能把消防安全链路做成普通消费级 IoT 网关。

消防主机的底线：

- 离线也必须报警和联动。
- HMI 卡死不能影响报警采集和联动输出。
- 网络断开不能影响本机判定。
- AI 功能只能做辅助分析和运维增强，不能直接绕过消防联动规则。
- 如果进入认证产品，硬件和软件架构变更会触发认证/复测成本。
