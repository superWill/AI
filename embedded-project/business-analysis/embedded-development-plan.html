Embedded Development Plan

热能共控机嵌入式开发梳理

当前共控机面向换热站和小区侧系统，一次侧热媒为热水，配置板式换热器，主通信协议为 MQTT，并需要本地屏、远程升级和断网自治。开发策略应以安全保护为最高优先级，再实现稳定控制、远程运维和节能优化。

产品边界

安全优先

任何自动控制、远程指令、本地手动操作，都必须先经过安全保护层判断。

本地自治

MQTT 断线后设备继续按本地参数运行，不能因为平台不可达而停止供热或丢失参数。

远程运维

支持数据上报、告警上报、参数下发、远程指令、OTA 升级和执行回执。

软件架构

建议采用分层架构。底层负责点位和驱动，中间层做校验、安全和状态机，上层处理控制策略、HMI、MQTT 和 OTA。

MQTT / HMI / OTA平台通信、本地屏交互、远程升级、参数同步、告警和事件上报。
控制算法供水温度控制一次侧调节阀，压差控制循环泵，低压控制补水。
状态机上电、自检、待机、启动、运行、调节、告警、急停、维护、升级。
安全保护层超温、超压、低压、缺水、泵故障、关键传感器故障，优先级最高。
数据校验滤波、量程判断、断线判断、跳变判断、数据质量标记。
点表与驱动AI、DI、AO、DO、温度、压力、流量、热表、阀门、泵、变频器。

核心模块

模块 开发重点 优先级
点表模块 统一定义测点、单位、量程、数据类型、阈值、采样周期和 MQTT 映射。 最高
安全保护模块 超温、超压、低压、缺水、泵故障和关键传感器故障处理。 最高
状态机模块 约束启动、运行、告警、急停、维护和升级流程，避免动作混乱。 最高
控制算法模块 供温闭环、压差闭环、补水闭环，先简单可靠，再逐步优化。 高
MQTT 模块 鉴权、心跳、遥测、告警、参数、命令、回执、断网缓存。 高
本地屏模块 总览、参数、告警、手动控制、权限、通信状态和升级状态。 高
OTA 模块 下载、签名校验、双分区/回滚、升级窗口、安全状态拦截。 中高

开发阶段

Phase 1 最小安全控制器
  • 点表
  • IO 驱动
  • 数据校验
  • 安全保护
  • 基础状态机
Phase 2 换热站控制
  • 板换点位
  • 一次侧阀门
  • 二次侧循环
  • 补水联锁
  • 启停顺序
Phase 3 MQTT 接入
  • 心跳
  • 遥测
  • 告警
  • 参数下发
  • 指令回执
Phase 4 可靠性与升级
  • OTA
  • 看门狗
  • 日志
  • 掉电保存
  • 断网补传
Phase 5 节能优化
  • 温度补偿
  • 分时段策略
  • 回温优化
  • 多泵轮换
  • 远程诊断
