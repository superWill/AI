# Baseline 实验结果（公开数据天花板探测）

> 2026-06-10 · 数据 donateacry(457条/221婴儿) + ESC-50(2000条) · 特征 MFCC(85维) · 模型 逻辑回归 · 评估 5折交叉验证
> 复现：`data/.venv/bin/python baseline/run_experiments.py` 与 `baseline/leakage_demo.py`

## 一句话结论

**L1 哭声检测 = 能打（AUC 0.986），今天就能商用；L3 意图分类 = 公开数据约等于噪声（按婴儿切分后接近随机），产品级必须靠自采数据。** 这不是模型不行，是数据不行。

## 实验 A — L1 哭声检测 ✅

donateacry 哭声 + ESC-50 婴儿哭 vs 49 类家庭环境音（狗叫/吸尘器/洗衣机/闹钟…），按婴儿/ESC官方fold 组切分。

| 指标 | 数值 |
|---|---|
| ROC AUC | **0.986** |
| balanced accuracy | 0.939（多数类基线 0.798） |
| **召回 @ 误报率 1%** | **0.706** |
| **召回 @ 误报率 5%** | **0.924** |

**解读**：连最廉价的 MFCC 特征都能把哭声从家庭噪声里干净分出来。换成 YAMNet/预训练 embedding 只会更高。产品口径"整夜低误报"成立——容忍 5% 误报时能抓到 92% 的哭声。**L1 是可靠卖点，无悬念。**

## 实验 B — hungry vs rest（二分类）⛔

| 指标 | 数值 | 含义 |
|---|---|---|
| ROC AUC | **0.479** | ≈ 0.5，**与随机猜测无异** |
| balanced accuracy | 0.466 | 低于"永远猜饿"的多数类基线 0.836 |

**解读**：在无泄漏评估下，MFCC 特征里几乎不含"饿/非饿"的可分信息。

## 实验 C — hungry/tired/discomfort（三分类）⛔

```
混淆矩阵 行=真值 列=预测   [discomfort, hungry, tired]
discomfort   1   16   10     ← 27条里只认对1条
hungry      43  286   53     ← 几乎全往"饿"猜
tired        2   20    2     ← 24条里只认对2条
```

| 指标 | 数值 |
|---|---|
| balanced accuracy | **0.290**（三分类随机=0.333，**低于随机**） |
| macro F1 | 0.295（全靠 hungry 一类撑着） |

**解读**：这就是预言中的"**猜饿机**"——模型学到的唯一策略是"全猜饿"。discomfort/tired 各自只有二三十条、来自十几个婴儿，根本不构成可学习的类别。

## 实验 D — 泄漏对照（为什么文献能报 60-71%）🔍

同一份数据、同一模型，只改交叉验证切分方式：

| 切分方式 | balanced_acc | macro_F1 |
|---|---|---|
| 随机分层（同一婴儿哭声可同时进训练/测试，**似多数文献**） | 0.379 | 0.359 |
| 按婴儿分组（测试婴儿训练时没见过，**真实泛化**） | 0.290 | 0.295 |
| 泄漏虚高 | **+0.089** | +0.064 |

**解读**：随机切分凭空多出 ~9 个点，靠的是"认出这是同一个宝宝的嗓音"而非"听懂需求"。文献里漂亮的数字 = 多数类占比（83%基线）+ 这种泄漏 + 比 MFCC 更强的特征，三者叠加的产物，不代表真实场景能用。

## 对产品决策的硬约束

1. **L3 意图卡片不进 MVP**。公开数据下连方向都看不到，上线即翻车。PRD 第 5 节 P2 的 F9 必须等自采数据达标后才评审。
2. **L1 + L2 是产品地基**。L1 已验证；L2（痛/非痛）赌在疫苗场景自采的客观真值上，是下一个要验证的点。
3. **少数类的死结**：discomfort/tired/burping 在公开世界各只有 8-27 条。增广救不了"类别不存在"，唯一出路是 App 反馈闭环按行为验证攒标注（"喂奶后停哭=饿"）。
4. **本结果是保守下界**：MFCC 是手工特征基线。YAMNet/wav2vec2 embedding 可能把 L3 抬一点，但抬不动"每类几十条"的根本盘——可作为后续确认实验，不改变 MVP 决策。
