# 闭环与建议引擎设计

> 2026-06-10 · 配套 PRD v0.5 / 技术方案 v0.3。
> 解决的问题：现有只是「**数据收集闭环**」（录音→分析→日志→反馈→捐赠），缺「**建议有效性闭环**」——App 不知道自己给的建议有没有帮到家长。
>
> 🎯 **产品核心（钉死）**：闭环不是"App 判断宝宝为什么哭"，闭环是"**App 帮家长排查，并记住什么办法对这个宝宝有效**"。关键问题不是"识别哭声"，而是——**这次哭，什么办法最终有效？**

## 0. 核心差别

| | 数据收集闭环（已有） | 建议有效性闭环（本文要补） |
|---|---|---|
| 记录 | 哭声样本 + "你觉得是什么" | **给了什么建议 → 家长做了什么 → 有没有缓解、多快** |
| 产出 | 声音样本库 | 知道"建议是否有效" + 个人模式 + **行为验证强标签** |
| 价值 | 攒数据 | 让 App **越用越准地给建议**，且为未来 L2/L3 产出高质量标签 |

> 一句话：必须把**家长采取的动作**和**缓解结果**记下来，否则 App 只能积累声音，不知道自己有没有用。

## 1. 完整使用闭环（8 步）

```
1. 录音 5–15s
2. 输出 哭声强度 + 录音可信度（DSP+L1质量检查，不下判断）
3. 给出 2–3 个排查建议（按上下文 + 个人历史排序）
4. 家长选「我先试这个」          ← 把建议和动作绑定
5. App 约 5 分钟后温和追问结果    ← 延迟追问（本地通知，可忽略）
6. 记录：做了什么 + 是否缓解 + 多快
7. 更新宝宝个人哭声档案
8. 下次基于历史 + 上下文 重新排序建议
```

第 4–6 步是现在缺的核心。第 7–8 步把它变成"越用越准"。

## 2. 关键新增环节

### 2.1 建议承诺：「我先试这个」
- 第 3 步给 2–3 条建议，每条带一个「先试这个」按钮。
- 点击即建立 `suggestion → action` 绑定，并启动第 5 步的追问计时。
- 也允许"都试过了/直接记录"，不强制。

### 2.2 延迟追问（缓解结果）
- 约 3–5 分钟后**本地通知**（非后台音频，合规无碍）："刚才宝宝怎么样了？"
- **做了什么**（可多选）：喂奶 / 拍嗝 / 换尿布 / 哄睡 / 抱抱安抚 / 量体温 / 其他
- **缓解程度**：已缓解 / 有一点缓解 / 没变化 / **更严重**（缓解"程度"比"多快"更能反映办法是否有效）
- 「更严重」或多次"没变化"→ **立即跳到升级/就医**（见 §5），不只是记录。
- 情绪设计：温和、可一键忽略、可静默；绝不反复打扰刚安顿好的家庭。

### 2.3 建议有效性记录
- 落库三元组：`offered_suggestions → chosen_action → outcome(缓解程度+时长)`。
- 这就是"建议是否有效"的闭环数据，也是后续个人化排序与 L2/L3 训练的来源。

## 3. 上下文 schema（每次记录都采，判断才不弱）

```
月龄
上次喂奶距今 (min)
上次睡觉距今 / 是否刚睡醒
上次换尿布距今 (min)
当前时间段 (晨/午/晚/夜)
本次哭了多久 (s)
伴随症状: 发热 / 呕吐 / 呼吸异常 / 精神差  (→ 直接触发就医红线)
环境噪声水平 (来自 L1 质量检查的 SNR)
```
- 表单要快：智能默认（喂奶/睡眠/换尿布时间可从历史自动推算并让用户确认）、可跳过。

## 4. 个人哭声档案 + 历史驱动的建议排序

**这是规则/统计，不是 ML**——对家长自己历史结果做透明聚合 + 上下文规则。可解释、可关闭，契合"v1 不下 ML 判断"。

排序输入：
- 上下文规则：`距上次喂奶 > 阈值 → 饥饿优先`；`刚换尿布 < 30min → 尿布降权`；`接近惯常入睡点 → 困倦优先`。
- 个人历史：`该宝宝 + 类似时段/上下文 下，哪种动作"缓解"占比高`。

呈现（务必谦逊，见 §6 因果警告）：
```
过去 7 天，夜里 23 点后哭闹，70% 是哄睡后比较快好转
距上次喂奶已 3 小时 → 这次建议优先看看饥饿
刚换过尿布 20 分钟 → 尿布这次往后排
```

## 5. 升级路径（持续没缓解 / 危险信号）

不能无限猜原因。触发任一即提示**联系医生/线下就医**、App 收手：
- 单次会话**持续哭闹 > X 分钟**且追问为"还在哭/更严重"。
- 上下文或追问出现：发热 / 呼吸异常 / 呕吐 / 精神差（就医红线）。
- 同一问题**短期内反复无效**（多次建议都没缓解）。

## 6. ⚠️ 因果性警告（设计红线）

"做了动作 → 缓解"**不等于**该动作起的作用——宝宝可能本就要停、或是综合因素。因此：
- 历史排序只作**温和先验**："上次类似情况，喂奶后比较快好"——**绝不**说"喂奶能解决"。
- 不对单次"缓解/未缓解"过度归因；用足够样本的聚合趋势，并标注"经验参考"。
- 这是第 0 原则（不过度承诺）在建议引擎上的延伸。

## 7. 数据模型（追加，配合技术方案 §7）

```
cry_record(id, ts, duration_s, rms_intensity, pause_ratio, quality_ok, ...)
context(record_id, since_feed_min, since_sleep_min, since_diaper_min,
        age_months, daypart, symptoms_json, env_snr)
suggestion(record_id, items_json, ranking_basis)         # 给了哪些建议、依据
action(record_id, taken_json, ts)                        # 家长做了什么
outcome(record_id, relief_level, relief_minutes, ts)     # 缓解程度+时长(追问回填)
baby_profile(baby_id, pattern_json, updated_ts)          # 个人模式(聚合产物)
```

## 8. 对未来 L2/L3 的价值

`动作 → 缓解(含时长)` 是**行为验证标签**，远强于"你觉得是什么"：
- "喂奶后 1 分钟好" ≈ 真饿；"换尿布后好" ≈ 真不适。
- 这批高质量标签 = 以后训练"原因预测(L3)/紧急度(L2)"的前提（达标才上，闸门见 PRD §6.5）。
- 即：本文要补的闭环，既改善 v1 体验，又是解锁未来判断能力的唯一正路。
