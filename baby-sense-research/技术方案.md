# 婴儿哭声感知 App — 技术方案（TDD）

> 版本 v0.2 · 2026-06-10 · 状态：草案
> 配套文档：产品侧 [`婴儿哭声感知-方案与PRD.md`](婴儿哭声感知-方案与PRD.md) · 实测 [`baseline/实验结果.md`](baseline/实验结果.md) · 数据 [`数据清单.md`](数据清单.md)
> 本文只讲"怎么实现"。能力边界与产品决策以 PRD v0.3 为准。
>
> ⚠️ **v0.2 形态调整**：MVP 改为**主动式单手机 App**（家长哭时打开录音→端侧判断→记录→反馈），**不做后台常驻/双端监护**——后者降为 §5「远期可选」。
> **MVP = 主动录音 + L1 哭声确认(已验证) + 记录 + 反馈闭环；L2"要不要紧"为主打但需先自采数据；L3 意图后置。**

## 1. 设计目标与约束

### 1.1 工程目标
- 纯 App（iOS + Android），**端侧推理**，音频不出设备。
- **主动录音→结果**低延迟（≤3s）；L1 哭声确认低误报。
- 单手机前台使用，无需后台常驻、无需双端、无需服务器推理。
- 一套训练产物导出双端，**iOS/Android 结果一致**。
- 内置"录音→反馈→标注→回传"闭环，为 L2/L3 攒自采数据。

### 1.2 硬约束（决定架构）
| 约束 | 来源 | 架构后果 |
|---|---|---|
| iOS 后台麦克风受限 | 平台 | **MVP 主动式前台使用，从根上规避**（不常驻、不后台）；双端监护降为远期 |
| 音频零上云（隐私承诺） | PRD 原则 | 推理全在端；音频只在内存，捐赠片段需单独授权 |
| 儿童音频=敏感个人信息 | 个保法 | 默认不上传；捐赠走单独同意 + 境内存储 |
| L2 无数据、未验证 | 实验结论 | v1 不接 L2 决策；先攒数据，AUC≥0.90 才上 |
| L3 公开数据不可行（实测） | 实验结论 | 不接入决策；预留接口，闸门达标才上 |

### 1.3 非功能指标（端侧）
| 项 | 目标 |
|---|---|
| 录音→结果延迟 | ≤3s（单机前台推理） |
| CPU/内存 | 一次会话短时推理，无常驻开销 |
| 模型体积 | L1 头 67KB（实测）；含 YAMNet 约 4MB；蒸馏可压更小 |
| L1 误报 | 召回 ≥0.95 @ FPR≤5%（公开数据已达，真实场景待验证） |

## 2. 系统总体架构（主动式，单手机）

```
┌──────────────── 用户手机 (前台主动使用) ────────────────┐
│  [家长点"录一段"]                                        │
│    → 采音 10–20s (16kHz mono) → 内存缓冲(不落盘)          │
│    → 前处理 log-mel → YAMNet embedding (端侧)            │
│    → [L1] 哭声确认 (CoreML/LiteRT, 已验证)               │
│         否→提示"没听到哭声/太吵, 重录"                    │
│    → [L2] 紧急度 痛苦/要紧 vs 普通烦躁 (数据到位后接入)    │
│    → 结果卡片: 紧急度% + 哭声特征 + 安抚/上下文建议        │
│    → 写入本地记录(仅元数据, 无音频)                        │
│    → [事后] 家长反馈"实际是什么"                          │
│         └─(单独授权)→ 片段+标签 → 云数据闭环              │
└──────────────────────────────┬───────────────────────────┘
                                │ 仅授权捐赠 / 模型OTA
                                ▼
                  ┌──── 云 (可选, 不做推理) ────┐
                  │ 捐赠片段入湖 + 标注          │
                  │ 训练/蒸馏 → OTA 下发模型     │
                  └─────────────────────────────┘
```

要点：
- **全程单手机前台**：录音是用户主动行为，不触碰 iOS 后台限制，无需双端/无需常驻。
- **音频只在内存**：处理完即弃，不落盘、不上传；唯一例外是用户在反馈后**单独授权**捐赠的那段。
- 云**不做推理**，只做（授权）捐赠数据汇聚与模型训练下发。无云也能用（仅推理+本地记录）。
- 远期"被动夜间监护"才需要常开 VAD/三级漏斗/双端，见 §5。

## 3. 端侧检测引擎（核心）

### 3.1 音频采集（主动录音，前台）
| 平台 | API | 配置 |
|---|---|---|
| iOS | AVAudioEngine + installTap | 16kHz, mono, Float32；AVAudioSession `.record`，**前台录音**（无需 audio 后台模式）；处理中断/路由变化 |
| Android | AudioRecord（或 Oboe） | 16kHz, mono, PCM16；**前台录音**（无需常驻 FGS） |

- 用户点"录一段" → 采 10–20s（或检测到静音自动停）→ 16kHz mono → 内存缓冲（不落盘）。
- 录完整段一次性送推理；无需常开环形缓冲（那是远期被动监护才要的）。

### 3.2 前处理（与训练严格一致）
- 帧：25ms 窗 / 10ms 跳（win=400, hop=160 @16k）。
- 特征：log-mel（YAMNet 输入规格：64 mel, 0.96s patch）。**特征实现跨端与训练端逐位对齐**（同一套常量），否则端侧精度塌方。
- baseline 已用 scipy 复现 mel（`baseline/features.py`），端侧走 YAMNet 自带前端或 Accelerate(iOS)/ndk。

### 3.3 推理流程（主动式，线性）
```
录音段 → log-mel → YAMNet embedding(整段池化)
      → [L1] cry_prob > τ1 ?
           否 → "没听到明显哭声/太吵，请靠近重录"
           是 → [L2] pain_prob → 紧急度("要紧" vs "普通烦躁") + 概率
      → 结果卡片(紧急度 + 哭声特征 + 建议) → 写记录 → 等反馈
```
- **L1 阈值 τ1** 取 ROC 上低误报工作点（拒绝电视/人声/宠物等非哭声）。
- **哭声特征**（音调高低/时长/间歇）从 log-mel 直接算，作可解释展示，非"翻译"。
- v1 **不接 L2 决策**（无数据）；接口预留，L2 上线后填入紧急度判断。
- > 远期被动监护才需要 `IDLE→SOUND_EVENT→CRYING→ESCALATE` 的常开状态机 + VAD 级联唤醒 + 去抖，见 §5。

### 3.4 模型现状（实测，公开数据）
| 层 | 方案 | 实测 |
|---|---|---|
| L1 | YAMNet 迁移 + Keras 头（可蒸馏） | AUC 0.999、召回 1.000±0.000 @5%误报；零样本即 0.986（`baseline/train_l1_model.py`，导出 TFLite 67KB） |
| L2 | YAMNet embedding + 小头 / log-mel CNN | **未验证、无数据**；待疫苗场景自采痛苦真值 |
| L3 | — | 公开数据≈随机，**不接入决策**，仅留 API 占位 |

> ⚠️ L1 数字基于公开数据（近场哭声 + ESC-50 干净剪辑），真实家庭场景需经真实录音验证（见 §11）。

## 4. 模型工程

### 4.1 训练
- **L1**：以 YAMNet（AudioSet 预训练，Apache 2.0）为骨干，迁移 "Baby cry/Infant cry/Crying" 相关表征 → 接浅层分类头；ESC-50/AudioSet 提供家庭噪声负样本（注意 ESC-50 为 CC BY-NC，**仅训练实验，不进商用发布模型**，商用版需替换为自采/可商用负样本）。
- **蒸馏**：教师=YAMNet+分类头，学生=<1MB MobileNet 系小网，蒸到端侧可跑。
- **评估**：严格按婴儿 uuid 组切分（`baseline/metrics.py`），低误报召回用保守口径 + 按折 mean±std。**禁止随机切分**（泄漏，见 `leakage_demo.py`）。
- **L2**：疫苗/采足跟血场景自采痛苦哭声（客观真值）+ 等量非痛苦，log-mel + 轻量 CNN；目标 AUC≥0.90。

### 4.2 导出与跨端一致性
| 平台 | 链路 | 备注 |
|---|---|---|
| iOS | TF/Keras → `coremltools` → `.mlpackage` | 走 ANE/GPU/CPU；量化(fp16/int8)压体积 |
| Android | TF → TFLite/LiteRT `.tflite` | NNAPI/GPU delegate；int8 量化 |
| 跨端 | 同一训练产物分别导出 | **前处理常量与归一化必须一致**；用同一组测试音频校验两端输出差异 < 容差 |

- 建一个**黄金测试集**（几十条音频 + 期望分数），CI 中对比 Core ML / LiteRT / 训练端三方输出，防止导出漂移。

### 4.3 推理运行时
- 抽象 `CryDetector` 接口（`predict(logmel) -> {cry_prob, pain_prob}`），iOS/Android 各自实现，上层决策状态机跨端共用同一套逻辑（可用 Kotlin Multiplatform / C++ 核共享，或各端原生但严格对齐规格）。

### 4.4 OTA 模型下发
- 模型版本化（语义版本 + 哈希），随 App 内置一份，云端可下发新权重（路线 B 蒸馏产物）。
- **训练在云、推理永远在端**，不破坏隐私承诺。下发只是换权重文件，不改变"音频不出端"。

## 5. 远期可选：被动夜间监护（双端，非 MVP）

> 以下整章仅当后续要做"分房睡自动告警"时启用。MVP 主动式单手机不涉及——列在此处仅为架构完整性。被动监护需引入：常开能量 VAD + 三级漏斗(VAD→L1→L2)状态机(`IDLE→SOUND_EVENT→CRYING→ESCALATE`，含去抖/持续哭升级)，监护端(旧手机插电常驻)前台运行，配合下述双端通信。受 iOS 后台限制约束，独立里程碑评估。

### 5.1 配对
- 接收端出示二维码 / 同账号登录 → 监护端扫码建立配对关系（设备公钥交换）。
- 配对信息本地保存；多接收端可订阅同一监护端。

### 5.2 局域网直连（主路径）
- 发现：mDNS/Bonjour（`_babysense._tcp`）。
- 传输：WebRTC DataChannel（或 TLS 长连）传**事件信号**；实时音频流（可选"听一听"功能）走 SRTP，仅用户主动点击时建立、不录制不上云。

### 5.3 弱网/跨网兜底
- 局域网不可达 → 云信令中转 + 系统推送（APNs / FCM）。
- 推送 payload **只含事件元信息**（"检测到哭声/痛苦哭声 + 时间"），**绝不含音频**。
- 推送失败本地重试 + 升级（响铃/震动）。

### 5.4 事件协议（示意）
```json
{ "type": "cry_event", "monitor_id": "...", "ts": 1730000000,
  "duration_s": 18, "level": "pain|normal",
  "cry_prob": 0.97, "pain_prob": 0.81, "model_ver": "l1-1.2.0" }
```

## 6. 数据闭环与回传

对应 PRD §6.4，工程实现：

### 6.1 反馈标注（闭环起点，MVP 核心）
- 一次录音判断后，App 推一张卡片："这次是什么？"（喂奶解决/哄睡/换尿布/抱起/送医/其他）。
- 记录 `{record_id, 用户标签, 解决方式, 时间}` → 本地；这是**行为验证标注**（"喂奶后停哭"≈饿、"送医/很痛苦"→L2 正样本），比人工听音更接近真值。**这是攒 L2/L3 数据的关键入口。**

### 6.2 方案 A — 片段捐赠（MVP 首选）
- 触发：用户在 F10 反馈后，弹**一次性授权**"捐赠这段哭声帮助改进？"。
- 内容：从监护端环形缓冲取对应 10s → Opus 压缩（≈20–30KB）→ 仅 WiFi 上传 → 云侧入数据湖，与标签关联。
- 法律：单独同意，明示用途；可随时撤回。

### 6.3 方案 C — 端上个性化（与 A 并行，零上传）
- iOS：Core ML `MLUpdateTask`；Android：LiteRT 端上训练。
- 用本机反馈微调**分类头最后一层**，做"我家宝宝"个性化（PRD F11），完全不传数据。

### 6.4 云侧（仅处理已授权捐赠数据）
- 数据湖（境内）→ 标注管理 → 周期训练/蒸馏 → 黄金集回归 → OTA 下发。
- 捐赠数据脱敏：去除可识别背景人声（参考 CryCeleb 做法）。

## 7. 本地存储与数据模型

- **不存原始音频**（除非用户主动捐赠那一刻的临时缓冲）。
- 本地库（SQLite/GRDB/Room）只存记录元数据：
  - `cry_record(id, ts, duration_s, cry_prob, pain_prob?, features_json, model_ver)`（pain_prob 在 L2 上线前为空）
  - `feedback(record_id, label, resolution, ts)`
  - `donation(record_id, status, uploaded_ts)`（捐赠状态）
- 趋势报告 = 对元数据做时段/时长/频次统计，纯本地，不做发育评价。

## 8. 隐私、权限与合规（工程实现）

| 项 | 实现 |
|---|---|
| 麦克风权限 | iOS `NSMicrophoneUsageDescription` 写清"仅录音时本机检测哭声，不上传"；Android RECORD_AUDIO（前台录音，无需常驻 FGS） |
| 录音状态可见 | 录音时 iOS 系统橙点 + App 内"录音中"动效；录完即停（主动式，无后台常驻监听） |
| 零上传默认 | 无任何后台音频上传通道；捐赠走独立、可审计的授权流程 |
| 儿童敏感信息 | 捐赠单独同意 + 监护人确认 + 境内存储；隐私清单(iOS PrivacyManifest)如实声明 |
| 医疗红线 | 文案禁用"诊断/病理/筛查"，禁用词表进 CI；异常仅提示"建议咨询医生" |

## 9. 性能预算（主动式单手机）

| 阶段 | 频率 | 成本 |
|---|---|---|
| 录音采集 | 用户触发，单次 10–20s | 前台短时，无常驻开销 |

## 11. 测试与验证

| 层 | 测试 | 闸门 |
|---|---|---|
| L1 模型(离线) | 按婴儿组切分 CV，AUC + 召回@FPR(mean±std) | 已过（公开数据） |

| 端到端 | 真机录音→结果 ≤3s | MVP 验收 |
| 隐私 | 抓包确认无音频外传；禁用词 CI | 上线必过 |

## 12. 技术风险与未决项（open questions）

| # | 问题 | 现状/方向 |
|---|---|---|
| 1 | **L2"要不要紧"无数据、未验证** | 最大风险；需疫苗场景自采痛苦真值；AUC≥0.90 才上；v1 先不承诺 |
| 2 | 真实远场手机麦与近场训练数据的域差 | 高；需远场重录/混响增广 + 真实录音验证 |
| 3 | Core ML vs LiteRT 数值一致性 | 黄金集回归把关；必要时统一量化策略 |
| 4 | YAMNet+头合并导出（vs 分两段） | M1 验证合并模型在 CoreML/LiteRT 的可行性与体积 |
| 5 | 端上个性化(方案C)收益与稳定性 | 先小流量灰度，量化提升后再放量 |
| 6 | 商用模型的负样本 license | ESC-50 是 NC，发布前替换为自采/可商用负样本 |
| 7 | 主动式留存（用完即走） | 记录/趋势/个性化增强黏性；轻召回 |
| — | （远期）iOS 后台回收 / WebRTC 穿透 | 仅被动监护模式相关，MVP 不涉及 |

## 13. 里程碑技术拆解（对齐 PRD §8）

| 阶段 | 技术交付 |
|---|---|
| M1 端侧 L1 | YAMNet+头合并导 CoreML/LiteRT；两端跑通"录一段→确认哭声"；黄金集一致性；真机延迟 |
| M2 v1 MVP | 主动录音+L1确认+哭声特征+记录趋势+**反馈闭环**+上下文建议+捐赠上传；10户内测；数据飞轮启动 |
| M2.5 痛苦数据采集 | 疫苗场景自采痛苦真值 + v1 反馈累积；攒 L2 训练集（并行） |
| M3 L2 紧急度 | L2 模型(自采)；AUC≥0.90 才上"要不要紧"；真实场景验证 |
| M4 个性化+意图评审 | 方案C端上个性化灰度；意图 macro-F1≥0.55 才评审 |
| M5（可选）被动监护 | 三级漏斗+双端+真实夜噪闸门，远期独立评估 |
