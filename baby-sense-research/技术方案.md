# 婴儿哭声感知 App — 技术方案（TDD）

> 版本 v0.1 · 2026-06-10 · 状态：草案
> 配套文档：产品侧 [`婴儿哭声感知-方案与PRD.md`](婴儿哭声感知-方案与PRD.md) · 实测 [`baseline/实验结果.md`](baseline/实验结果.md) · 数据 [`数据清单.md`](数据清单.md)
> 本文只讲"怎么实现"。能力边界与产品决策以 PRD 为准：**MVP = L1 哭声检测 + L2 痛苦分级 + 隐私端侧 + 双端监护；L3 意图识别后置。**

---

## 1. 设计目标与约束

### 1.1 工程目标
- 纯 App（iOS + Android），**端侧推理**，音频不出设备。
- 哭声检测低延迟（≤3s）、低误报（夜间每晚误报可控）。
- 监护端长时运行稳定（插电常驻），接收端及时收告警（≤5s）。
- 一套训练产物导出双端，**iOS/Android 检测结果一致**。
- 内置反馈→标注→回传闭环，为后期 L2/L3 攒自采数据。

### 1.2 硬约束（决定架构）
| 约束 | 来源 | 架构后果 |
|---|---|---|
| iOS 后台麦克风受限、系统可能回收 | 平台 | 采用**双端模式**，监护端前台插电常驻；不与后台限制对抗 |
| 音频零上云（隐私承诺） | PRD 原则 | 推理全在端；跨端只传"哭声事件"信号，捐赠片段需单独授权 |
| 儿童音频=敏感个人信息 | 个保法 | 默认不上传；捐赠走单独同意 + 境内存储 |
| L3 公开数据不可行（实测） | 实验结论 | 检测引擎只接 L1/L2；L3 预留接口但不接入决策 |

### 1.3 非功能指标（端侧）
| 项 | 目标 |
|---|---|
| 检测端到端延迟 | ≤3s（哭声起始→本机判定） |
| 跨端推送延迟 | ≤5s |
| 监护端 CPU 占用 | 常态 <10%（常开层极轻，仅事件触发后跑模型） |
| 模型体积 | L1 蒸馏后 <1MB，L2 <2MB |
| 误报 | 见 M1.5 真实夜噪闸门（每晚误报次数为准） |

## 2. 系统总体架构

```
┌─────────────── 监护端 (闲置旧手机，插电，前台常驻) ───────────────┐
│  麦克风 → 音频采集环形缓冲(16kHz mono)                              │
│     → [级联1] 能量VAD / 声音事件门控   (常开, 极轻)                  │
│     → [级联2] L1 哭声检测 (Core ML/LiteRT)  (有声音事件才跑)         │
│     → [级联3] L2 痛苦分级 (Core ML/LiteRT)  (确认是哭声才跑)         │
│     → 决策状态机(去抖/持续哭升级) → 哭声事件                         │
│            │ 本地日志(仅元数据)         │ 滚动缓冲(10s, 仅内存)      │
└────────────┼───────────────────────────┼───────────────────────────┘
             │ 事件信号(无音频)           │ 仅"反馈+授权"后→捐赠片段
             ▼                            ▼
   ┌─ 局域网直连(mDNS+WebRTC) ─┐   ┌──── 云(可选) ────┐
   │  弱网/跨网回退: 云信令+推送 │   │ 信令中转/推送      │
   └────────────┬───────────────┘   │ 捐赠片段入湖+标注   │
                ▼                    │ 训练/蒸馏→OTA模型  │
┌──────── 接收端 (父母主力手机) ────────┐ └─────────────────┘
│  告警通知 / 哭声日志 / 趋势报告        │
│  反馈标注(F10) / 个性化设置            │
└───────────────────────────────────────┘
```

要点：
- **音频只在监护端内存流转**，不落盘、不传输。跨端传的是"事件信号"（时间戳+时长+类型+概率），不是声音。
- 云是**可选**的：局域网直连为主，云仅做弱网信令兜底、推送、以及（用户授权的）捐赠数据汇聚与模型训练下发。
- 单机模式：白天陪护可只用监护端（检测+本机提示），不依赖接收端/云。

## 3. 端侧检测引擎（核心）

### 3.1 音频采集
| 平台 | API | 配置 |
|---|---|---|
| iOS | AVAudioEngine + installTap | 16kHz, mono, Float32；`audio` 后台模式；AVAudioSession `.record`，处理中断/路由变化 |
| Android | AudioRecord（或 Oboe） | 16kHz, mono, PCM16；前台服务(FGS, microphone 类型) + 常驻通知 |

- 统一重采样到 **16kHz mono**（与训练一致）。
- **环形缓冲** 保留最近 ~12s，供事件触发后回取 10s 窗口做分类与（授权后）捐赠。

### 3.2 前处理（与训练严格一致）
- 帧：25ms 窗 / 10ms 跳（win=400, hop=160 @16k）。
- 特征：log-mel（YAMNet 输入规格：64 mel, 0.96s patch）。**特征实现跨端与训练端逐位对齐**（同一套常量），否则端侧精度塌方。
- baseline 已用 scipy 复现 mel（`baseline/features.py`），端侧用 Accelerate(iOS)/ndk 或直接走 YAMNet 自带前端。

### 3.3 三级漏斗 + 状态机
```
IDLE ──(能量超阈, VAD命中)──► SOUND_EVENT
SOUND_EVENT ──L1(cry_prob>τ1)──► CRYING ──┐
            └─(否)─► IDLE                  │
CRYING ──L2(pain_prob)──► 决策(普通/痛苦)   │
CRYING ──(持续>N分钟)──► ESCALATE ──────────┘
CRYING ──(连续静音>M秒)──► IDLE (事件结束, 落日志)
```
- **级联唤醒**省功耗：VAD 常开极轻；L1 仅在有声音事件时跑；L2 仅在确认哭声后跑。
- **去抖**：cry_prob 需在滑窗内连续 K 帧超阈才进 CRYING，避免单帧抖动误报（直接对应夜间低误报目标）。
- **灵敏度档位**：暴露 τ1 档位（高灵敏/标准/省心），对应 ROC 上不同工作点。L2 阈值独立配置。
- 痛苦判定参考声学特征（高音调、长时长、短间歇），与 L2 模型概率融合。

### 3.4 模型现状（实测，公开数据）
| 层 | 方案 | 实测 |
|---|---|---|
| L1 | YAMNet 迁移 + 蒸馏小模型 | AUC 0.999、召回 1.000±0.000 @5%误报；零样本即 0.986 |
| L2 | log-mel + 轻量 CNN | 待自采痛苦数据（疫苗场景客观真值） |
| L3 | — | 公开数据≈随机，**不接入决策**，仅留 API 占位 |

> ⚠️ L1 数字基于公开数据（近场哭声 + ESC-50 干净剪辑），真实家庭场景需经 M1.5 闸门（见 §11）。

## 4. 模型工程

### 4.1 训练
- **L1**：以 YAMNet（AudioSet 预训练，Apache 2.0）为骨干，迁移 "Baby cry/Infant cry/Crying" 相关表征 → 接浅层分类头；ESC-50/AudioSet 提供家庭噪声负样本（注意 ESC-50 为 CC BY-NC，**仅训练实验，不进商用发布模型**，商用版需替换为自采/可商用负样本）。
- **蒸馏**：教师=YAMNet+分类头，学生=<1MB MobileNet 系小网，蒸到端侧可跑。
- **评估**：严格按婴儿 uuid 组切分（`baseline/metrics.py`），低误报召回用保守口径 + 按折 mean±std。**禁止随机切分**（泄漏，见 `leakage_demo.py`）。
- **L2**：疫苗/采足跟血场景自采痛苦哭声（客观真值）+ 等量非痛苦，log-mel + 轻量 CNN；目标 AUC≥0.90。

### 4.2 导出与跨端一致性
| 平台 | 链路 | 备注 |
|---|---|---|
| iOS | TF/Keras → `coremltools` → `.mlpackage` | 走 ANE/GPU/CPU；量化(fp16/int8)压体积 |
| Android | TF → TFLite/LiteRT `.tflite` | NNAPI/GPU delegate；int8 量化 |
| 跨端 | 同一训练产物分别导出 | **前处理常量与归一化必须一致**；用同一组测试音频校验两端输出差异 < 容差 |

- 建一个**黄金测试集**（几十条音频 + 期望分数），CI 中对比 Core ML / LiteRT / 训练端三方输出，防止导出漂移。

### 4.3 推理运行时
- 抽象 `CryDetector` 接口（`predict(logmel) -> {cry_prob, pain_prob}`），iOS/Android 各自实现，上层决策状态机跨端共用同一套逻辑（可用 Kotlin Multiplatform / C++ 核共享，或各端原生但严格对齐规格）。

### 4.4 OTA 模型下发
- 模型版本化（语义版本 + 哈希），随 App 内置一份，云端可下发新权重（路线 B 蒸馏产物）。
- **训练在云、推理永远在端**，不破坏隐私承诺。下发只是换权重文件，不改变"音频不出端"。

## 5. 双端通信

### 5.1 配对
- 接收端出示二维码 / 同账号登录 → 监护端扫码建立配对关系（设备公钥交换）。
- 配对信息本地保存；多接收端可订阅同一监护端。

### 5.2 局域网直连（主路径）
- 发现：mDNS/Bonjour（`_babysense._tcp`）。
- 传输：WebRTC DataChannel（或 TLS 长连）传**事件信号**；实时音频流（可选"听一听"功能）走 SRTP，仅用户主动点击时建立、不录制不上云。

### 5.3 弱网/跨网兜底
- 局域网不可达 → 云信令中转 + 系统推送（APNs / FCM）。
- 推送 payload **只含事件元信息**（"检测到哭声/痛苦哭声 + 时间"），**绝不含音频**。
- 推送失败本地重试 + 升级（响铃/震动）。

### 5.4 事件协议（示意）
```json
{ "type": "cry_event", "monitor_id": "...", "ts": 1730000000,
  "duration_s": 18, "level": "pain|normal",
  "cry_prob": 0.97, "pain_prob": 0.81, "model_ver": "l1-1.2.0" }
```

## 6. 数据闭环与回传

对应 PRD §6.4，工程实现：

### 6.1 反馈标注（F10，闭环起点）
- 一次告警结束后，接收端推一张卡片："这次是什么？"（喂奶解决/哄睡/换尿布/抱起/其他）。
- 记录 `{event_id, 用户标签, 解决方式, 时间}` → 本地；这是**行为验证标注**（"喂奶后停哭"≈饿），比人工听音更接近真值。

### 6.2 方案 A — 片段捐赠（MVP 首选）
- 触发：用户在 F10 反馈后，弹**一次性授权**"捐赠这段哭声帮助改进？"。
- 内容：从监护端环形缓冲取对应 10s → Opus 压缩（≈20–30KB）→ 仅 WiFi 上传 → 云侧入数据湖，与标签关联。
- 法律：单独同意，明示用途；可随时撤回。

### 6.3 方案 C — 端上个性化（与 A 并行，零上传）
- iOS：Core ML `MLUpdateTask`；Android：LiteRT 端上训练。
- 用本机反馈微调**分类头最后一层**，做"我家宝宝"个性化（PRD F11），完全不传数据。

### 6.4 云侧（仅处理已授权捐赠数据）
- 数据湖（境内）→ 标注管理 → 周期训练/蒸馏 → 黄金集回归 → OTA 下发。
- 捐赠数据脱敏：去除可识别背景人声（参考 CryCeleb 做法）。

## 7. 本地存储与数据模型

- **不存原始音频**（除非用户主动捐赠那一刻的临时缓冲）。
- 本地库（SQLite/GRDB/Room）只存事件元数据：
  - `cry_event(id, start_ts, duration_s, level, cry_prob, pain_prob, model_ver)`
  - `feedback(event_id, label, resolution, ts)`
  - `donation(event_id, status, uploaded_ts)`（捐赠状态）
- 趋势报告（F12）= 对元数据做时段/时长统计，纯本地，不做发育评价。

## 8. 隐私、权限与合规（工程实现）

| 项 | 实现 |
|---|---|
| 麦克风权限 | iOS `NSMicrophoneUsageDescription` 写清"仅本机检测哭声，不上传"；Android RECORD_AUDIO + 前台服务 |
| 录音状态可见 | iOS 系统橙点 + App 内常驻"监听中"；Android 麦克风指示 + 常驻通知；一键停止 |
| 零上传默认 | 无任何后台音频上传通道；捐赠走独立、可审计的授权流程 |
| 儿童敏感信息 | 捐赠单独同意 + 监护人确认 + 境内存储；隐私清单(iOS PrivacyManifest)如实声明 |
| 医疗红线 | 文案禁用"诊断/病理/筛查"，禁用词表进 CI；异常仅提示"建议咨询医生" |

## 9. 性能与功耗预算（监护端）

| 阶段 | 频率 | 成本 |
|---|---|---|
| 能量VAD | 每帧/常开 | 极低（简单能量+过零率） |
| L1 推理 | 仅声音事件时 | 小模型，单次几 ms（ANE/NNAPI） |
| L2 推理 | 仅确认哭声后 | 偶发，可忽略 |
| 录音采集 | 常开 | 主要耗电项 → 要求插电；优化缓冲与唤醒策略 |

- 目标：插电常驻无系统回收；电池态仅作短时/前台兜底。

## 10. 工程结构与模块划分

```
共享(规格对齐):  特征前处理常量 / 决策状态机逻辑 / 事件协议 / 阈值配置
iOS:   AudioCapture(AVAudioEngine) · FeatureExtractor(Accelerate) ·
       CryDetector(CoreML) · DecisionEngine · PeerLink(WebRTC) · Store(GRDB)
Android: AudioCapture(AudioRecord/Oboe) · FeatureExtractor ·
       CryDetector(LiteRT) · DecisionEngine · PeerLink(WebRTC) · Store(Room)
云(可选): Signaling · Push · DonationIngest · LabelStore · TrainPipeline · OTA
训练(本仓 baseline/ 演进): 数据准备 · YAMNet迁移/蒸馏 · 导出 · 黄金集回归
```

## 11. 测试与验证

| 层 | 测试 | 闸门 |
|---|---|---|
| 模型(离线) | 按婴儿组切分 CV，AUC + 召回@FPR(mean±std) | L1 已过（公开数据） |
| **真实夜噪(M1.5)** | 多户真实夜间录音 + 难负样本(电视/人声/宠物/白噪声) + **连续流"每晚误报次数"** | **未过 → 不进 MVP、不宣称真实可用** |
| 导出一致性 | 黄金集三方(训练/CoreML/LiteRT)输出差 < 容差 | CI 必过 |
| 端到端 | 真机延迟≤3s、推送≤5s、监护端长跑稳定性 | MVP 验收 |
| 隐私 | 抓包确认无音频外传；禁用词 CI | 上线必过 |

详见 [`baseline/实验结果.md`](baseline/实验结果.md) 的「尚未验证」清单。

## 12. 技术风险与未决项（open questions）

| # | 问题 | 现状/方向 |
|---|---|---|
| 1 | 真实远场手机麦与近场训练数据的域差 | 高风险；需远场重录/混响增广，M1.5 验证 |
| 2 | 连续流误报（片段级 FPR ≠ 每晚误报次数） | 改用流式评估指标；去抖+灵敏度档位缓解 |
| 3 | Core ML vs LiteRT 数值一致性 | 黄金集回归把关；必要时统一量化策略 |
| 4 | iOS 长时后台被回收 | 双端+插电+前台规避；监控存活并自恢复 |
| 5 | WebRTC 跨网穿透成功率 | 云信令兜底；评估 TURN 成本 |
| 6 | 端上个性化(方案C)收益与稳定性 | 先小流量灰度，量化提升后再放量 |
| 7 | 商用模型的负样本 license | ESC-50 是 NC，发布前替换为自采/可商用负样本 |

## 13. 里程碑技术拆解（对齐 PRD §8）

| 阶段 | 技术交付 |
|---|---|
| M1 端侧 L1 demo | YAMNet→蒸馏→CoreML/LiteRT；两端跑通检测；黄金集一致性；真机延迟/误报初测 |
| **M1.5 真实夜噪闸门** | 采集真实夜噪+难负样本集；流式评估；调阈值/去抖；过闸才进 MVP |
| M2 MVP | 双端配对+局域网直连+云推送兜底；决策状态机；日志/麦克风控制；10户内测 |
| M3 紧急度分级 | L2 痛苦模型(自采)；分级告警；上线 F10 反馈闭环+方案A捐赠开始攒数据 |
| M4 意图卡片 | 自采数据达量且离线 macro-F1≥0.55 才接入 L3；方案C端上个性化灰度 |
