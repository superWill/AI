# v1 页面流原型（完整闭环）

> 2026-06-10 · 配套 PRD v0.5 / [`闭环与建议引擎设计.md`](闭环与建议引擎设计.md) / [`v1-结果页文案与交互.md`](v1-结果页文案与交互.md)。
> 目的：先把闭环**跑顺**（用户能不能顺手走完），再做档案页(②)和工程(③)。可点击原型已在评审中演示。

## 闭环主干（8 屏）

```
S1 录音首页 → S2 录音中 → S3 分析结果 → S4 上下文 → S5 排查建议
   │(先手动记录,跳过录音/分析)──────────↗
   → S6 已记下(等5min) → S7 追问结果 → S8 宝宝档案(沉淀) ↺ 回 S1
                                          └(更严重/危险症状)→ SE 升级就医
```
顶部阶段标识：`x/6 名称`（1录音 2分析 3上下文 4建议 5追问 6档案），让家长知道在第几步、还剩几步——降焦虑。

| 屏 | 内容 | 关键交互 / 出口 |
|---|---|---|
| S1 录音首页（见 §「首屏定稿」） | 标题"录一小段哭声" + 副标"靠近宝宝，录5–15秒" + 麦克风大按钮+"开始录音" + 隐私弱提示 + "先手动记录"弱按钮 | "开始录音" → S2；**"先手动记录" → S4**（宝宝已停/太吵时不中断闭环） |
| S2 录音中 | 波形动效 + "正在仔细听…" + **方块停止键** | 点停止 → S3 |
| S3 分析结果 | ✓是哭声·清晰 + 强度中等·12s（**强度≠严重**） | "下一步" → S4 |
| S4 上下文 | 距喂奶/状态/伴随症状 等快选（智能默认、可跳过） | 选"危险症状"→ SE；否则 → S5 |
| S5 排查建议 | 2–3 条**按上下文+历史排序**，每条「我先试这个」 | 选动作 → S6（记录 action） |
| S6 已记下 | "去试试「{动作}」，约 5min 后问你结果" | "模拟5min/现在反馈" → S7 |
| S7 追问结果 | 缓解程度：已缓解/有一点/没变化/**更严重** | "更严重"→ SE；否则 → S8（记录 outcome） |
| S8 宝宝档案 | 见下「极简档案入口」 | "再记一次" → S1 |
| SE 升级就医 | 危险/恶化 → 推就医，App 收手，仍记录 | "回首页" → S1 |

## 极简档案入口（S8，本轮只验证"能沉淀成记录"）

只做这一张卡，不做完整趋势页（留给 ②）：
```
本次哭声     强度中等 · 12s · 23:10
上下文       距喂奶>3h · 刚睡醒
处理动作     {action}              ← 来自 S5
结果         {outcome}            ← 来自 S7
下次排序依据  ← 闭环的"学到了什么"
   已缓解/有一点 → "夜里+距喂奶久时，「{action}」往前排"
   没变化       → "「{action}」这次没用 → 下次降权，优先换别的"
```

## 首屏定稿（S1，评审改版）

克制、低压、无"诊断感"——家长已焦虑，界面越稳越好。布局：
```
哭闹排查助手                1/6 录音

         录一小段哭声
       靠近宝宝，录 5–15 秒

        [ 麦克风大按钮 ]
           开始录音

   音频仅在本机分析，默认不上传

          先手动记录
```
5 条要点：① 主按钮用麦克风/"开始录音"，**录音中(S2)才变方块停止**——避免首屏像"停止"；② 标题"录一小段哭声"（动作邀请，不是系统反问）；③ 隐私提示放按钮下、弱化；④ 顶部 `1/6 录音` 明示阶段；⑤ "先手动记录"弱按钮兜底，保闭环不中断。无复杂装饰。

## 状态如何穿过整条流（闭环成立的关键）

`S5 选的动作` 和 `S7 选的结果` 必须一路带到 S8，并写成"下次排序依据"——这正是「建议→动作→结果→下次更准」闭环闭合的证据。原型已用前端 state 演示：选不同结果，S8 的依据文案与 SE 升级分支随之变化。

## 情绪/合规要点（贯穿，见结果页文档）

- S1 共情、S3 强度中性、S6/S7 语气温和、S7 追问可忽略可静默。
- "更严重"或危险症状 → 立即 SE，不再让 App 猜。
- 全程音频不上云；底部常驻"仅供参考，不替代医生"。
