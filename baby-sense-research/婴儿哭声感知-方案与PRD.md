# 婴儿哭声感知 — 技术方案与 PRD

> 版本 v0.2 · 2026-06-10 · 状态：草案（已含自有数据实测验证）
> v0.2 变更：①产品形态从边缘硬件改为 iOS/Android App 端侧推理；②可行性表替换为自有实测数字；③新增 §2.4 实测结论；④L3 意图卡片移出 MVP。

---

## 1. 一句话定位

**本地优先的婴儿声音感知 App（iOS/Android）**：在手机端侧实时检测婴儿哭声、判断紧急程度（痛苦/非痛苦），并以"概率提示"的方式辅助父母判断需求——音频不出手机、不存云端、不承诺"翻译婴语"。

## 2. 背景与调研结论

### 2.1 技术可行性边界（核心认知）

| 能力层级 | 学术/产业现状 | **本项目实测（见 §2.4）** | 可行性 |
|---|---|---|---|
| L1 哭声事件检测（哭没哭） | CNN 类 95%+（CNN-SCNet） | **AUC 0.986，召回@5%误报 0.924** | ✅ 实测可商用 |
| L2 痛苦 vs 非痛苦 | ChatterBaby 痛苦哭声 90.7% | 待自采数据验证 | ✅ 较可靠（需验证） |
| L3 具体意图（饿/困/不适/烦躁） | ChatterBaby 71.5%；论文 ~60% | **三分类 balanced acc 0.290（低于随机），公开数据≈噪声** | ⛔ 公开数据做不到，移出 MVP |
| L4 病理性哭声（窒息/脑损伤/耳聋） | 论文可达 95%（Baby Chillanto） | 不做 | ⛔ 属医疗器械，本产品不做 |

**结论（已被实测修正）：产品地基是 L1（实测可靠）+ L2（赌自采真值）；L3 在公开数据下连方向都看不到，必须等 App 反馈闭环攒够自采数据后才评审上线；L4 明确排除。**

### 2.2 竞品扫描

| 产品 | 形态 | 哭声相关能力 | 弱点 |
|---|---|---|---|
| ChatterBaby (UCLA) | 免费 App | 痛/饿/烦躁三分类，云端推理 | 需手动触发录音，无监护硬件，录音上云 |
| CuboAi Monitor 3 | 摄像头监护器（2.5K） | 哭声/咳嗽检测告警，AI 较快 | 贵（$200+），依赖云，意图分类弱 |
| Nanit | 摄像头监护器 | 睡眠分析为主，哭声告警 | 订阅制，哭声只是附属功能 |
| Dunstan 婴语 | 方法论/课程 | 5 种反射音理论 | 无严格科学验证，非技术产品 |

**机会点：没有一家做"纯本地推理、隐私零上云"的哭声感知——这是边缘 AI 的天然主场，也是国内市场（隐私敏感 + 摄像头焦虑）的差异化卖点。**

### 2.3 可用公开数据集

| 数据集 | 规模 | 标签 | 用途 |
|---|---|---|---|
| [donateacry-corpus](https://github.com/gveres/donateacry-corpus) | 457 条 | 饿/拍嗝/困/腹痛/不适 | L3 意图分类起步（量小、用户自标、噪声大） |
| Baby Chillanto (INAOE, 墨西哥) | 2,268 条 1s 片段 | 窒息/耳聋/饿/正常/痛 | L2 痛苦分类参考（需邮件申请） |
| ICSD (2024, 开源) | 哭声+鼾声事件 | 事件检测 | L1 哭声检测训练 |
| CryCeleb (2023) | 6 千+ 段，786 婴儿 | 说话人(婴儿)身份 | 预训练/嵌入学习，非意图标签 |
| AudioSet (Google) | 海量含 "Baby cry" 类 | 事件级 | L1 预训练（YAMNet 即基于此） |

**数据结论：L1 数据充足；L2/L3 公开数据总量 < 3000 条且标注质量参差——自建数据闭环是中期壁垒，产品设计必须内置"家长反馈标注"机制。**

### 2.4 自有数据实测（2026-06-10，关键决策依据）

用 donateacry(457条/221婴儿) + ESC-50(2000条环境音)，MFCC 特征 + 逻辑回归，**严格按婴儿 ID 组切分**（杜绝同一宝宝哭声跨训练/测试泄漏）。完整报告见 [`baseline/实验结果.md`](baseline/实验结果.md)，可一键复现。

| 实验 | 结果 | 判定 |
|---|---|---|
| A) L1 哭声 vs 环境音 | **AUC 0.986**，召回@1%误报 0.706，**召回@5%误报 0.924** | ✅ 廉价特征已达商用级，换 YAMNet 更高 |
| B) hungry vs rest | AUC **0.479**（≈随机 0.5） | ⛔ 无可分信号 |
| C) hungry/tired/discomfort 三分类 | balanced acc **0.290**（随机=0.333，**低于随机**），模型退化为"全猜饿" | ⛔ 公开数据≈噪声 |
| D) 泄漏对照 | 随机切分 0.379 vs 按婴儿切分 0.290，虚高 **+0.089** | 🔍 文献高分=多数类基线+泄漏+强特征的叠加，非真实可用 |

**这组实测直接锁定三条产品约束：**
1. **L3 意图卡片移出 MVP**——公开数据下连方向都看不到，上线即翻车（F9 改为 P2-后置，待自采数据达标再评审）。
2. **L1 是确定可交付的地基**，L2 是下一个待验证赌注（疫苗场景自采客观真值）。
3. **少数类死结**：discomfort/tired/burping 公开世界各仅 8–27 条，增广救不了"类别样本不存在"，唯一出路是 App 反馈闭环的行为验证标注。

## 3. 用户与场景

**目标用户**：0–12 月龄婴儿的父母/看护人（核心 0–6 月，哭声声学特征最稳定期）。

| 场景 | 用户痛点 | 产品响应 |
|---|---|---|
| S1 夜间分房睡 | 听不到/睡太死，担心错过 | **双端模式**：旧手机放婴儿房当监护端（端侧检测）→ 父母手机收推送（见 §6.3 iOS 后台约束） |
| S2 哭声升级 | 不知道"这次哭是不是不对劲" | 痛苦概率高 → 升级告警（声音特征：高音调、长时长、短间歇） |
| S3 新手父母手足无措 | 不知道先试喂还是先哄睡 | 意图提示卡片（**P2 后置**，实测公开数据不支持，待自采数据达标后上线） |
| S4 看护人交接 | 阿姨/老人带娃，父母想了解白天情况 | 哭声日志/时段统计（仅元数据，无录音） |
| S5 隐私焦虑 | 不想家里有联网摄像头/麦克风传云 | 全端侧推理，音频不出手机；麦克风权限与录音状态在 App 内明确可关 |

## 4. 产品原则（不可妥协）

1. **诚实呈现**：意图分类永远显示概率 + "仅供参考"，永不输出"宝宝饿了"这种断言句式。
2. **隐私零上云**：原始音频不离开设备；可选上传的仅为用户主动捐赠的标注片段（明示授权）。
3. **非医疗**：不做病理判断，UI/文案/商详页不出现"诊断""健康筛查"字样；检测到持续异常只提示"建议咨询医生"。
4. **宁漏勿炸**（告警分级）：L1 检测高召回（漏报哭声不可接受），L3 意图高精确（瞎猜不如不猜——§2.4 实测证实公开数据下瞎猜≈全猜饿，故宁缺勿滥）。

## 5. 功能需求

### P0 — MVP（哭声检测 + 告警）

| ID | 需求 | 验收标准 |
|---|---|---|
| F1 | 实时哭声检测（端侧） | 召回 ≥ 95% @ 误报率 ≤ 5%（实测 MFCC 基线已达召回 0.924@5%，YAMNet 更高）；电视/狗叫/成人说话不触发 |
| F2 | 检测延迟 | 哭声起始到本机提示 ≤ 3s |
| F3 | 跨端推送告警 | 监护端检出 → 父母端收到通知 ≤ 5s（局域网直连优先，弱网回退轻量云推送，仅传"哭声事件"信号不传音频） |
| F4 | 哭声日志 | 时间戳 + 时长 + 强度，存元数据不存音频 |
| F5 | 麦克风状态可控 | App 内一键停止监听；录音中状态常驻可见（遵循 iOS 橙点/Android 麦克风指示规范） |

### P1 — 紧急度分级（痛苦检测）

| ID | 需求 | 验收标准 |
|---|---|---|
| F6 | 痛苦哭声识别 | 痛 vs 非痛 AUC ≥ 0.90（参照 ChatterBaby 基线） |
| F7 | 告警分级 | 普通哭=普通通知；痛苦概率 > 阈值=强提醒（声音+震动+置顶） |
| F8 | 持续哭闹升级 | 连续哭 > N 分钟（可配）自动升级告警 |

### P2 — 数据闭环（先建闭环，意图卡片达标才上）

> ⚠️ §2.4 实测：公开数据无法支撑 L3 意图分类。本阶段先把"反馈→标注→数据"闭环建起来攒自采数据，F9 意图卡片**作为闸门项**，只有离线评估达标（见 §6.5）才解锁上线。

| ID | 需求 | 验收标准 |
|---|---|---|
| F10 | 家长反馈标注（**优先做，闭环起点**） | 一次告警后单击反馈"实际是什么"（喂奶解决/哄睡解决/换尿布解决…）；反馈即标注 |
| F11 | 个性化微调 | 累积 ≥ 200 条本机反馈后端侧增量学习（Core ML MLUpdateTask / LiteRT 端上训练），分类头自适应 |
| F12 | 哭声趋势报告 | 周报：哭闹时段分布、时长趋势（纯统计，不做发育评价） |
| F9 | 意图概率卡片（**闸门解锁**） | 自采数据离线评估 macro-F1 达标后才上线；显示 Top-2 + 概率 + 免责；永不断言 |

### 明确不做（Non-goals）

- 病理/疾病检测（医疗器械红线）
- "婴语翻译机"式断言输出
- 云端音频存储/回放
- 视频能力（v1 纯音频，降低隐私门槛与成本）

## 6. 技术方案

### 6.1 总体架构（三级漏斗，全端侧）

```
手机麦克风 (16kHz mono, AVAudioEngine / AudioRecord)
  → [级联1] 能量VAD/声音事件门控        — 极轻，常开（控制后台耗电）
  → [级联2] 哭声检测小模型 (L1)          — 仅有声音事件时跑
       YAMNet 迁移 + 蒸馏小模型, log-mel
  → [级联3] 痛苦分类 (L2)               — 仅确认是哭声后跑
       10s 窗口, log-mel + 轻量CNN
  → 决策层：分级告警 + 跨端推送 + 日志元数据
       (L3 意图：闭环数据达标后才接入此层)
```

级联设计同时解决三个问题：耗电（常开层最轻，对手机续航关键）、误报（逐级收窄）、隐私（音频只在内存流转，不落盘）。端侧推理：iOS 走 **Core ML**，Android 走 **LiteRT(TFLite)**，模型由同一 YAMNet 迁移训练分别导出。

### 6.2 模型路线

**路线 A（MVP 首选）：经典轻量路线**
- L1：YAMNet（AudioSet 预训练，MobileNet-v1 骨干）取 "Baby cry/Infant cry" 相关类做迁移学习，再蒸馏到 <1MB 小模型；ESC-50/AudioSet 补家庭场景负样本（电视、炒菜、宠物）。**实测 MFCC 基线已达 AUC 0.986，YAMNet 为上界。**
- L2：log-mel + 3–5 层 CNN（参考 SE-ResNet 思路加注意力），自采痛苦数据训练。
- 部署：训练产物经 coremltools 导出 Core ML（iOS）、TFLite 转换导出 LiteRT（Android）；模型小，CPU/ANE/NNAPI 均可，无需服务器推理。

**路线 B（P2 升级）：预训练语音大模型蒸馏**
- 2025 年方向：wav2vec 2.0 / HuBERT / Whisper encoder 的逐层特征对低资源哭声分类显著优于手工特征（Springer 2025、arXiv 2509.02259）。
- 做法：云端用大模型在自建数据上训教师模型 → 蒸馏成端侧学生模型 → OTA 下发新模型权重。**训练在云，推理永远在端**，不破坏隐私承诺。

### 6.3 端侧运行环境与产品形态

纯 App、无专用硬件。核心约束来自 **iOS 后台音频限制**——持续监听需 `audio` 后台模式 + 麦克风常占，状态栏录音指示常亮，整夜运行须插电，且系统可能回收长时间后台。因此监护场景采用业界通行的**双端模式**：

| 角色 | 设备 | 职责 |
|---|---|---|
| 监护端 | 闲置旧手机（放婴儿房，插电） | 前台常驻运行，端侧跑 L1/L2，检出即推送 |
| 接收端 | 父母主力手机 | 收告警通知、看哭声日志、做反馈标注 |

- **配对**：扫码/同账号配对，局域网直连优先（mDNS/WebRTC 数据通道），弱网回退轻量云信令（仅转发"哭声事件"信号，**不经手音频**）。
- **单机模式**：白天陪护场景支持单机前台运行（检测+提示），不依赖双端。
- iOS/Android 共用一套 C++/ONNX 或各自原生（Core ML / LiteRT）推理核，特征提取与决策逻辑跨端一致。

### 6.4 数据策略（中期壁垒）

1. **冷启动**：YAMNet 迁移 + ESC-50/AudioSet 负样本（L1，已验证 AUC 0.986）；donateacry 仅作 L3 天花板参照（实测不可商用，见 §2.4）。
2. **自采**：疫苗接种/采足跟血场景采集痛苦哭声（客观真值，ChatterBaby 同款方法，需伦理授权）；母婴社区招募种子家庭采集日常哭声。
3. **闭环**：F10 家长反馈 = 行为验证标注（"喂奶后停止哭"≈饿），比人工听音标注更接近真值，这是对学术数据集的本质改进。
4. **数据回传方案（App 形态，按成本递增）**：
   - **A 明示授权片段捐赠（MVP 首选）**：哭声事件→内存滚动缓冲留 10s→家长反馈后弹一次性确认→Opus 压缩(10s≈20–30KB)→仅 WiFi 上传。法律最干净（单独同意）、带行为标签、流量可忽略。**反馈即标注，捐赠即回传。**
   - **C 端上个性化零上传（与 A 并行）**：Core ML MLUpdateTask / LiteRT 端上训练，本机反馈微调分类头，解决"我家宝宝"个性化，完全不碰传输。
   - **B 只传特征不传音频（隐私模式选项）**：上传 log-mel/embedding 而非波形；代价是无法人工复核、特征改版历史作废，故作可选不作默认。
   - **D 联邦学习**：进 backlog，DAU 过万再评估（单用户样本少 + 标签噪声，对 MVP 不划算）。

### 6.5 评估指标

| 层 | 指标 | 目标 | 当前实测 |
|---|---|---|---|
| L1 | 召回 @ 误报率 | 召回 ≥0.95 @ FPR≤5%（10h 家庭噪声混音集） | 0.924 @5%（MFCC基线，YAMNet 待确认） |
| L2 | AUC | ≥ 0.90 | 待自采痛苦数据 |
| L3 | 离线 macro-F1（闸门） | ≥ 0.55 才解锁上线（按婴儿组切分） | **0.295（公开数据，未达标，故不上）** |
| 系统 | 端到端延迟 / 监护端续航 | ≤3s / 插电常驻无回收 | — |

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| L3 意图准确率不及预期 | 高（**已实测坐实**） | 已移出 MVP；卖点是 L1+L2 可靠告警+隐私。L3 设离线 macro-F1≥0.55 闸门，未达标不上卡片 |
| **iOS 后台监听受限** | 高 | 双端模式（旧手机插电常驻当监护端）+ 前台运行 + 录音状态常显；不与系统后台限制对抗 |
| 数据不足/标注真值难 | 高 | 行为验证闭环（§6.4.3）+ 回传方案 A/C（§6.4.4）；月龄分桶建模（0–3/3–6/6–12 月声学特征不同） |
| 误报招致用户卸载 | 中 | L1 用家庭噪声负样本库压误报（实测 FPR5% 可用），提供灵敏度档位 |
| 隐私合规（儿童数据） | 中 | 默认零上传架构即最强对策；捐赠单独同意 + 法务评审（个保法：儿童信息按敏感个人信息，需监护人同意、境内存储） |
| 医疗宣称越界 | 中 | 文案白名单制，"病理/诊断/筛查"禁用词表进 CI 检查 |
| 双端配对/弱网推送不稳 | 中 | 局域网直连优先 + 云信令兜底（仅转发事件信号，不经手音频）；推送失败本地重试 |
