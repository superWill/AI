# RK3506 vs GD32F407VET6 Checklist

## Baseline

原方案主控：GD32F407VET6。

需要确认的原系统资源：

- 主频、Flash、SRAM 实际占用。
- UART/SPI/I2C/CAN/ADC/GPIO/PWM/定时器使用情况。
- 二总线时序精度和轮询周期。
- 单回路最大设备数、实际典型设备数、满载响应时间。
- 屏幕分辨率、刷新频率、色深、接口类型。
- 按键矩阵、LED、蜂鸣器、打印机、RTC、存储、主备电采样。
- RS485 主机互联协议和吞吐需求。
- 网关协议、远程平台协议、是否要求 TLS/证书。

## RK3506 Known Advantages

根据 Rockchip 官方公开资料，RK3506 系列提供三核 Cortex-A7、DDR2/DDR3/DDR3L 存储接口，以及 UART、I2C、SPI、CAN、PWM、SARADC、RMII 等外设；公开资料也显示 RK3506 平台有 Cortex-M0 实时核。需要以最终选型芯片和 SDK/TRM 为准。

优势：

- 资源远高于 MCU：适合图形界面、日志、配置、网络服务。
- 外设丰富：UART/RS485、CAN、Ethernet、PWM、ADC 等适合工业控制。
- 可跑 Linux：便于 Web UI、远程升级、日志导出、数据库、设备管理。
- 可做多媒体：适合摄像头/视频联动，但 RK3506 本身不是高算力 AI 芯片。

## Key Risks

| Risk | Why it matters | Mitigation |
| --- | --- | --- |
| Linux 非硬实时 | 二总线轮询、联动输出不能被调度延迟影响 | 使用 M0/外置 MCU/RTOS 负责实时链路 |
| 认证边界变大 | 主控平台变更可能触发重新认证 | 先将 RK3506 作为 HMI/网关，安全控制内核保持稳定 |
| 供电与启动时间 | Linux 启动慢于 MCU，断电恢复路径复杂 | 安全控制器先启动，Linux 后启动 |
| 文件系统损坏 | 异常断电可能破坏日志/配置 | 只读 rootfs + A/B 分区 + 配置校验 + 工厂恢复 |
| HMI 失效 | 消防主机不能因 UI 卡死丢失报警 | 硬件指示灯/蜂鸣器/关键按键独立链路 |
| 视频 AI 资源不足 | RK3506 无法承担复杂视频 AI | 只做轻量辅助或外接 AI 模块/云端辅助，不能进安全链路 |
| 二总线兼容性 | 现有探测器和模块协议可能私有 | 先拿协议/波形/设备清单做兼容性验证 |

## Resource Validation Plan

### Phase 1: Measure Existing MCU Workload

- 导出现有 GD32F407 固件功能清单。
- 统计 Flash/SRAM/堆栈/中断占用。
- 记录二总线波形、帧格式、轮询周期、错误处理。
- 记录 HMI 刷新周期、按键响应、报警响应时间。

### Phase 2: RK3506 Prototype Split

- Linux 侧实现 HMI、点表、日志、远程接口。
- M0 或外置 MCU 侧实现模拟二总线轮询和关键输出。
- 建立 Linux 与实时控制器的 IPC 协议。
- 模拟 256 设备满载、故障、报警风暴、断网、重启。

### Phase 3: Safety and Certification Pre-check

- HMI 崩溃测试：报警和联动是否继续。
- Linux 重启测试：实时控制器是否继续。
- 网关断开测试：本机是否继续。
- 配置损坏测试：是否回退到上一个有效配置。
- 断电恢复测试：主备电、日志、点表是否一致。

## Decision Gate

只有满足以下条件，才能说“RK3506 能支撑替代”：

1. 满载点位下报警响应时间满足目标和标准要求。
2. Linux 卡死/重启不影响报警采集与联动输出。
3. 二总线短路、开路、设备离线、CRC 错误都有确定故障状态。
4. 配置系统可审计、可回滚、可锁定，不会让普通用户破坏联动规则。
5. 产品认证路径清晰，知道哪些变更需要重新认证或差异复测。
