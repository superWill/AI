# Thermal Energy Co-controller Logic

## 1. Definition

热能共控机可以理解为供热换热站或楼宇热力系统中的本地控制核心。它连接传感器、执行器、上位平台和现场设备，负责采集运行数据、判断当前工况、执行供热调节策略，并在异常时进入保护或告警状态。

在系统中，它通常不直接产生热量，而是控制热量如何被换热、输送、分配和稳定运行。

## 2. Business Objective

核心目标是让用户侧供热稳定、节能、安全。

- 稳定：保证二次侧供水温度、回水温度、压力和流量处于目标区间。
- 节能：根据室外温度、时间段、负荷变化动态调节阀门、水泵和补水策略。
- 安全：避免超温、超压、缺水、泵空转、传感器异常等风险。
- 可运维：把关键数据、告警、控制状态上传给平台，支持远程监控和参数配置。

## 3. Controlled Objects

热能共控机通常管理以下对象：

- 换热器：监测一次侧、二次侧供回水温度和换热效果。
- 电动调节阀：调节一次侧热媒流量，控制进入换热器的热量。
- 循环泵：控制二次侧热水循环，可支持工频、变频、启停或轮换。
- 补水泵/补水阀：维持二次侧系统压力。
- 泄压阀/旁通阀：在压力异常或特殊工况下保护系统。
- 传感器：温度、压力、流量、液位、电量、阀位、泵状态等。
- 通信模块：对接平台、触摸屏、PLC、热表或其他现场仪表。

- 二次侧供水温度
- 二次侧回水温度
- 二次侧供水压力
- 二次侧回水压力
- 二次侧流量

- 通信在线状态

- 循环泵启停

- 声光告警或本地告警输出
- 平台数据上报

## 6. Core Control Loops

### 6.1 Supply Temperature Control

目标：让二次侧供水温度接近目标供水温度。

基本逻辑：

1. 根据室外温度、时间段和运行模式计算目标供水温度。
2. 读取二次侧实际供水温度。
3. 计算偏差：目标供水温度 - 实际供水温度。
4. 偏差较大且实际温度偏低时，增大一次侧调节阀开度。
5. 偏差较大且实际温度偏高时，减小一次侧调节阀开度。
6. 偏差进入死区后，保持阀门或小幅修正。

建议控制方式：

- 简单版本：分段比例控制。
- 标准版本：PID 控制调节阀门开度。
- 工程版本：PID + 阀门开度限幅 + 调节速率限制 + 防振荡死区。

### 6.2 Pressure Differential Control

目标：让二次侧供回水压差保持在目标区间，保证末端有足够循环能力。

基本逻辑：

1. 读取二次侧供水压力和回水压力。
2. 计算压差：供水压力 - 回水压力。
3. 压差低于目标时，提高循环泵频率或启动备用泵。
4. 压差高于目标时，降低循环泵频率。
5. 压差异常高时，触发保护或泄压策略。

### 6.3 Return Temperature Optimization

目标：控制回水温度，提升换热效率，避免大流量小温差运行。

基本逻辑：

1. 监测二次侧供回水温差。
2. 温差过小说明循环流量可能偏大或换热不足。
3. 在满足供温的前提下，可适当降低循环泵频率。
4. 若供温不足且温差小，需要检查一次侧热量、阀门开度或换热器效率。

### 6.4 Water Refill Control

目标：保证二次侧系统压力不低于安全下限。

基本逻辑：

1. 读取系统补水压力或二次侧回水压力。
2. 低于补水启动压力时，启动补水泵或打开补水阀。
3. 达到补水停止压力时，停止补水。
4. 如果长时间补水仍无法升压，判断为泄漏或补水故障。
5. 如果压力超过高限，停止补水并触发高压告警。

## 7. Operating Modes

### 7.1 Automatic Mode

系统按目标曲线、传感器数据和控制算法自动运行。

适合正常供热期。

### 7.2 Manual Mode

运维人员本地或远程直接设置阀门开度、泵启停、泵频率等。

手动模式下仍应保留硬保护，如超压、缺水、泵故障联锁。

### 7.3 Remote Mode

平台可以下发目标温度、运行模式、参数和启停指令。

远程指令需要做权限、范围和安全校验，不能绕过现场保护条件。

### 7.4 Local Mode

现场触摸屏或按钮优先控制。

当本地模式启用时，平台只能监控或只能下发非关键参数，具体取决于项目规则。

### 7.5 Emergency Mode

当出现严重异常时，系统进入保护状态。

典型动作包括：

- 关闭或减小一次侧调节阀。
- 停止相关水泵。
- 启动备用泵。
- 打开泄压或旁通设备。
- 锁定告警，等待人工确认。

## 8. Suggested State Machine

```text
Power On
  -> Self Check
  -> Standby
  -> Starting
  -> Running
  -> Adjusting
  -> Alarm
  -> Emergency Stop
  -> Standby
```

### 8.1 Power On

设备上电，初始化 IO、通信、参数、时钟和历史状态。

### 8.2 Self Check

检查传感器、阀门、泵、通信和关键参数是否可用。

若关键点位缺失或超限，进入告警或禁止启动。

### 8.3 Standby

设备待命，保持监测，不主动供热调节。

### 8.4 Starting

按顺序启动必要设备。

推荐顺序：

1. 确认水压正常。
2. 确认阀门处于安全初始开度。
3. 启动循环泵。
4. 等待流量或压差建立。
5. 缓慢打开一次侧调节阀。
6. 进入运行状态。

### 8.5 Running

正常运行，周期性执行采集、计算、控制和上报。

### 8.6 Adjusting

当温度、压力或负荷变化明显时，系统执行调节策略。

调节完成后回到 Running。

### 8.7 Alarm

出现非致命异常，例如传感器漂移、通信中断、温度轻微超限。

系统继续运行或降级运行，同时上报告警。

### 8.8 Emergency Stop

出现严重异常，例如超压、缺水、泵故障、温度严重超限。

系统执行保护动作，等待人工复位或安全条件恢复。

## 9. Main Control Cycle

建议主循环周期按 1 秒到 5 秒执行，关键保护可以更快。

```text
while system_is_on:
    read_sensors()
    validate_sensor_values()
    update_device_status()
    evaluate_alarm_rules()

    if emergency_condition:
        execute_emergency_protection()
        upload_status()
        continue

    if mode == AUTO:
        calculate_target_temperature()
        control_primary_valve()
        control_circulation_pump()
        control_refill()

    if mode == MANUAL:
        execute_manual_commands_with_safety_limit()

    upload_realtime_data()
    store_operation_log()
```

## 10. Key Protection Rules

### 10.1 Over Temperature

触发条件：

- 二次侧供水温度超过高限。
- 一次侧供水温度超过高限。

处理动作：

- 减小或关闭一次侧调节阀。
- 保持循环泵运行一段时间用于散热。
- 上报告警。

### 10.2 Low Pressure

触发条件：

- 二次侧回水压力低于低限。
- 补水后仍无法恢复。

处理动作：

- 启动补水。
- 补水失败时停止循环泵，避免空转。
- 上报告警。

### 10.3 High Pressure

触发条件：

- 二次侧供水压力超过高限。

处理动作：

- 降低循环泵频率。
- 停止补水。
- 必要时打开泄压设备。
- 严重时停机保护。

### 10.4 Pump Fault

触发条件：

- 泵运行反馈异常。
- 变频器故障。
- 电流过载。

处理动作：

- 停止故障泵。
- 启动备用泵，若配置了备用泵。
- 上报告警。

### 10.5 Sensor Fault

触发条件：

- 数据断线。
- 数据超物理范围。
- 短时间跳变过大。
- 多个相关传感器数据矛盾。

处理动作：

- 使用备用测点或保持上一安全输出。
- 降级运行。
- 关键传感器故障时禁止自动调节或停机保护。

## 11. Data Reporting

建议上报数据分为三类：

- 实时数据：温度、压力、流量、阀位、泵频率、运行模式。
- 事件数据：启停、模式切换、参数修改、远程指令。
- 告警数据：告警类型、发生时间、恢复时间、确认状态、处理动作。

## 12. Parameter Configuration

建议支持配置：

- 目标供水温度曲线。
- 室外温度补偿曲线。
- 温度控制死区。
- 阀门最小/最大开度。
- 阀门调节步长或 PID 参数。
- 压差目标值。
- 循环泵最小/最大频率。
- 补水启动压力和停止压力。
- 高低温、高低压告警阈值。
- 通信上报周期。
- 设备启停延时。

## 13. Minimal Embedded Module Split

面向嵌入式实现，可以先拆成以下模块：

- IO 采集模块：读取传感器、DI、AI、通信仪表。
- 数据校验模块：滤波、限幅、断线判断、异常跳变判断。
- 状态机模块：管理启动、运行、告警、急停等状态。
- 控制算法模块：温度控制、压差控制、补水控制。
- 设备驱动模块：阀门、水泵、变频器、继电器输出。
- 参数管理模块：保存阈值、曲线、模式和 PID 参数。
- 通信模块：对接平台、触摸屏、Modbus/485/CAN/以太网等。
- 日志告警模块：记录事件、告警、操作和恢复。
