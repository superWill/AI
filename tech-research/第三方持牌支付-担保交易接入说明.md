# 第三方持牌支付　担保交易接入说明

> **给谁看**：平台、产品、技术、运营、商务
> **目的**：把"什么是第三方持牌担保、钱怎么走、平台/乙方各需要什么条件、怎么接入"一次说清楚
> **一句话定位**：当平台**只想抽 3% 服务费、不碰交易本金，但又要保留"验收前冻结资金"的强担保**时，微信生态内做不到（分账只有弱担保/账期），唯一解是接入**央行持牌的第三方支付公司**，用它的「担保交易 + 资金清算」能力。
> **核实时间**：2026-05-30。持牌机构接入是"一户一议、商务审批"，本文是通用框架，**具体条件以商务对接为准**。
> **配套文档**：《微信分账与服务费收取-角色定义与模式选型》（微信生态内方案）。

---

## 1. 它是什么

### 1.1 定义

第三方持牌支付公司 = 央行颁发《支付业务许可证》的金融机构（连连、易宝、通联、汇付、宝付等）。它们**自身就有支付牌照**，可以合法做代收代付、担保交易、资金清算——**等于一个"小微信支付"**，不在微信支付的规则约束下。

```
央行（监管）── 颁发支付牌照
  ├─ 微信支付（财付通）
  ├─ 支付宝（蚂蚁）
  ├─ 连连支付   ← 候选
  ├─ 易宝支付   ← 候选
  ├─ 通联支付   ← 候选
  └─ …（约 200 家持牌机构）
```

### 1.2 为什么要它（和微信方案的本质区别）

| 维度 | 微信分账 | 第三方持牌担保 |
|---|---|---|
| 钱进谁账户 | 收款商户的微信商户号 | 持牌公司的**银行存管担保账户** |
| 谁做监管 | 微信支付 | 持牌公司（平台发指令）|
| 分配规则 | 微信分账规则（30% 上限、对私禁用）| 持牌公司自有规则（无 30% 限制）|
| 强担保（验收前冻结）| 弱（账期）| ✅ 强 |
| 平台资质 | 需升级微信支付服务商 | **不需要**，签 B2B 合同即可 |
| 涉及"微信分账"吗 | 是 | **否**，完全独立的另一套体系 |

> **关键认知**：这条路**和微信分账没关系**。资金清算走持牌公司自己的系统，绕开微信分账的所有限制。

## 2. 角色定义

| 业务角色 | 在持牌体系里的身份 | 干什么 |
|---|---|---|
| **甲方** | 付款人 | 微信/银行卡付款（微信仅作支付通道）|
| **乙方** | 持牌体系内的**收款账户持有人**（个人钱包 / 商户）| 收款，提现到本人银行卡 |
| **平台** | 持牌公司的 **B2B 客户**（指令发起方）| 发"冻结/放款/分配"指令，抽 3% |
| **持牌公司** | 资金托管 + 清算执行方 | 托管资金、按指令清算、出对账单 |
| **存管银行** | 备付金集中存管 | 钱实际存在银行存管账户，谁都不能挪用 |

> 平台**不是收款主体、不碰本金**，只是"发指令的人"——这正是它既能保留监管、又不构成二清的原因。

---

## 3. 钱怎么走（担保交易资金流）

### 3.1 资金流向（10000 元订单、平台抽 3%）

```
甲方付款 10000
       ↓
   微信支付（仅作支付通道）
       ↓
持牌公司担保账户【冻结】（银行存管）
       ↓ ← 等平台验收指令
   ┌──────────────────┐
   ↓                  ↓
✅ 验收通过        ❌ 验收不通过
   ↓                  ↓
持牌按指令清算    持牌原路退款给甲方
├─ 乙方账户：9700
├─ 平台账户：220   （3% 抽佣 − 通道费）
└─ 持牌服务费：80  （约 0.8%）
```

### 3.2 端到端 7 步

| 步骤 | 谁 | 做什么 |
|---|---|---|
| 1 | 甲方 | 在平台小程序选中乙方、提交订单 |
| 2 | 甲方 | 微信支付 10000 → **进持牌担保账户冻结**（不进平台账户）|
| 3 | 乙方 | 交付成果到平台 |
| 4 | 甲方 | 在平台点"验收通过" |
| 5 | 平台 | 调持牌"释放资金 / 分账"API |
| 6 | 持牌 | 按规则：9700→乙方账户、220→平台账户、80→持牌服务费 |
| 7 | 乙方 | 在持牌体系内提现到本人银行卡 |

### 3.3 平台始终保留监管权

钱在持牌担保账户里冻结，**必须平台触发才能放款**。平台从不持有本金（不二清），但握有"验收前冻结"的抓手——这就是相比"彻底分离"模式的核心优势。

## 4. 接入条件（核心）⭐

持牌机构没有公开标准清单，是商务审批、一户一议。下面是行业通用门槛，按**四个层面**拆。

### 4.1 平台方（你们）接入条件

| 类别 | 具体条件 | 说明 |
|---|---|---|
| **主体资质** | 企业营业执照（通常要求成立满 1 年、注册资本达标、经营范围相关）| 个体户一般不收，要公司主体 |
| **互联网资质** | **ICP 许可证 或 EDI 许可证** | 经营性互联网/在线交易处理，尽调必查 |
| **银行账户** | 对公银行账户 | 结算、对账、保证金 |
| **法人/实控人** | 身份证、征信良好、无重大涉诉 | 反洗钱尽调 |
| **业务合规性** | 商业模式说明 + 资金流向图，证明是**撮合服务、走持牌清算** | 尽调核心：说清钱为何经持牌、平台只抽佣 |
| **技术能力** | 有研发团队对接 API（下单/冻结/释放/分账/对账/退款）| 评估开发量 |

### 4.2 担保交易 / 资金存管 产品的开通条件

持牌公司的担保能力通常打包在"账户系统 / 账户+"产品里（如"连连账户+"：总分账户、出入金、担保支付、资金清分）。

| 条件 | 说明 |
|---|---|
| 签**资金存管 / 托管协议** | 资金进**银行存管的备付金账户**，集中存管，平台账户不碰钱 |
| 开通"担保支付 / 冻结-释放"功能 | 保留监管权的关键模块，**务必确认对方支持** |
| 保证金 / 预存 | 部分公司要，金额看流水与风险评级 |
| 最低流水承诺 | 部分公司有，达不到则费率上浮 |

### 4.3 乙方（个人）在持牌体系开户条件 —— **成败开关** ⚠️

这是商务对接**第一个要问**的问题。

| 项 | 说明 |
|---|---|
| **实名认证** | 个人"四要素"鉴权：身份证 + 本人银行卡 + 手机号 + 人脸 |
| **开虚拟子账户** | 乙方在持牌体系内开个人钱包/子账户，收款先进这里 |
| **提现** | 只能提到**本人同名银行卡** |
| **合规审查点** | "个人持续性、经营性收款"部分机构按经营所得/反洗钱审查，**不一定每家放开** |
| **个税** | 是否代扣代缴 + 出具完税凭证；不提供则叠加灵活用工平台 |

> **关键判断**：跨境/C 端钱包类业务（连连等）通常支持个人实名钱包；但"平台撮合、个人持续经营性收款"是否放开、限额多少，**逐家政策不同，必须商务确认**。这是整个方案能否成立的唯一硬变量。

### 4.4 商务 / 合同 / 成本条件

| 项 | 估算 |
|---|---|
| 接入费 | 0–数万元，可谈 |
| 单笔费率 | 0.7%–1.5%（含支付通道+清算+担保），比微信直连 0.6% 多 0.1%–0.9% |
| 月费/年费 | 部分公司有 |
| 保证金 / 最低流水 | 部分公司有 |
| 合同条款 | 保留**切换条款**（防牌照/系统风险）；同时谈 2–3 家备份 |

> 费率会挤压抽成空间：10000 元订单多付 10–90 元，平台 3% 抽成可能要微调到 3.5%–4%。

## 5. 候选机构

| 公司 | 特点 |
|---|---|
| **连连支付** | 撮合平台经验多、互联网行业熟、账户+体系成熟 |
| **易宝支付** | 老牌行业服务商，分账/担保产品齐 |
| **通联支付** | 银联背景，重合规 |
| **汇付天下** | 港股上市，B2B 经验 |
| **宝付** | 平安系，行业方案多 |

> **建议同时谈 2–3 家**，比报价、比方案、比个人开户政策，并作互为备份。

## 6. 资质门槛对比：比微信收付通低在哪

| 维度 | 微信平台收付通 | 第三方持牌 |
|---|---|---|
| 平台要升级微信服务商 | ✅ 必须 | ❌ 不需要 |
| 每个乙方进微信二级商户 | ✅ 必须，个人进不去 | ❌ 在持牌体系开户即可 |
| 个人乙方收款 | 基本卡死（小微行业/限额）| ⚠️ 需确认，但有可能 |
| 行业类目限制 | 面向实物商品撮合，设计服务受限 | 相对宽松 |
| 接入主导方 | 微信规则 | 商务谈判 |

> 平台侧门槛核心就三样：**企业主体 + ICP/EDI + 能证明业务合规**。不确定性全压在 4.3——**个人乙方能否开经营性收款户**。

## 7. 接入流程（落地步骤）

| 阶段 | 谁 | 做什么 |
|---|---|---|
| 1 商务对接 | 平台商务 | 同时接触 2–3 家，**第一问：个人乙方能否开收款户** |
| 2 尽调 | 持牌 | 收平台资质材料（见 8）、审核商业模式 |
| 3 签约 | 双方 | 签 B2B 合作 + 资金存管/托管协议 |
| 4 开通产品 | 持牌 | 开"账户+/担保支付/资金清分"，配保证金 |
| 5 技术对接 | 平台技术 | 接 API：下单/冻结/释放/分账/对账/退款；联调沙箱 |
| 6 乙方开户 | 平台+乙方 | 乙方实名开虚拟账户，绑定提现卡 |
| 7 试运行 | 双方 | 小额灰度，验证全链路与对账 |
| 8 上线 | 平台 | 切流，运营话术配套 |

---

## 8. 尽调材料清单（对方会要）

营业执照、ICP/EDI 证、对公开户许可、法人身份证、公司章程/股权结构、商业模式说明（含资金流向图）、预计交易流水、技术对接方案。

---

## 9. 待确认清单（行动项）

| 优先级 | 待确认 | 找谁 |
|---|---|---|
| P0 | **个人乙方能否开经营性收款户 + 限额** | 持牌商务 |
| P0 | 是否提供担保支付（冻结-放款）产品 | 持牌商务 |
| P1 | 平台是否已有 EDI / ICP 证书 | 内部 |
| P1 | 费率 / 接入费 / 保证金 / 最低流水 | 同时谈 2–3 家 |
| P1 | 个税是否代扣 + 完税凭证 | 持牌商务 |
| P2 | API 能力与开发量（含对账、退款、回退）| 技术对接 |
| P2 | 切换/退出条款 | 法务 |

---

## 10. 风险与应对

| 风险 | 应对 |
|---|---|
| 持牌机构尽调不通过 | 同时谈 2–3 家备份 |
| 个人乙方收款资质受限 | 商务第一问；不行则叠加灵活用工平台兜底 |
| 持牌机构自身风险（牌照、系统）| 选头部公司，合同留切换条款 |
| 个税处理不到位 | 商务确认；不提供完税凭证则叠加灵活用工 |
| 收款方名称变化引发甲方疑虑 | 运营客服话术解释 |

## 附录 A：术语表

| 术语 | 解释 |
|---|---|
| 持牌支付公司 | 央行发牌、独立运营的第三方支付机构 |
| 担保交易 | 资金先冻结，买方确认后释放给卖方 |
| 资金清算 | 持牌公司按规则把钱分配给多方的核心能力 |
| 备付金集中存管 | 客户资金集中存于银行/央行存管账户，机构不得挪用 |
| 账户+ / 账户系统 | 持牌公司为平台提供的总分账户、出入金、担保、清分一体化能力 |
| 二清 | 二次清算：无证机构代收代付，央行禁止（持牌方案天然规避）|
| EDI 证书 | 在线数据处理与交易处理业务经营许可证 |
| ICP 许可证 | 经营性互联网信息服务许可证 |
| 灵活用工平台 | 持税务委托代征资质的代发公司（个税兜底）|
