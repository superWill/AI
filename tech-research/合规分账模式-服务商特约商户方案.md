# 合规分账模式　服务商 + 特约商户方案

> **给谁看**：平台、产品、技术、运营、商务
> **目的**：把"在微信生态内合法做分账、平台只抽 3% 又不碰钱"这套模式，从原理到落地条件一次讲清
> **一句话结论**：让**乙方当收款主体（特约商户）拿 97%**、**平台当服务商兼分账接收方只抽 3%**。钱进乙方账户、平台不碰本金 → **不构成二清**；只分 3% 给平台（企业）→ **天然避开 30% 上限和对私分账禁用**。唯一前提：**乙方要能进件成特约商户（办个体工商户即可，不必是公司）**。
> **核实时间**：2026-05-30，关键参数以微信支付官方文档为准。

---

## 1. 先讲什么叫"合规" vs "二清"

这是整套模式的地基。

| | 合规 | 二清（违规）|
|---|---|---|
| 钱进谁账户 | **直接进收款方（乙方）账户** | 先进平台账户，再由平台转给乙方 |
| 平台角色 | 只发"分账指令"、抽自己的佣金 | 代收代付（替别人收钱再分发）|
| 是否需牌照 | 不需要（走微信支付的合规产品）| 需要支付牌照，无证即违规 |
| 央行态度 | 允许 | **明令禁止** |

> **合规的核心动作**：平台**永远不让交易本金进自己账户**。钱从甲方直接进乙方的收款账户，平台只是"在旁边按规则抽 3%"。

---

## 2. 角色设定（关键的反转）⭐

很多人第一反应是"平台先收钱再分给乙方"——那正是二清。合规做法要把角色**反过来**：

| 业务角色 | 支付身份 | 资金 | 说明 |
|---|---|---|---|
| **甲方** | 付款人 | 付全款 10000 | 正常微信支付，**无需任何资质** |
| **乙方** | **特约商户**（收款主体）| 拿 9700（97%）| 钱直接进乙方账户 |
| **平台** | **服务商 + 分账接收方** | 抽 300（3%）| 不当收款主体，只代理 + 抽佣 |

**为什么这样设就合规**：
- 钱进的是**乙方**账户，不是平台账户 → 平台不碰本金 → **不二清**。
- 平台作为"分账接收方"只分走 3% → 远小于 30% 上限。
- 分账接收方是**平台（企业）**，不是个人 → 不触发"对私分账禁用"。

> 一句话：**收大头的（乙方）当商户，抽小头的（平台）当接收方**——三条规则全部绕开。

---

## 3. 钱怎么走（资金流）

```
甲方付款 10000
       ↓
进【乙方·特约商户】账户 ── 标记"分账订单"，可分账部分【冻结】
       ↓ 平台（服务商）调分账 API
   ┌──────────────────┐
   ↓                  ↓
分给平台 300（3%）   解冻剩余 9700
（分账接收方）       （结算给乙方）
       ↓                  ↓
   平台账户          乙方银行卡
```

### 生命周期 5 步

| 步骤 | 谁 | 动作 | 要点 |
|---|---|---|---|
| 1 | 甲方 | 支付时打分账标记 | 下单带 `profit_sharing=true`，钱才会冻结成"可分账池" |
| 2 | 平台 | 添加分账接收方 | 把"平台自己"登记为接收方 |
| 3 | 平台 | 发起分账 | 分 300 给平台 |
| 4 | 平台 | 完结/解冻 | 剩余 9700 结算给乙方 |
| 5 | 平台 | 分账回退（按需）| 退款场景追回已分资金 |

> 平台账户**从头到尾不经手 10000**，只收到 300 的分账。这就是"只要 3%、不碰钱"的合规实现。

---

## 4. 为什么它能避开三条规则

| 规则 | 普通理解会踩雷 | 本模式为何不踩 |
|---|---|---|
| **二清禁止** | 平台先收 10000 再分 | 钱直接进乙方账户，平台不碰本金 |
| **30% 分账上限** | 平台收款后要分 97% 给乙方（超 30%）| 反过来，平台只分 3% 给自己 |
| **对私分账禁用（2025-07）** | 分账给个人乙方 | 分账接收方是平台（企业），乙方是"收款方"不是"接收方" |

---

## 5. 落地条件（核心）⭐

### 5.1 平台：成为微信支付服务商

**主体条件**

| 条件 | 要求 |
|---|---|
| 主体类型 | **企业 / 政府机关 / 事业单位 / 社会组织**——⚠️ 个体户、个人不能当服务商 |
| 微信认证 | 企业类型主体 |
| 经营资质 | 营业执照有效、经营范围相关、无重大涉诉 |

**基础注册材料**

| 材料 | 说明 |
|---|---|
| 营业执照 / 登记证书 | 彩色扫描件或照片 |
| 法定代表人证件 | 身份证正反面 |
| 业务联系人 | 姓名、手机、邮箱 |
| 对公银行账户 | 用于账户验证（小额打款）|

> 基础注册审核 1–3 工作日，**一般无保证金**。

**进阶条件（要真正用上分账）**

| 进阶项 | 说明 |
|---|---|
| **ICP 或 EDI 许可证** | 有自营撮合平台 → 经营性互联网，基本绕不开 |
| 开通分账产品 | 商户平台申请，登记平台为分账接收方 |
| 对接特约商户进件 API | 代乙方进件、绑定分账关系 |
| 行业类目合规 | 设计/服务类目需符合行业准入 |

### 5.2 乙方：进件成特约商户（这是分水岭）⚠️

| 乙方主体 | 要营业执照吗 | 能进件吗 |
|---|---|---|
| 企业 | ✅ 公司执照 | ✅ |
| **个体工商户** | ✅ 个体户执照（好办）| ✅ **推荐** |
| 小微商户（纯个人）| ❌ 不用执照 | ⚠️ 能，但**行业受限（设计类多半不支持）+ 限额** |

> **乙方不必是公司，办个体工商户即可**。纯个人只能走小微，会卡在行业和限额——这是整套方案能否成立的关键。

### 5.3 甲方：无需任何资质

甲方只是付款人，正常微信支付，**不进件、不需营业执照、不需商户身份**。

---

## 6. 两个层别混：入驻平台 ≠ 成为商户

| 层面 | 是什么 | 要营业执照吗 |
|---|---|---|
| **业务层：入驻共点平台** | 注册账号、发/接项目 | ❌ 谁都能注册 |
| **支付层：成为特约商户** | 在微信支付里能收款 | ✅ 仅收款方（乙方）需要 |

> 入驻平台只是用产品，和执照无关；要执照的是"乙方在微信支付里收款"这一步，且个体户就够。

---

## 7. 端到端流程（落地步骤）

| 阶段 | 谁 | 做什么 |
|---|---|---|
| 1 | 平台 | 以公司主体注册微信支付服务商 |
| 2 | 平台 | 补 ICP/EDI，开通分账产品 |
| 3 | 乙方 | 办个体工商户（或用已有企业资质）|
| 4 | 平台 | 代乙方进件成特约商户，绑定分账关系 |
| 5 | 甲方 | 下单付款 10000 → 进乙方账户、冻结 |
| 6 | 乙方 | 交付，平台验收 |
| 7 | 平台 | 调分账 API：300→平台、解冻 9700→乙方 |
| 8 | 乙方 | 9700 结算到银行卡 |

## 8. 决策点与待确认

### 8.1 必须先拍板

| # | 决策 | 影响 |
|---|---|---|
| D1 | **能否要求乙方办个体工商户？** | 能 → 本模式直接成立、最省事；不能 → 卡在小微，转第三方持牌 |
| D2 | 平台是否已是公司主体 + 有 ICP/EDI？ | 缺则先补 |

### 8.2 待确认清单

| 优先级 | 待确认 | 找谁 |
|---|---|---|
| P0 | 个人乙方能否进件小微（行业 / 限额）| 微信支付 |
| P0 | 乙方群体里有照 vs 纯个人占比 | 内部业务 |
| P1 | 平台 ICP/EDI 是否齐备 | 内部 |
| P1 | 设计/服务行业类目准入 | 微信支付 |
| P2 | 分账 API + 进件 API 开发量 | 技术 |

### 8.3 运营要准备

- **乙方话术**：引导办个体工商户，强调"合法收入 + 完税凭证"对贷款、报税有用。
- **过渡期**：方案上线前，对大额订单做业务侧规避（限单笔金额 / 分阶段交付）。

---

## 9. 局限与边界

| 局限 | 说明 |
|---|---|
| 担保偏弱 | 分账是"先结算给乙方、再抽佣"模式，强担保（验收前长期冻结）能力有限，靠账期 |
| 个人乙方进不来 | 纯个人只能小微，行业/限额受限 → 需转第三方持牌（另见配套文档）|
| 平台门槛 | 必须公司 + 服务商 + ICP/EDI |

> 若乙方以纯个人为主、或需要强担保，本模式不适用，见配套文档《第三方持牌支付-担保交易接入说明》。

## 附录 A：术语表

| 术语 | 解释 |
|---|---|
| 服务商 | 微信认证代理，可代接入、代发起分账、抽佣 |
| 特约商户（二级商户）| 通过服务商间接接入的收款主体 |
| 分账方 / 分账接收方 | 发起分账的一方 / 被分钱的一方 |
| 分账订单 | 支付时打了分账标记、资金会被冻结的订单 |
| 二清 | 二次清算：无证机构代收代付，央行禁止 |
| 小微商户 | 无营业执照的个人收款主体，行业与限额受限 |
| ICP 许可证 | 经营性互联网信息服务许可证 |
| EDI 证书 | 在线数据处理与交易处理业务经营许可证 |
