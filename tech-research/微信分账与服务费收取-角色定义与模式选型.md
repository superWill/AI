# 微信分账 / 服务费收取　角色定义与模式选型

> **给谁看**：平台、产品、技术、运营
> **目的**：统一术语，把"谁是谁、钱怎么走、平台只想抽 3% 该选哪条路"一次说清楚
> **一句话结论**：本文聚焦**微信生态内**的两条路——**A 服务商佣金**（钱进乙方特约商户、平台抽 3%）和 **C 彻底分离**（甲方直付乙方、平台单收撮合服务费）。两条都让平台**不碰交易本金**，区别在要不要"验收前冻结"的担保（A 弱担保/账期、C 无担保）。若要**强担保又不碰钱**，需走微信生态外的第三方持牌方案，详见配套文档《第三方持牌支付-担保交易接入说明》。最终都卡在同一前提：**乙方是有照主体还是纯个人**。
> **核实时间**：2026-05-30，关键参数以微信支付官方文档 + 商务对接为准。

## 1. 角色定义（全文统一口径）⭐

这是最容易混的地方。**先把两套角色分开**：一套是我们业务上的角色，一套是微信支付体系里的技术角色。**同一个实体，在两套里叫法不同。**

### 1.1 业务角色（我们平时说的）

| 业务角色 | 定义 | 在交易里干什么 |
|---|---|---|
| **甲方** | 项目发起方 / 买方 | 出钱，发起项目，验收 |
| **乙方** | 承接项目方 / 卖方 | 干活、交付，收钱（拿大头 ~97%）|
| **平台** | 我们（撮合方）| 撮合甲乙、提供担保与服务，抽 **3% 服务费** |

### 1.2 微信支付角色（接入时的技术身份）

| 支付角色 | 定义 | 通俗理解 |
|---|---|---|
| **普通商户** | 直接和微信支付签约的收款主体 | "我自己收钱" |
| **服务商**（合作伙伴）| 微信认证的代理，帮别人接入、可代发起分账、可抽佣 | "我帮别人收钱并抽成" |
| **特约商户**（二级商户）| 通过服务商间接接入的收款主体 | "我挂在服务商下面收钱" |
| **分账方** | 发起分账的一方 | "我决定这笔钱怎么分" |
| **分账接收方** | 被分走一部分钱的对象（可为商户或个人）| "我等着分一杯羹" |

### 1.3 映射关系（关键！同一实体的两个身份）

> ⚠️ **这张表是全文核心**：业务角色怎么对应到支付角色，决定了钱怎么走、卡不卡规则。

| 业务角色 | 在"服务商+特约商户"模式里的支付身份 | 说明 |
|---|---|---|
| **平台** | = **服务商** + **分账接收方**（抽 3%）| 平台不当收款主体，只做代理 + 抽佣 |
| **乙方** | = **特约商户**（收款主体，拿 97%）| 钱进乙方账户，平台从中抽 3% |
| **甲方** | = 付款人（无特殊支付身份）| 正常微信支付 |

**这个映射的妙处**：因为钱进的是**乙方（特约商户）**账户、平台只抽 3%，所以：
- ✅ 不触发"分账 30% 上限"（平台只分走 3%，远小于 30%）
- ✅ 不触发"对私分账禁用"（分账接收方是平台＝企业，不是个人）
- ✅ 平台账户**全程不碰交易本金** → 不构成二清

**唯一的代价/前提**：乙方必须能进件成"特约商户"——这就引出第 5 章的资质门槛。

## 2. 微信分账模式：钱是怎么走的

### 2.1 一句话本质

> 钱**先进收款商户号 → 冻结一部分 → 由分账方按指令分给接收方 → 解冻剩余结算**。全程在微信支付体系内。

### 2.2 资金的 4 个状态

```
甲方付款 10000
     ↓
进【收款商户】号 ── 标记为"分账订单"的部分被【冻结】（可分账池）
     ↓ 分账方调 API
  ┌───────────────┬────────────────┐
  ↓               ↓                ↓
分给接收方A      分给接收方B        解冻剩余
                                （结算给收款商户）
```

| 状态 | 含义 |
|---|---|
| 待分账（冻结）| 付款时打了"分账标记"才会冻结，没标记的钱直接结算、不能再分 |
| 已分账 | 调分账 API 后进各接收方账户 |
| 已解冻 | 分完后剩余部分结算给收款商户 |
| 可回退 | 退款时能把已分出的钱追回 |

### 2.3 生命周期 5 步

| 步骤 | 动作 | 要点 |
|---|---|---|
| 1 | 下单打分账标记 | `profit_sharing=true`，钱才会冻结成"可分账池" |
| 2 | 添加分账接收方 | 接收方要**先登记**；类型分"商户"和"个人" |
| 3 | 发起分账 | 指定"给谁、各多少"，可多次分 |
| 4 | 完结/解冻 | 剩余结算给收款商户 |
| 5 | 分账回退 | 退款场景追回已分资金 |

### 2.4 两条硬规则（决定能不能用）

| 规则 | 内容 | 对我们的影响 |
|---|---|---|
| **30% 上限** | 单笔分给所有接收方合计默认 ≤ 订单 30% | 看映射方向：平台抽 3% → 不超；平台分 97% 给乙方 → 远超 |
| **对私分账禁用（2025-07 起）** | 分账接收方不能是"个人" | 平台当接收方（企业）→ OK；要分给个人乙方 → ❌ |

> **结论**：分账规则本身不是问题，**问题在"谁当收款商户、谁当接收方"**。让乙方当收款商户、平台当接收方（抽 3%），规则全部绕开。

## 3. 服务商 + 特约商户模式：怎么落地

### 3.1 角色就位

| 业务角色 | 支付身份 | 资金 |
|---|---|---|
| 平台 | 服务商 + 分账接收方 | 不碰本金，抽 3% |
| 乙方 | 特约商户 | 收款主体，拿 97% |
| 甲方 | 付款人 | 付全款 |

### 3.2 端到端流程

| 步骤 | 谁 | 做什么 |
|---|---|---|
| 1 | 平台 | 升级为微信支付服务商 |
| 2 | 平台 | 代乙方进件成"特约商户"，绑定分账关系 |
| 3 | 甲方 | 微信支付 10000 → **进乙方（特约商户）账户**，标记分账订单冻结 |
| 4 | 乙方 | 交付，平台验收 |
| 5 | 平台 | 调分账 API：分 300（3%）给平台、解冻 9700 给乙方 |
| 6 | 乙方 | 9700 结算到自己银行卡 |

> 平台账户**从头到尾不经手 10000**，只收到 300 的分账。这就是"只要 3%、不碰钱"在微信生态内的实现方式。

## 4. 模式选型：平台只想要 3%、不想参与金钱交易过程 ⭐

### 4.1 先点破一个矛盾

> **「平台完全不碰钱」与「平台保留担保监管（验收前冻结）」不能同时满足。**

担保的本质就是"钱先冻结、平台点头才放"——只要想保留这个抓手，平台就必须参与资金的**调度指令**（哪怕钱不进自己账户）。所以先按"要不要担保"分两条路。

### 4.2 三种模式对照

| 模式 | 钱进谁账户 | 平台怎么拿 3% | 担保 | 平台碰本金吗 | 二清风险 |
|---|---|---|---|---|---|
| **A. 服务商佣金**（乙方=特约商户）| 乙方账户 | 作分账接收方抽 3% | 弱（可设账期）| ❌ 不碰 | 无 |
| **C. 彻底分离** | 乙方账户（甲方直付）| 单独收"信息/撮合服务费" | ❌ 无 | ❌ 完全不碰 | 无 |

> 第三种"强担保又不碰钱"的路（钱进第三方持牌担保账户、平台只发放款指令抽 3%）属于**微信生态外**，单独成文，见配套文档《第三方持牌支付-担保交易接入说明》。

### 4.3 怎么选

- **微信生态内 + 轻度担保** → **A（服务商佣金）**：钱进乙方特约商户、平台抽 3%。前提是乙方能进件成特约商户。
- **彻底不参与、可放弃担保** → **C（彻底分离）**：甲方的钱直接进乙方，平台只就"撮合服务"单独收费。最干净、零资金风险，但失去验收冻结的抓手。
- **要强担保又不碰钱** → 微信生态内做不到（A 只有弱担保/账期），需走**第三方持牌担保**，见配套文档《第三方持牌支付-担保交易接入说明》。

### 4.4 模式 C 为什么"零二清风险"

模式 C 里，平台收的 3% 是**对自己撮合服务的经营收入**，和甲乙之间的交易本金**完全无关**——平台从不代收代付，自然不构成二清。代价是退款/纠纷平台兜不住，得靠规则与信用。

## 5. 资质条件清单（按角色拆）⭐

### 5.1 平台（作为服务商）必备

| 条件 | 模式 A 服务商佣金 | 模式 C 彻底分离 |
|---|:--:|:--:|
| 企业营业执照 | ✅ | ✅ |
| ICP 或 EDI 许可证 | ✅ | 视收费方式 |
| 升级微信支付服务商 | ✅ 必须 | 不需要 |
| 独立运营+开发能力 | ✅ | 视情况 |
| 对公银行账户 | ✅ | ✅ |

> 第三方持牌方案的平台资质要求见配套文档《第三方持牌支付-担保交易接入说明》。

### 5.2 乙方进件条件 —— **这是所有方案的分水岭** ⚠️

| 乙方主体类型 | 模式 A（特约商户）| 模式 C（自己收款）|
|---|:--:|:--:|
| 企业 | ✅ 可进件 | ✅ |
| 个体工商户 | ✅ 可进件 | ✅ |
| **纯个人（无营业执照）** | ⚠️ 只能"小微商户"，**行业受限+限额** | ⚠️ 同样卡（设计类小微不支持）|

**小微商户的两道硬限制**（个人乙方唯一入口）：
1. **行业受限**：为线下小微（餐饮/零售/生活服务）设计，**线上设计类服务通常不支持**。
2. **交易限额**：单笔/年累计有上限，撮合大额设计订单易触顶。

> **核心判断**：乙方有照（企业/个体户）→ 路都好走，微信生态内（模式 A）最省事；乙方主要是无照个人 → 微信侧基本卡死，需转向**第三方持牌方案**（见配套文档《第三方持牌支付-担保交易接入说明》）。

## 6. 决策点与待确认清单

### 6.1 必须先拍板的业务取舍

| # | 决策 | 影响 |
|---|---|---|
| D1 | **要不要"验收前冻结资金"的担保？** | 要强担保 → 走第三方持牌（见配套文档）；要弱担保 → 模式 A；完全不要 → 模式 C |
| D2 | **乙方主体以什么为主——有照 / 纯个人？** | 有照 → 微信生态(模式A)可行；纯个人 → 微信侧卡死，转第三方持牌（见配套文档）|
| D3 | 能否要求乙方办个体工商户？ | 可以 → 大幅简化，模式 A 直接成立 |

### 6.2 技术 / 商务待确认

| 优先级 | 待确认 | 找谁 |
|---|---|---|
| P0 | 个人乙方能否进件特约商户（小微行业 / 限额）| 微信支付 |
| P1 | 平台升级服务商资质（ICP/EDI）是否齐备 | 内部 |
| P2 | 服务商分账 API 能力与开发量 | 技术对接 |

> 第三方持牌方案的接入条件与待确认项，单独见配套文档《第三方持牌支付-担保交易接入说明》。

### 6.3 运营需要准备的

- **乙方话术**：解释为什么要办个体户 / 多开一个收款账户，强调"合法收入 + 完税凭证"对买房贷款、报税有用。
- **甲方话术**：若收款方名称发生变化，需客服解释。
- **过渡期**：新方案上线前，对大额订单做业务侧规避（限单笔金额 / 分阶段交付）。
